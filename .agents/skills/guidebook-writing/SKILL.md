# 교과서 집필·검수

기준 문서: **docs/STYLE-GUIDE.md**(확정, 최우선), 템플릿 docs/chapter-template-v2.html, 학습자 질문 docs/learner-questions.md. 이 Skill은 그 요약과 시행착오 목록이다.

## 핵심 원칙 (왜 3장 개편 샘플이 좋아졌나)

1. **질문에서 출발**: 장마다 초보 학습자가 실제로 묻는 질문 5개를 먼저 적고, 그 질문에 답하는 내용만 쓴다.
2. **결론 먼저**: 절의 첫 문장이 직답이다. 불리한 답(0원, 안 된다)도 그대로 말한다.
3. **구체 숫자 + 계산 예**: "쿠팡 기본 3%: 5만 원 × 20건 × 3% = 3만 원".
4. **같은 틀 반복**(안 A 뼈대): 축마다 정의 → 흐름 → 얼마 → 조건 → 언제부터 → 지금 할 일.
5. **주의는 한곳에**: 불확실성은 축 끝 "확인할 점" 상자 하나에. 문장마다 단서를 붙이지 않는다.
6. **행동으로 끝내기**: 축·장마다 "지금 할 일".
7. **쉬운 말**: 회계·법률·연구 용어 금지(STYLE-GUIDE 금지어 표).
8. **내부 용어 금지**: Phase 이름, 사실 ID, Hermes, 원응답, "키트 계약", "실측 아님", "탐색 후보", 작성자 면책 문장.

장 끝에는 **자주 묻는 질문 5개**(안 B), 단계에 따라 달라지는 내용이 있으면 **단계표 1개**(안 C).

## 실습편

- 단계 틀: 지금 하는 일 / 왜 / 따라 하기 / 이렇게 보이면 성공 / 이렇게 보이면? / Windows·macOS 탭.
- 대상은 터미널을 처음 여는 사람이다. 개념(터미널, 경로, 가상환경, JSON, 토큰)은 처음 나온 자리에서 한 문장으로 설명한다.
- 앱 버튼 안내 표준 문구: "앱이 업데이트되면 버튼 이름이나 위치가 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 공식 도움말(링크)을 확인하세요."
- 명령은 **깨끗한 임시 복사본에서 실제 실행해 확인한 것만** 쓰고, "이렇게 보이면 성공"은 실제 출력과 일치시킨다.
- 실습편 목표는 **오늘 실제 게시 완료**다. 핵심 경로(공식 앱/Studio 업로드)와 선택 경로(API 자동화)를 구분한다.
- 실제 앱 스크린샷 대신 직접 그린 도식형 SVG. 브랜드 로고·아이콘 복제 금지.

## 근거

- 정책·수치·가격·법률 문장은 research/FACT-SHEET.md에 근거가 있어야 하고 [S###] 각주를 단다. 근거 없는 숫자를 만들지 않는다.
- 상충 정보는 결론과 권장 행동을 함께 준다. 근거가 없으면 학습자가 확인할 위치를 알려 준다.
- "2026년 10월 조사 기준"처럼 조사 기준월을 장 머리에 한 번 표기한다.
- 가상 인물·가상 수치는 "가상" 표시와 계산식 공개. 예측처럼 쓰지 않는다.

## 검수 (자기 검수와 리뷰어 공통)

- `python3 scripts/style_lint.py <파일들> --baseline docs/results/phase-9/baseline.json` 통과(금지어·내부 용어 0, 단서 표현 장당 2회 이하, 이론편 분량 70% 이하).
- STYLE-GUIDE 5절 채점표를 **엄격하게** 적용한다. 관련 설명만 있고 직답·숫자·할 일이 없으면 "부분"이며 불통과다.
- 구조·각주·렌더링 통과는 품질 통과가 아니다. 본문을 처음 읽는 사람 입장에서 3분 안에 "그래서 무엇을 하면 되나"를 말할 수 있어야 한다.
- 브라우저 검사: 1280/375/360px 가로 넘침 0, 콘솔 오류 0, 내부 링크·앵커, 퀴즈 정답이 본문과 일치, 시뮬레이터 키보드 조작.

## 인터랙션

- 시뮬레이터는 학습자 질문에 답하는 것만. 결과는 "숫자 하나 + 해석 한 문장".
- "교육용 가정 모형" 배지와 가정값 공개, 극단값 프리셋 1개.
- 참고 사이트(art.euiyun.com, books.euiyun.com)는 패턴만 참고하고 문장·코드·이미지를 복사하지 않는다. 고도화 패턴 목록은 docs/reference-analysis-books.md.
