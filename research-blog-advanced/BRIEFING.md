## ① 한 쪽 요약

**무료 mock로 완주하고, 건강·협찬·아이 경험은 사람이 승인하는 WordPress 과정으로 진행한다.** 설치형 WordPress가 공식 발행 API와 서버 통제권을 함께 제공한다. 네이버·티스토리의 종료된 API를 복구 경로로 안내하지 않는다. Docker가 없어도 학습 완료가 가능해야 한다. 현재 안정판은 WordPress **7.1.3**, 공식 이미지 후보는 **wordpress:7.1.3-php8.3-apache**다. 실제 Docker 실행·이전 검증과 DB 이미지 고정은 다음 단계다. [BXF-001~010](01-publishing.md)

수익은 광고·제휴·협찬을 분리한다. AdSense의 보편적인 최소 글 수/방문자 기준은 확보하지 못했다. 설계의 “글20~30편”을 공식 신청조건으로 쓰지 않는다. 쿠팡은 누적 판매15만원에서 최종 채널검토를 시작하는 가이드와 별도의 API 자격·한도를 구별한다. 현행 API 최근실적·쿼터·가격 저장 규칙은 미확인이다. 수동 링크/mock를 기본으로 해야 막히지 않는다. 협찬은 방문자수만이 아니라 조건·권리·실제 경험·제품 안전을 보고 수락한다. [BXF-017~034](FACT-SHEET.md#bxf-017)

현행 공정위 지침은 **2026-06-01 개정/시행 예규499호**, 경제관계 공개는 **Ⅴ.6**이다. 블로그는 제목 또는 첫 부분에 표시한다. 사진형 표시 예외와 더보기/댓글에 숨기는 경우를 구별한다. 받은 제품·현금·대여·조건부 제휴수수료를 정확히 밝힌다. AI가 경험을 만들거나 가상인물을 실제 사용자처럼 표현하게 두지 않는다. 일부 체험단은 AI 원고 자체를 제한하므로 **계약 확인 → 허용된 작성 경로 선택**이 먼저다. [BXF-035~040](05-disclosure-law.md) [BXF-060](FACT-SHEET.md#bxf-060)

제품은 분류부터 한다. 조제유류의 제휴·협찬, 의료기기 사용자 체험담 광고, 안전 수면과 충돌하는 제품 협찬은 기본 차단한다. KC/광고주 확인/대가성 표시 중 하나만 통과했다고 다른 규제가 사라지지 않는다. 규제 적용이나 제품자료가 없으면 보류하고 확인한다. 아이 얼굴·실명·정확 생일·기관·위치와 EXIF는 기본 비공개이며 사람이 사진을 본다. 이는 일부 법정 의무보다 엄격한 프로젝트 기본값이다. [BXF-041~057](06-product-rules.md)

비용은 월500원 호스팅 광고가만으로 정하지 않는다. 이 상품의 추가 플러그인·SSH·FTP 제한, REST 인증과 복구 가능성을 먼저 확인해야 한다. 도메인 첫해 할인과 갱신비, VM 공인IP·백업, LLM 재시도를 분리한다. 현물 협찬도 세금 검토 대상이며 육아휴직급여의 취업 신고는 세금과 별도로 확인한다. [BXF-011~016](02-hosting-costs.md) [BXF-063~067](09-tax.md)

GA4/GSC/AdSense는 지표 정의와 날짜·통화·예상/확정을 보존해서 모은다. 상한·중복 검사는 대량 저가치 콘텐츠 방지 장치일 뿐 합법/SEO 합격을 보장하지 않는다. 아직 구현을 시작하지 않았으며, 질문별 확인 공백은 ⑧에 둔다.

| 선택: 실제 호스팅 | HTTPS·REST·Application Passwords·권한·플러그인/광고 코드/ads.txt·백업/복구 지원 | 사용자 자격으로 먼저 초안 저장·응답id/URL 기록; 명시적 승인 뒤 공개 상태 재조회 |

WordPress 애플리케이션 비밀번호의 도입 하한은5.6이며 **새 설치에5.6을 권장한다는 뜻이 아니다**. 사용자 이름+앱 비밀번호 Basic 인증을 HTTPS로 전달한다. 운영 서버에서 차단되면 HTTPS 인식·역방향 프록시 Authorization·보안 플러그인·호스팅 지원을 확인한다. 기능 강제 활성화를 공용 HTTP 운영 우회책으로 주지 않는다. [BX003](SOURCES.md#bx003)

Docker 태그는 digest처럼 불변하지 않다. 구현 시 pull 결과 digest·WordPress/PHP/DB/플러그인 버전을 기록하고 재현/보안갱신 절차를 나눈다. 이번 단계에서는 Docker pull/실행·실호스팅 이전을 하지 않았다. Python/DB 세부 패치버전은 조사만으로 실행 검증 완료라고 표시하지 않는다. [BX001](SOURCES.md#bx001) [BX002](SOURCES.md#bx002)

발행 순서: 분류ID/이미지ID 준비 → draft 저장 → 최종 HTML/미디어/표시/링크 해시 승인 → future 예약 → 서버 공개 상태 확인. POST 타임아웃에는 post_id/서버 목록부터 조회한다. WordPress가 키트의 중복 방지·승인 상태를 자동 보장하지 않는다. WP-Cron은 방문 기반이므로 예약 성공과 정각 공개는 다르다. [BX004~007](01-publishing.md) [BX127](SOURCES.md#bx127)

WordPress.com의 OAuth·플랜 제한은 설치형 연결과 구별한다. Blogger API v3는 OAuth 쓰기/isDraft/publishDate가 대안이며 프로젝트 쿼터는 실제 콘솔에서 확인한다. 네이버·티스토리는 공식 편집기/수동 내보내기 경로만 유지한다.

## ⑨ 설계 목차·키트 조정 제안

설계서는 Claude가 수정한다. 이번 작업은 제안만 남긴다.

1. **A0**: “글20~30편→AdSense”를 운영 예시/근거 없음으로 구별하고 콘텐츠/정책 준비 기준으로 바꾼다. 광고→제휴→협찬은 학습 순서이며 법정 해금 단계가 아님을 쓴다.
2. **A1·A2**: mock와Docker/실호스팅 성공화면을 구별한다. 최신 WordPress7.1.3/공식태그·실행환경 진단·호스팅 플러그인제한/REST확인·DB/미디어복구 과제를 추가한다. PHP/DB 고정버전은 후속 실행으로 확정한다.
3. **A3**: CSV집계/기관주소록/API를 구별하고 자료별 허락·기준일을 스키마에 넣는다. 터미타임 예시는 건강·안전 승인등급으로 고정한다.
4. **A4·A9**: 계약/플랫폼의 AI 허용을 초안 생성보다 먼저 확인한다. 협찬은 `ai_allowed=false/unknown`일 때 사람작성/보류 경로로 완주할 수 있어야 한다. AI허용이어도 미사용 경험은 차단한다.
5. **A5·A8**: `product_type, intended_use, model, maker, certification_scheme, recall_check, ad_review_scope`를 분리한다. KC번호없음=모두불법, 분유브랜드명검색=모두금지 같은 단순 판정을 피한다. 법적 금지/프로젝트 거절/자료보류를 나눈다.
6. **A6·A11**: WP-Cron·스케줄러 지연, 타임아웃 후조회, 서버post_id보존·중복잠금·해시재승인, 공개상태재확인을 성공 기준에 넣는다. 건강/협찬 글의 무응답 자동공개는 만들지 않는다.
7. **A7**: 개인정보처리방침의 실제 의무와 소개/문의/광고정책의 권장을 구별한다. ads.txt는권장,AdFit은사전문의,아동광고는실제코드유형별확인으로 가르친다.
8. **A8**: 쿠팡 live API는 현행자격/쿼터/약관이 확인된 뒤 선택 실습으로 둔다. 기본 수동링크·가격미표시·mock 검색/딥링크로 재현성을 지킨다.
9. **A9**: 낮잠이불 거절사례와 그림책꽂이 수락사례를 유지하되, 후자도 분류/리콜/권리/표시 확인을 통과해야 한다. 광고주확인과최종사람승인을 별개 상태로 만든다.
10. **A10**: GA4/GSC/PT·속성시간대·빈행/지연·예상/확정/실입금을 명시한다. Jetpack의2024조건을2026고정사실로 복사하지 않는다.
11. **A12**: 현물/부가세/사업자등록을 일괄소득세율과 나누고 육아휴직급여 취업신고 확인을 추가한다. 2026공정위 개정과 시행전 화장품 조항의 구별을 반영한다.
12. **완료 기준**: 규칙통과와사람승인·실계정성공을 구별한다. 다음 단계에서 mock정상/규제품목거절/자료보류/승인후수정/timeout중복/백업복구를검증하고 Windows/macOS실기기는미실행이면명시한다.
