STEP 01 · 개발자 앱과 역할 준비

개발자 앱과 역할 준비

지금 하는 일

문서의 Instagram Login 앱 생성 흐름을 확인해요.

왜 하는지

앱 로그인·권한·계정 유형이 맞아야 요청할 수 있어요.

따라 하기

앱이 업데이트되면 버튼 이름이나 위치가 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 공식 도움말을 확인하세요.

  1. 앱 생성 안내를 열고 Meta App Dashboard에서 Create App → Other → Business → 앱 이름·연락 이메일 → Instagram → Set up 흐름을 확인하세요.
  2. Instagram → API setup with Instagram login에서 본인 공개 프로페셔널 계정을 추가하세요. App Roles → Roles에서 본인 역할을 확인해요.[S176][S179]
  3. 게시 권한은 instagram_business_basic과 instagram_business_content_publish예요.[S002]
  4. 본인 소유·관리 계정의 Standard Access와 다른 고객 계정의 Advanced Access를 구분하세요. Advanced Access는 앱 검수가 필요해요. 본인 테스트의 검수 면제만으로 일반 독자에게 보이는지는 판단하지 말고 게시 후 공개 범위를 확인하세요.[S031]

공식 한국어 도움말 · 테스터 초대를 받았다면 현재 대시보드의 안내와 공식 도움말을 확인하세요.[S179]

확인할 점

현재 Instagram 테스터 수락 버튼 경로는 공식 안내에서 아직 확인되지 않았어요. 역할 수락이 막히면 여기서 멈추고 앱 수동 게시를 사용하세요. Facebook 테스터나 과거 Basic Display 순서를 대신 쓰지 마세요.

이렇게 보이면 성공

Instagram Login 제품·본인 계정·역할·게시 권한을 확인했어요. 역할을 수락하지 못했다면 다음 요청은 보류해요.

이렇게 보이면?

  • Instagram 제품이 없으면 앱 유형/use case를 공식 생성 문서와 비교하세요.
  • 권한 오류를 해결하려고 불필요한 전체 권한이나 Live 전환을 먼저 하지 마세요.

Windows

PC 명령은 없어요. 위 순서를 휴대폰 앱이나 웹에서 따라 하세요.

macOS

PC 명령은 없어요. 위 순서를 휴대폰 앱이나 웹에서 따라 하세요.

STEP 02 · 토큰과 로컬 .env 준비

토큰과 로컬 .env 준비

지금 하는 일

토큰·계정 ID·버전을 비공개 환경에 둬요.

왜 하는지

비밀 값을 공개 코드나 명령 기록에 남기지 않기 위해서예요.

따라 하기

  1. 토큰은 접근 권한이 담긴 비밀 문자열이에요. Instagram → API setup with Instagram business login → Generate token에서 본인 계정용 토큰을 발급받아요.[S177]
  2. 대시보드 토큰은 60일 장기, OAuth 토큰은 1시간 단기로 안내돼요. 실제 반환된 expires_in을 확인하고 발급일·만료일을 개인 메모에 적으세요.[S177]
  3. 아래 복사 명령으로 .env를 만들고 IG_ACCESS_TOKEN·IG_USER_ID를 본인 편집기로 입력하세요. 기본 API 버전은 v26.0이에요.[S174] 토큰을 화면 캡처나 공개 저장소에 넣지 마세요.
  4. 대상 계정은 비공개 실행 환경에서 GET /v26.0/me?fields=user_id,username으로 확인해요.[S177]
  5. 장기 토큰은 발급 24시간 이후·만료 전에 갱신하면 60일로 다시 연장돼요. 공식 안내의 refresh_access_token 요청을 사용해요. 만료 뒤에는 재인증하세요. 키트는 자동 갱신하지 않아요.[S030]
IG_ACCESS_TOKEN=
IG_USER_ID=
IG_API_VERSION=v26.0

이렇게 보이면 성공

토큰·계정 ID가 비공개 .env에 있고 대상 사용자 이름과 만료일을 확인했어요.

이렇게 보이면?

  • 토큰 만료면 갱신 요청을 반복하지 말고 재인증하세요.
  • 권한은 instagram_business_basic·instagram_business_content_publish를 확인해요. *_publishing으로 오기하지 않아요.

Windows

Copy-Item .env.example .env
메모장으로 .env를 열어 편집해요. 파일 이름이 .env.txt가 되지 않게 확인하세요.

macOS

cp .env.example .env
텍스트 편집기의 일반 텍스트 모드로 .env를 편집해요.

STEP 03 · 승인 파일로 공개 URL 만들기

승인 파일로 공개 URL 만들기

지금 하는 일

JPEG와 MP4만 별도 공개 폴더로 준비해요.

왜 하는지

Instagram Login은 이미지·동영상 모두 Meta가 읽을 공개 URL이 필요해요.

따라 하기

  1. 실습 6 승인을 마친 본인 실제 자료 출력 폴더에 아래 도우미를 실행해요. 예시는 first-post지만 합성 샘플은 live 게시할 수 없어요.
  2. 도우미는 승인된 JPEG/MP4만 새 폴더에 복사해요. .env·검수표·설정·토큰은 복사하지 않아요. 네트워크 요청은 없어요.
  3. 본인의 별도 공개 GitHub 저장소 → Add file → Upload files에서 hosting/first-post 안의 cards 폴더와 reel.mp4를 함께 드래그 앤 드롭하고 Commit changes로 저장해요.
  4. Settings → Pages → Build and deployment → Source: Deploy from a branch에서 branch와 /(root)를 고르고 배포 완료를 확인해요. 업로드를 하위 폴더에 했다면 기본 URL에도 그 경로를 포함해요.
  5. 로그인하지 않은 창에서 https://사용자.github.io/저장소/cards/card-01.jpg와 /reel.mp4가 파일 자체로 열리는지 확인해요. curl -I -L "실제 파일 URL"로 헤더·최종 URL·MIME도 확인할 수 있지만 실제 GET 파일 열기를 대신하지 않아요.
  6. 기본 URL은 두 파일 경로의 공통 부모 폴더예요. localhost·로컬 경로·Drive 미리보기·/blob/ HTML 주소는 대체가 아니에요. Meta 수신 성공은 별도로 확인해야 해요.

GitHub 웹 업로드는 파일당 25MiB[S188]이에요. Pages는 Free 공개 저장소에서 가능한 작은 교육 실습 후보지만 사업 운영용 무료 호스팅을 제한해요. 운영용 미디어 서버로 쓰지 마세요.[S185][S186]

[S001][S004]

이렇게 보이면 성공

기본 카드 5장일 때 공개 준비 완료: 6개 JPEG/MP4 → …가 출력돼요. 공개 폴더에는 cards/*.jpg와 reel.mp4만 있고 배포 후 로그인 없이 파일 자체가 열려요.

이렇게 보이면?

  • 승인 파일 변경 오류면 render·새 검수·approve부터 다시 하세요.
  • 대상 폴더가 이미 있으면 새 이름을 지정하세요. 파일당 25MiB 초과면 크기를 조정해 다시 검수해요.
  • 공개 창에서 열려도 Meta의 다운로드는 봇 차단·접근 제어로 실패할 수 있어요.

Windows

.venv\Scripts\python.exe prepare_hosting.py output/first-post --dest hosting/first-post

macOS

python prepare_hosting.py output/first-post --dest hosting/first-post

STEP 04 · 요청 미리보기와 선택 live 실행

요청 미리보기와 선택 live 실행

지금 하는 일

실제 URL의 드라이런을 확인하고 본인이 게시 여부를 결정해요.

왜 하는지

컨테이너 생성과 게시를 구분하고 중복 재시도를 피해요.

따라 하기

  1. 아래 <URL>을 본인 HTTPS 폴더 주소로 바꾸고, --live 없이 드라이런을 실행하세요. JPEG의 image_url과 MP4의 video_url을 확인해요.
  2. 게시 흐름은 컨테이너 생성 → 처리 상태 FINISHED 확인 → media_publish예요. 캐러셀은 자식 파일들을 처리한 뒤 부모를 발행해요. 미발행 컨테이너는 24시간 뒤 만료돼요.[S001][S004]
  3. 키트의 live 명령은 캐러셀과 릴스, 두 게시물을 시도해요. 본인 실제 자료·권리·필수 표시·공개 URL·권한을 모두 갖춘 뒤 키트 README의 실제 게시 절차를 선택하세요.
  4. 이 키트는 Instagram Login의 협찬 API 파라미터를 지원하지 않아요. 필요한 협찬 표시를 설정하려면 앱 게시 경로를 사용하세요.[S001]
확인할 점

공식 문서에 이동 24시간 한도가 100건·50건으로 다르게 적혀 있어요. 안전하게 50건 이내로 계획하고 GET /<IG_USER_ID>/content_publishing_limit?fields=quota_usage,config에서 실제 사용량과 한도를 확인하세요.[S001][S003][S207]

이렇게 보이면 성공

드라이런 출력에 "mode": "dry-run"과 본인 URL이 보여요. 실제 게시를 선택했다면 미디어 ID와 앱 게시물·공개 범위를 확인하고 완료로 기록하세요.

이렇게 보이면?

  • 권한 오류면 계정·역할·scope·토큰 대상부터 확인하세요.
  • ERROR/EXPIRED/시간 초과는 성공이 아니에요. 기록과 대시보드를 확인하세요.
  • 응답이 끊겼으면 일부 게시가 이미 됐을 수 있어요. LIVE_ATTEMPT.json을 지우고 재실행하지 마세요.

Windows

.venv\Scripts\python.exe publish.py output/first-post --base-url "<URL>"

macOS

python publish.py output/first-post --base-url "<URL>"

자동 게시에는 무엇이 필요한가요?

공개 프로페셔널 계정과 앱·권한·토큰이 필요해요.[S002][S031]

예: Instagram Login으로 본인 계정을 연결하세요. 이 경로에는 Facebook 페이지가 필수가 아니에요. 따라 하기 →

토큰은 어디에 두고 언제 갱신하나요?

비공개 .env에 두고 만료 전에 갱신하세요.

장기 토큰은 60일이며 발급 24시간 뒤부터 갱신할 수 있어요.[S030] 발급일과 만료일을 개인 메모에 남기세요. 따라 하기 →

내 컴퓨터의 파일을 바로 보내나요?

이미지와 동영상 모두 공개 파일 URL이 필요해요.[S001][S004]

예: 로그인 없이 card-01.jpg와 reel.mp4 자체가 열리는 주소를 확인하세요. 따라 하기 →

하루 게시 한도는 100개인가요, 50개인가요?

안전하게 50개 이내로 계획하고 계정의 실제 한도를 확인하세요.

같은 공식 안내에 100과 50이 함께 있어요.[S001][S003] content_publishing_limit에서 사용량과 config를 함께 읽으세요. 따라 하기 →

실패하면 다시 누르면 되나요?

원격 게시 상태를 확인하기 전에는 다시 실행하지 마세요.
