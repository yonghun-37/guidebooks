STEP 01 · 오늘의 소재와 권리 기록

오늘의 소재와 권리 기록

지금 하는 일

누구의 어떤 질문을 풀지 원자료와 함께 적어요.

왜 하는지

문안 생성 전에 사실과 재사용 가능한 범위를 정해요.

따라 하기

  1. 동봉 합성 피드로 연습하거나, 직접 확인한 원자료의 제목·날짜·URL·핵심 사실을 메모하세요.
  2. RSS는 새 글 목록을 전달하는 형식이에요. 제공된 피드가 기사·사진의 재사용 허락을 뜻하지는 않아요.[S010]
  3. 예: “신청은 언제까지 하나요?”처럼 독자 질문을 쓰고 원자료에서 답을 찾으세요. 기사 전체·사진을 무단으로 채팅에 넣지 마세요.

확인한 사실:

이렇게 보이면?

  • 원출처가 없으면 생성 전에 찾으세요.
  • 이용 허락이 불분명하면 합성 연습을 유지하거나 권리를 확인한 다른 자료로 바꾸세요.

STEP 02 · 웹 채팅에 붙여 넣을 문서 만들기

웹 채팅에 붙여 넣을 문서 만들기

지금 하는 일

기존 news.json에서 prompt.md를 만들어요.

왜 하는지

API 키 없이 사람이 채팅에 전달할 자료를 준비해요.

따라 하기

  1. JSON은 이름과 값을 큰따옴표·쉼표로 연결하는 데이터 문서예요. copy.json에 카드·영상·캡션을 함께 담아요.
  2. 아래 명령으로 prompt.md를 만드세요. 기존 copy.json은 유지돼요.
  3. prompt.md를 이용 가능한 웹 채팅에 붙여 넣으세요. 수정할 때는 현재 copy.json 전체도 함께 주고 원출처와 합성 표시를 유지해 달라고 요청하세요.
확인할 점

무료 채팅 한도에 걸리면 기존 오프라인 초안을 직접 고치세요. 유료 API는 필요 없어요.

이렇게 보이면 성공

웹 채팅에 붙여 넣을 프롬프트: …/prompt.md가 출력돼요. 기존 copy.json이 그대로 있어요.

이렇게 보이면?

  • 무료 이용 한도에 걸리면 기존 오프라인 초안을 직접 편집해도 돼요. 유료 API는 필수가 아니에요.
  • 채팅에 토큰·비밀번호·민감한 원자료는 넣지 마세요.

Windows

.venv\Scripts\python.exe write_copy.py output/first-post/news.json --mode prompt --template cards --output output/first-post/copy.json

macOS

python write_copy.py output/first-post/news.json --mode prompt --template cards --output output/first-post/copy.json

STEP 03 · 답변 저장과 구조 검증

답변 저장과 구조 검증

지금 하는 일

전체 JSON을 저장하고 필수 구조를 검사해요.

왜 하는지

화면에 넣을 필드와 원출처 누락을 먼저 잡아요.

따라 하기

  1. 답변의 전체 JSON 객체만 텍스트 편집기에서 copy.json에 저장해요. 앞뒤 설명과 ``` 울타리는 빼세요. 웹 채팅을 쓰지 않았다면 기존 파일을 직접 편집해요.
  2. 카드의 title과 본문 points, 영상 자막 subtitle, 게시 문구 caption을 확인해요. 본문 카드는 body 대신 points를 표시하므로 함께 고쳐요.
  3. 아래 검증을 실행하고 인명·날짜·수치·조건을 원문과 직접 대조해요. 구조 검사는 사실·저작권 검증이 아니에요. 수정 뒤 실습 4에서 다시 렌더링해요.

이렇게 보이면 성공

구조 검증 OK: output/first-post/copy.json (사실 확인은 사람이 해야 합니다)가 출력돼요.

이렇게 보이면?

  • JSON 오류면 큰따옴표·쉼표·코드 울타리를 확인하세요.
  • 원출처 또는 합성 표시 오류면 필드를 삭제하지 말고 원자료에 맞게 복원하세요.

Windows

.venv\Scripts\python.exe write_copy.py output/first-post/news.json --validate --output output/first-post/copy.json

macOS

python write_copy.py output/first-post/news.json --validate --output output/first-post/copy.json
실제 자료로 바꾸기: 새 로컬 피드 만들기

합성 연습을 한 번 마친 뒤 본인 자료로 게시하려면, 아래 XML의 제목·URL·날짜·요약을 본인이 확인한 원자료와 자기 문장으로 모두 바꿔 starter-kit/my-feed.xml에 UTF-8 일반 텍스트로 저장하세요. 예시의 example.org와 안내 문구는 실제 자료가 아니에요. XML은 시작·끝 태그로 내용을 감싸는 문서 형식이에요. 값에 &를 쓰면 &amp;로 적어요. 권리·사실이 확인되지 않았다면 만들지 말고 보류해요.

<rss version="2.0"><channel>
<title>내가 확인한 소재</title>
<item><title>직접 확인한 제목으로 교체</title>
<link>https://example.org/replace-with-real-source</link>
<description>내 말로 다시 쓴 짧은 요약으로 교체</description>
<pubDate>원자료의 날짜로 교체</pubDate></item>
</channel></rss>
python run_pipeline.py --offline --feed my-feed.xml --output output/my-news

Windows PowerShell에서는 python을 .venv\Scripts\python.exe로 바꿔요. 새 폴더에서 검수 대기로 멈추면 이후 모든 명령의 output/first-post를 output/my-news로 바꿔 실습 3~7을 다시 진행해요. 피드를 바꾸지 않고 synthetic만 false로 고치면 실제 자료가 되지 않아요. 이 XML에는 합성 태그를 넣지 않으므로 실제 확인한 자료일 때만 사용해요. news.json·copy.json의 원출처와 문장을 직접 확인해요.
