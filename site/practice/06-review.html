STEP 01 · 여섯 항목 직접 검수

여섯 항목 직접 검수

지금 하는 일

원문·카드·영상·권리·표시를 사람이 확인합니다.

왜 하는지

구조 검사와 생성 성공만으로 게시 준비가 끝나지 않습니다.

따라 하기

  1. 이론 12장 게시 전 체크리스트와 출력 폴더 REVIEW.md를 엽니다.
  2. 원출처·날짜·인명·수치·조건을 카드와 대조하고 모든 JPEG와 영상을 봅니다. 내레이션·음원·폰트·사진 권리, 캡션, is_ai_generated를 확인합니다.
  3. 검토한 여섯 줄의 - [ ]를 - [x]로 바꿔 저장합니다. 합성 자료는 연습용임을 확인하는 것이며 실제 뉴스 게시 승인이 아닙니다.

이렇게 보이면 성공

REVIEW.md의 여섯 항목을 실제로 검토했고 여섯 줄만 [x]로 저장했습니다. 자동으로 체크하는 명령은 사용하지 않습니다.

이렇게 보이면?

  • 모르는 권리·사실이 남으면 체크하지 말고 보류하세요.
  • 캡션 수정은 REVIEW.md만 고치지 말고 copy.json을 고친 뒤 render부터 다시 합니다.

Windows

이 단계는 Windows와 무관한 휴대폰 또는 웹 작업입니다. 휴대폰 OS와 앱 버전의 화면 차이는 공식 도움말로 확인하세요.

macOS

이 단계는 macOS와 무관한 휴대폰 또는 웹 작업입니다. 휴대폰 OS와 앱 버전의 화면 차이는 공식 도움말로 확인하세요.

STEP 02 · AI·협찬 표시 판단

AI·협찬 표시 판단

지금 하는 일

필요한 표시와 게시 가능 여부를 결정합니다.

왜 하는지

캡션과 플랫폼 라벨을 서로 대체한다고 오해하지 않게 합니다.

따라 하기

  1. 실사형 합성 영상·사실적으로 들리는 합성 음성 등은 AI 자기공개 필요성을 검토합니다. AI 글쓰기 보조를 모두 같은 조건으로 판정하지 않습니다.
  2. 경제적 이해관계가 있으면 국내 표시 기준의 문구와 플랫폼 유료 파트너십 라벨을 각각 확인합니다. 광고 집행 허락은 별개입니다.
  3. 필요한 앱 라벨을 확인하지 못한 콘텐츠는 게시 준비 단계에 남깁니다. 아래 앱 메뉴의 위치는 7v 확인 전 후보입니다.

앱 버전에 따라 이름이 다를 수 있음 — 보통 이런 이름: AI 라벨 추가 / Add AI label · AI 정보 / AI info. 최종 설정의 더 많은 옵션 / More options · 고급 설정 / Advanced settings 안에 있는지도 미확인입니다.

한국 앱 메뉴·배치 미확인. 확인일 2026-10-26. 공식 도움말 · S183에서 기능을 찾고, 다르면 OS·앱 버전·계정 유형과 화면을 기록하세요. 개인정보·인증 코드·토큰은 기록하지 마세요.

앱 버전에 따라 이름이 다를 수 있음 — 보통 이런 이름: 파트너십 레이블 및 광고 / Partnership label & ads · 유료 파트너십 레이블 추가 / Add paid partnership label. 계정 자격·파트너 선택·승인 순서는 미확인입니다.

한국 앱 메뉴·배치 미확인. 확인일 2026-10-26. 공식 도움말 · S184에서 기능을 찾고, 다르면 OS·앱 버전·계정 유형과 화면을 기록하세요. 개인정보·인증 코드·토큰은 기록하지 마세요.

이렇게 보이면 성공

표시 필요 여부·근거·보류할 조건을 적었습니다. 필요한 라벨을 확인할 수 없는 상태는 완료로 판단하지 않습니다.

이렇게 보이면?

  • 토글이 안 보인다고 의무가 없다고 판단하지 마세요.
  • 캡션에 AI/광고 문구만 넣으면 플랫폼 라벨이 대체된다는 근거는 없습니다.

STEP 03 · 승인과 드라이런 확인

승인과 드라이런 확인

지금 하는 일

검수 기록을 승인하고 요청 미리보기를 봅니다.

왜 하는지

실제 전송 전에 파일 변경과 요청 경로를 확인합니다.

따라 하기

  1. 드라이런은 실제 요청을 보내지 않고 보낼 내용을 출력하는 연습입니다. 아래 approve 명령은 항상 드라이런입니다.
  2. APPROVED.json은 승인 시 파일 해시를 저장합니다. 해시는 파일이 바뀌었는지 비교하는 요약값입니다. dry-run.json에는 요청 미리보기가 생깁니다.
  3. 캐러셀 자식 JPEG → 상태 확인 → 부모 게시, 릴스 생성 → 상태 확인 → 게시 순서를 읽습니다. 이미지와 영상 URL은 아직 예시입니다. 앱 게시에는 공개 URL이 필요 없습니다.

이렇게 보이면 성공

"mode": "dry-run", "컨테이너 생성", "상태 확인", "게시"가 출력되고 APPROVED.json·dry-run.json이 생깁니다. 실제 게시하지 않습니다.

이렇게 보이면?

  • 여섯 칸 오류면 검수표를 실제로 읽고 저장했는지 확인하세요.
  • 검수 대상 변경 오류면 render → 새 검수 → approve 순서로 다시 합니다.

Windows

.venv\Scripts\python.exe run_pipeline.py approve output/first-post
.venv\Scripts\python.exe publish.py output/first-post

macOS

python run_pipeline.py approve output/first-post
python publish.py output/first-post
