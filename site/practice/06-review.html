STEP 01 · 여섯 항목 직접 검수

여섯 항목 직접 검수

지금 하는 일

원문·카드·영상·권리·표시를 사람이 확인해요.

왜 하는지

구조 검사와 생성 성공만으로 게시 준비가 끝나지 않아요.

따라 하기

  1. 이론 12장 게시 전 체크리스트와 출력 폴더 REVIEW.md를 열어요.
  2. 원출처·날짜·인명·수치·조건을 카드와 대조하고 생성된 모든 JPEG와 영상 끝까지 봐요. 카드만 게시해도 현재 승인은 카드·영상 묶음 전체를 확인하므로 영상 검수를 생략하지 않아요. 내레이션·음원·폰트·사진 권리, 캡션, is_ai_generated를 확인해요.
  3. 검토한 여섯 줄의 - [ ]를 - [x]로 바꿔 저장해요. 합성 자료는 연습용임을 확인하는 것이며 실제 뉴스 게시 승인이 아니에요.

이렇게 보이면 성공

REVIEW.md의 여섯 항목을 실제로 검토했고 여섯 줄만 [x]로 저장했어요. 자동으로 체크하는 명령은 사용하지 않아요.

이렇게 보이면?

  • 모르는 권리·사실이 남으면 체크하지 말고 보류하세요.
  • 캡션 수정은 REVIEW.md만 고치지 말고 copy.json을 고친 뒤 render부터 다시 해요.

Windows

PC 명령은 없어요. 위 순서를 휴대폰 앱이나 웹에서 따라 하세요.

macOS

PC 명령은 없어요. 위 순서를 휴대폰 앱이나 웹에서 따라 하세요.

STEP 02 · AI·협찬 표시 판단

AI·협찬 표시 판단

지금 하는 일

필요한 표시와 게시 가능 여부를 결정해요.

왜 하는지

캡션과 플랫폼 라벨을 서로 대체한다고 오해하지 않게 해요.

따라 하기

앱이 업데이트되면 버튼 이름이나 위치가 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 공식 도움말을 확인하세요.

  1. 사실적으로 보이거나 들리는 합성 영상·음성은 AI 레이블 추가를 확인하고 공유 전에 켜세요.[S183]
  2. 현금·제품·서비스 제공을 받았다면 관계를 쉽게 알아보도록 밝히세요. 예: 캡션 첫 부분에 “제품을 제공받아 제작했어요”라고 쓰고 영상 안 표시도 확인하세요.[S008]
  3. 플랫폼 협찬 표시는 파트너십 레이블 및 광고 → 협찬 광고 레이블 추가 → 브랜드 파트너 선택에서 설정해요.[S237]

공식 한국어 도움말 · 게시물·릴스를 만들 때 AI 레이블 추가를 찾아요.[S183]

공식 한국어 도움말 · 브랜드는 최대 2개를 고를 수 있어요. 첫 승인 전에는 브랜드명 없이 표시되고 승인 뒤 이름이 보여요.[S239][S237]

확인할 점

AI 토글의 위치와 계정별 지원은 최신 화면에서 확인하세요. 필요한 표시가 없으면 게시를 보류하세요. 브랜드명 표시 승인과 광고 집행 허가는 따로 확인해요.[S241]

이렇게 보이면 성공

필요한 AI·협찬 표시와 문구를 정했어요. 설정할 수 없는 필수 표시가 있으면 공유를 보류해요.

이렇게 보이면?

  • 토글이 안 보인다고 의무가 없다고 판단하지 마세요.
  • 캡션에 AI/광고 문구만 넣으면 플랫폼 라벨이 대체된다는 근거는 없어요.

Windows

PC 명령은 없어요. 위 순서를 휴대폰 앱이나 웹에서 따라 하세요.

macOS

PC 명령은 없어요. 위 순서를 휴대폰 앱이나 웹에서 따라 하세요.

STEP 03 · 승인과 드라이런 확인

승인과 드라이런 확인

지금 하는 일

검수 기록을 승인하고 요청 미리보기를 봐요.

왜 하는지

실제 전송 전에 파일 변경과 요청 경로를 확인해요.

따라 하기

  1. 드라이런은 실제 요청을 보내지 않고 보낼 내용을 출력하는 연습이에요. 아래 approve 명령은 항상 드라이런이에요.
  2. APPROVED.json은 승인 시 파일 해시를 저장해요. 해시는 파일이 바뀌었는지 비교하는 요약값이에요. dry-run.json에는 요청 미리보기가 생겨요.
  3. 캐러셀 자식 JPEG → 상태 확인 → 부모 게시, 릴스 생성 → 상태 확인 → 게시 순서를 읽어요. 이미지와 영상 URL은 아직 예시예요. 앱 게시에는 공개 URL이 필요 없어요.

이렇게 보이면 성공

"mode": "dry-run", "컨테이너 생성", "상태 확인", "게시"가 출력되고 APPROVED.json·dry-run.json이 생겨요. 실제 게시하지 않아요.

이렇게 보이면?

  • 여섯 칸 오류면 검수표를 실제로 읽고 저장했는지 확인하세요.
  • 검수 대상 변경 오류면 render → 새 검수 → approve 순서로 다시 해요.

Windows

.venv\Scripts\python.exe run_pipeline.py approve output/first-post
.venv\Scripts\python.exe publish.py output/first-post

macOS

python run_pipeline.py approve output/first-post
python publish.py output/first-post

예: 제품을 제공받았다면 그 관계를 첫 부분에 쓰고 협찬 광고 레이블도 확인하세요. 따라 하기 →
