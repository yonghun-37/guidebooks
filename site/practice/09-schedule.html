진행 기록은 이 브라우저에 저장해요.

이 실습의 흐름

매일 초안을 만들고 검수 대기에서 멈추도록 설정해요. 예약 시간은 생성 시각이에요. 게시 시각은 검수 뒤 본인이 정해요. 9장의 역할표와 14장의 운영 달력에 생성·검수·게시 시간을 따로 적으세요.

실습 2의 가상환경에서 시작해요. Windows의 모든 python은 .venv\Scripts\python.exe를 써요. 예약 안내는 PC에 명령을 출력만 해요. 아래 등록 단계에서 본인이 명령을 실행해야 OS 예약이 생겨요.

STEP 01 · 매일 생성할 예약 안내 만들고 등록하기

매일 생성할 예약 안내 만들고 등록하기

지금 하는 일

OS에 날짜별 초안 생성 작업을 등록해요.

왜 하는지

매일 손으로 같은 생성 명령을 입력하는 일을 줄여요.

따라 하기

  1. 오늘 올릴 자료를 자동 수집하지는 않아요. 먼저 내 자료 만들기에서 config.yaml·my-feed.xml을 준비하세요. config.yaml의 llm.mode는 offline, reel.tts는 silent로 둬요. 동봉 연습만 한다면 아래 명령에서 --config config.yaml --feed my-feed.xml을 빼세요.
  2. 아래 명령의 09:00을 내 생성 시각으로 바꿔 실행하세요. 예약 시각은 이 컴퓨터의 현지 시간이에요. 출력의 Python·daily.py는 절대 경로인지 확인해요. Windows는 키트 안 설정·피드 경로를 starter-kit 기준 상대 경로로 표시하고, 키트 밖 파일은 절대 경로로 표시해요. macOS·Linux는 설정·피드도 절대 경로예요. 모두 내가 준비한 파일을 가리키는지 읽어요. 가상환경이나 키트 폴더를 옮기면 안내를 다시 만들어 재등록해요.
  3. Windows: 출력의 안내대로 PowerShell에서 cmd.exe를 입력한 뒤 등록 아래의 schtasks 한 줄만 복사해 실행하세요. 나중에 PowerShell로 돌아오려면 exit를 입력해요.[S268] macOS·Linux: crontab -e를 열어 출력의 예약 한 줄을 추가하고 저장해요. 처음 편집기를 고르면 nano를 선택하세요. nano는 Ctrl+O → Enter로 저장하고 Ctrl+X로 닫아요. vi가 열렸다면 i → 줄 붙여넣기 → Esc → :wq → Enter로 저장해요. 다른 예약 줄은 유지하세요.[S269][S270]
  4. 출력의 확인 명령으로 Windows 작업 이름 ReelsBookDaily와 시각, 또는 crontab의 daily.py 줄과 시각을 확인하세요. 예: 0 9 * * *는 매일 09:00이에요.
확인할 점

로컬 예약은 PC가 켜져 있고 실행 가능한 상태여야 해요. 잠자기 중 실행을 보장하지 않아요. 토큰은 이 예약 명령에 넣지 않아요. macOS에서 접근 권한 오류가 나면 출력 안내와 시스템 설정에서 터미널 권한을 확인하세요.

이렇게 보이면 성공

예약 안내만 출력했다면 아직 등록 전이에요. 등록 명령을 실행한 뒤 작업 목록에 내 시각과 절대 경로가 있으면 이 단계를 체크해요.

이렇게 보이면?

Windows 예약 명령이 길다는 오류가 나면 키트를 C:\reels처럼 짧은 경로로 옮기고 예약 안내를 다시 만드세요. 같은 이름의 Windows 작업이 있으면 먼저 확인하세요. 이전 작업을 바꾸려면 마지막 단계에서 해당 작업만 삭제하고 새로 등록해요.

Windows

.venv\Scripts\python.exe schedule_setup.py --os windows --time 09:00 --config config.yaml --feed my-feed.xml

macOS

python schedule_setup.py --os macos --time 09:00 --config config.yaml --feed my-feed.xml

Linux

python schedule_setup.py --os linux --time 09:00 --config config.yaml --feed my-feed.xml

STEP 02 · 등록한 작업을 수동으로 한 번 실행하기

등록한 작업을 수동으로 한 번 실행하기

지금 하는 일

기다리기 전에 등록한 명령을 실행해 파일이 생기는지 확인해요.

왜 하는지

예약 목록만 있고 실제 파일이 안 생기는 문제를 오늘 발견해요.

따라 하기

  1. schedule_setup 출력의 수동 실행 명령을 실행하세요. Windows는 cmd.exe에서 schtasks /Run /TN ReelsBookDaily예요. macOS·Linux는 출력의 절대 경로 Python으로 시작하는 daily.py 한 줄을 터미널에 붙여 넣어요.
  2. 키트의 output/daily/daily.log를 편집기로 열어 오늘 날짜의 검수 대기와 REVIEW.md 위치를 찾으세요. 로그는 실행 결과를 모으는 텍스트 파일이에요. 실행 요청 성공만으로 생성 완료라고 체크하지 않아요.
  3. output/daily/오늘날짜/에 news.json·copy.json·cards/·reel.mp4·REVIEW.md가 있는지 확인해요. 예행연습 날짜를 따로 쓰려면 아래 명령을 사용해요. 예시 2026-10-27은 연습 날짜이며 실제 오늘 날짜로 바꿔도 돼요.

이렇게 보이면 성공

로그에 검수 대기와 날짜 폴더가 있어요. 승인 전이므로 APPROVED.json은 없어요.

이렇게 보이면?

같은 날짜 폴더가 있으면 덮어쓰지 않고 멈추는 것이 정상이에요. 기존 파일을 보관하고 예행연습에는 다른 --date 또는 --output-root를 쓰세요. 실패 폴더가 남았어도 새 경로에서 다시 생성하고 검수해요.

Windows

.venv\Scripts\python.exe daily.py --config config.yaml --feed my-feed.xml --date 2026-10-27 --output-root output/daily-rehearsal

macOS

python daily.py --config config.yaml --feed my-feed.xml --date 2026-10-27 --output-root output/daily-rehearsal

STEP 03 · 다음 날 날짜 폴더 확인하기

다음 날 날짜 폴더 확인하기

지금 하는 일

다음 날 예약 시각 뒤 새 폴더와 실행 로그를 확인해요.

왜 하는지

예행연습과 매일 예약 실행을 구분해요.

따라 하기

  1. PC가 켜진 상태로 다음 예약 시각을 지나게 하세요. 그 뒤 output/daily/다음날짜/REVIEW.md가 생겼는지 확인해요. 예: 10월 27일 실행은 output/daily/2026-10-27/이에요.
  2. daily.log에서 같은 날짜의 검수 대기를 찾고, 어제 폴더가 남아 있는지도 보세요. 생성되는 피드는 매번 현재 my-feed.xml이에요. 같은 자료를 매일 새 뉴스처럼 게시하지 말고, 다음 실행 전에 새 자료와 권리를 직접 확인해 갱신하세요.
  3. 달력에 다음 날 폴더 경로와 검수할 시간을 적어요. 실제 다음 날 폴더를 확인하기 전에는 이 칸을 비워 두세요.

이렇게 보이면 성공

다음 날 폴더와 그 날짜 로그의 검수 대기를 직접 확인했어요.

이렇게 보이면?

폴더가 없으면 PC 전원·잠자기·OS 작업 목록·daily.log의 오류 순서로 보세요. 저장 위치·버전이 바뀌었으면 예약 안내를 다시 만들고 등록해요.

STEP 04 · 날짜별 결과를 검수·승인하고 게시하기

날짜별 결과를 검수·승인하고 게시하기

지금 하는 일

날짜 폴더를 검수한 뒤 앱 게시 또는 API 전송을 선택해요.

왜 하는지

새로 만든 초안이 검수 없이 자동 공개되지 않게 해요.

따라 하기

  1. 문안 확인부터 카드·영상·여섯 항목 검수를 해당 날짜 폴더에서 진행해요. 모든 예제 명령의 output/first-post를 실제 날짜 폴더로 바꾸세요. 수정했다면 render부터 다시 하고 REVIEW.md를 직접 체크해요.
  2. 아래 approve를 실행해 APPROVED.json과 드라이런을 확인해요. 합성 연습은 여기까지예요. 내 자료도 권리·필수 표시가 갖춰졌는지 확인하세요.
  3. 앱 게시: 승인한 날짜 폴더의 실제 JPEG 묶음 또는 MP4를 실습 7로 옮겨 올리고 게시물 주소를 기록해요. API 토큰이 필요 없어요.
  4. API 게시 선택: 실습 8에서 해당 날짜의 승인 파일만 공개 URL로 만들고 --live 없는 드라이런부터 확인해요. 토큰·대상 계정·만료일·권한을 확인한 본인만 아래 --live를 선택해요. 두 게시물(캐러셀과 릴스)을 시도하므로 하나만 올릴 때는 앱을 쓰세요. 필요한 협찬 표시를 설정할 때도 앱을 사용해요.

예시 날짜와 https://사용자.github.io/저장소/날짜폴더는 내 실제 폴더와 URL로 바꿔요. 이 URL은 같은 폴더 안 cards/*.jpg와 reel.mp4의 공통 부모 주소예요.

이렇게 보이면 성공

앱에서 게시물을 다시 열고 주소를 기록했거나, API 결과의 미디어 ID와 실제 게시물·공개 범위를 확인했어요. 드라이런만 했으면 게시 완료 칸은 남겨요.

이렇게 보이면?

승인 뒤 파일 변경 오류는 render → 새 검수 → approve로 해결해요. API 응답이 끊겼다면 LIVE_ATTEMPT.json을 지우거나 전체를 재시도하지 말고 원격 게시 여부부터 확인해요.

Windows

.venv\Scripts\python.exe run_pipeline.py approve output/daily/2026-10-27
.venv\Scripts\python.exe publish.py output/daily/2026-10-27 --base-url "https://사용자.github.io/저장소/날짜폴더"

조건을 모두 확인한 뒤 실제 API 게시를 선택할 때만:

.venv\Scripts\python.exe publish.py output/daily/2026-10-27 --base-url "https://사용자.github.io/저장소/날짜폴더" --live

macOS

python run_pipeline.py approve output/daily/2026-10-27
python publish.py output/daily/2026-10-27 --base-url "https://사용자.github.io/저장소/날짜폴더"

조건을 모두 확인한 뒤 실제 API 게시를 선택할 때만:

python publish.py output/daily/2026-10-27 --base-url "https://사용자.github.io/저장소/날짜폴더" --live

로컬 생성 예약을 지워도 앱/Suite에 이미 저장한 게시 예약은 남아요. 그 예약은 해당 앱 목록에서 따로 확인해요.

선택: 검수한 완성 파일을 앱에서 예약 게시하기

파일 준비와 검수·승인이 끝난 뒤 앱에서 옵션 더 보기 → 이 게시물 예약 / 이 릴스 예약 → 날짜·시간 → 완료 → 돌아가기 → 예약을 확인해요. 현재 도움말은 공개 계정·최대 30일 전·하루 25개를 안내해요.[S037] 예약 목록은 만들기 → 게시물/릴스 → 예약됨, 변경·취소는 항목의 옵션에서 찾아요. 앱이 업데이트되면 버튼 이름이나 위치가 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 공식 도움말을 확인하세요.

계정·현지 시각·필수 표시를 확인하고 저장 뒤 목록에서 다시 열어요. 시간대·AI·협찬·음원 조합을 확인할 수 없다면 앱에서 직접 게시하세요. 생성 예약 목록과 앱의 게시 예약 목록은 따로 확인해요.
