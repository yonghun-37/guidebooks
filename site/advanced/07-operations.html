이 장의 흐름

먼저 답부터

처음엔 로컬 예약으로 돌리고, PC를 계속 켤 수 없으면 상태를 외부에 보존한 뒤 GitHub Actions로 옮기세요. 승인을 기다리는 실행은 종료해도 돼요.

하린 「출근길 3분 생활 뉴스」를 매일 만들고 싶어요.
정 선배 오늘은 OS 예약 파일과 하루 운영 계획부터 확인해요.

지금 하는 일

하루를 tick으로 나눠요

tick은 재개·예약 발행·오늘 새 실행을 확인하는 명령이에요.

새 생성은 OS 현지 시각의 지정 시간 이후 하루 한 번이에요. 아래 그림에서 시작·대기·공개 시각을 구분하고 PC 전원·절전·로그인 사용자를 확인하세요.

지금 할 일 · 설치 파일을 생성해 내용을 읽고 실제 등록은 본인 PC에서 하세요.

알림에는 예외 이유를 담아요

Discord는 알림, Telegram은 허용 사용자 승인으로 연결해요.

기본 notification.json에는 event·run ID·상태·미리보기 정보가 남아요. live에서 .env에 알림 자격을 넣으면 전송해요. Telegram은 TELEGRAM_ALLOWED_USER·TELEGRAM_CHAT_ID를 둘 다 정해요.

python pipeline.py telegram --live는 최대 25초 새 응답을 읽고 끝나요. 승인 후 resume 또는 다음 tick이 발행해요. Discord incoming webhook 자체는 승인 결과를 받지 않아요.[A066][A067][A144]

지금 할 일 · 처음엔 로컬 approve를 쓰고 휴대폰 승인 필요 시 Telegram을 붙이세요.

알림은 Discord 한 채널부터 연결해요

서버의 Webhook URL 하나를 .env에 넣으면 알림을 받을 수 있어요. 웹훅은 정해 둔 채널에 메시지를 보내는 주소예요. 서버 설정을 관리할 수 있는 본인 서버에서 Server Settings → Integrations → Create Webhook을 선택해요. 받는 텍스트 채널을 고르고 Copy Webhook URL로 복사하세요. 이 키트에는 주소 끝에 /github를 붙이지 않아요.[A167]

DISCORD_WEBHOOK_URL=발급받은_웹훅_URL

채널을 볼 수 있는 사람이 알림과 미리보기를 함께 보게 돼요. 본인만 보는 채널부터 쓰세요. URL도 비밀이므로 채팅·공개 저장소에 붙이지 마세요. Discord 알림에는 클릭 승인을 받는 기능이 없어요. 승인은 로컬 approve → resume으로 이어가요.[A066][A144]

휴대폰 승인은 Telegram을 선택해요

봇 토큰·대화방 ID·허용 사용자 ID 세 값이 필요해요. 이 책은 본인과 봇의 개인 대화로 시작해요.

  1. 공식 @BotFather에 /newbot을 보내고 이름과 username을 정해요. 받은 token을 .env의 TELEGRAM_BOT_TOKEN에 넣어요.[A168] Instagram 토큰과 다른 값이에요.
  2. BotFather가 알려 준 내 봇 대화를 열어 Start를 누르고 식별할 문자 하나를 보내세요. 다른 봇에 토큰을 보내지 마세요.
  3. 아래 ID 조회 명령을 한 번 실행해요. 출력의 chat_id를 TELEGRAM_CHAT_ID, user_id를 TELEGRAM_ALLOWED_USER에 넣어요. 토큰이나 메시지 내용은 출력하지 않아요. 빈 목록이면 내 봇에 문자를 다시 보낸 뒤 조회하세요.
  4. 키트의 ops.telegram_* 빈 설정 대신 아래 .env 값을 사용해요. 사용자 ID와 대화방 ID를 바꾸지 마세요. 새 개인 대화에서는 두 값이 같아 보일 수 있어도 각각 응답에서 읽어요.
TELEGRAM_BOT_TOKEN=BotFather가_발급한_값
TELEGRAM_CHAT_ID=응답의_chat_id
TELEGRAM_ALLOWED_USER=응답의_user_id
.\.venv\Scripts\python.exe -c "import json; from transport import HTTP; from common import secrets; v=secrets(); d=HTTP().json('GET','https://api.telegram.org/bot'+v['TELEGRAM_BOT_TOKEN']+'/getUpdates',params={'timeout':0,'allowed_updates':json.dumps(['message'])}); print([{'chat_id':m['chat']['id'],'user_id':m['from']['id']} for u in d.get('result',[]) if (m:=u.get('message')) and m.get('from')])"
python -c "import json; from transport import HTTP; from common import secrets; v=secrets(); d=HTTP().json('GET','https://api.telegram.org/bot'+v['TELEGRAM_BOT_TOKEN']+'/getUpdates',params={'timeout':0,'allowed_updates':json.dumps(['message'])}); print([{'chat_id':m['chat']['id'],'user_id':m['from']['id']} for u in d.get('result',[]) if (m:=u.get('message')) and m.get('from')])"

앱이 업데이트되면 버튼 이름이나 위치가 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 Discord 발급 안내와 Telegram 봇 생성 안내를 확인하세요.[A067]

먼저 알림만 시험해요

다음 명령은 설정한 메신저에 시험 알림만 보내요. 생성·호스팅·게시 API는 호출하지 않아요. .env를 저장한 뒤 실행하고, 받는 채널이나 봇 대화에 [연결 시험]과 연습: 알림 연결 확인이 보이는지 확인하세요.

.\.venv\Scripts\python.exe -c "from ops.notifications import notify; notify({'id':'notification-test','flow':'insta','status':'exception','output':'private/notification-test','gates':{'policy':{'reasons':['연습: 알림 연결 확인']}}},'연결 시험',live=True); print('private/notification-test/notification.json 확인')"
python -c "from ops.notifications import notify; notify({'id':'notification-test','flow':'insta','status':'exception','output':'private/notification-test','gates':{'policy':{'reasons':['연습: 알림 연결 확인']}}},'연결 시험',live=True); print('private/notification-test/notification.json 확인')"

로컬 notification.json의 delivery_failed가 생겼으면 URL·토큰·대화방을 다시 확인해요. 값이 빠진 메신저는 전송을 건너뛰므로 파일 존재만으로 수신 성공을 판단하지 마세요. 실제 실행 알림은 관문 예외·승인 대기·실행 완료 등에 오고 일일 보고는 tick이 보내요.

버튼을 읽는 터미널은 따로 켜 둬요

이 키트의 Telegram 명령은 최대 25초 동안 한 번 읽고 끝나요. OS 예약 생성기는 tick만 등록해요. 휴대폰 승인을 쓴다면 운영자가 같은 PC·같은 config·같은 --state로 아래 수신 명령을 별도 터미널에서 실행해야 해요. 처음엔 명령 실행 → 그 25초 안에 휴대폰 버튼 누르기 순서로 확인하세요. 클릭을 수신하면 승인 기록만 바뀌고 게시 작업은 다음 tick 또는 같은 ID의 resume이 진행해요.

.\.venv\Scripts\python.exe pipeline.py telegram --live --config config.json --state private/state
python pipeline.py telegram --live --config config.json --state private/state

연속 수신하려면 아래 루프를 한 개만 실행하세요. 매번 최대 25초 수신 후 1초 쉬고 반복해요. Ctrl+C로 종료해요. 컴퓨터가 꺼지거나 터미널을 닫으면 수신도 멈춰요. 승인 대기 작업과 수신기의 상태 경로가 다르면 버튼을 처리할 수 없어요. webhook을 따로 등록한 기존 봇 대신 새 봇으로 시작하세요.[A067]

while ($true) {
  .\.venv\Scripts\python.exe pipeline.py telegram --live --config config.json --state private/state
  Start-Sleep -Seconds 1
}
while true; do
  python pipeline.py telegram --live --config config.json --state private/state
  sleep 1
done

지금 할 일 · 실제 승인 대기 알림의 원문·미리보기를 확인하고 수신기를 켠 뒤 본인 버튼을 눌러요. 처리 완료 후 status를 확인하고 resume 또는 다음 예약 tick으로 이어가세요. Actions에서 생성했다면 먼저 최신 외부 상태를 복원하고 결정 기록을 다시 저장해야 해요. 처음에는 로컬 한 PC에서 운영하세요.

Actions는 상태를 밖에 남겨요

새 runner는 어제 SQLite를 자동으로 기억하지 않아요.

examples/github-actions.yml을 본인 저장소에 검토해 복사해요. 암호화된 private 전체는 미디어와 다른 비공개 R2 bucket에 저장해요. pull → 실행 → 항상 push 순서예요. 같은 상태는 같은 concurrency 그룹으로 직렬 실행해요.

STATE_*·STATE_ENCRYPTION_KEY·공급자/플랫폼 키는 Secrets, 비밀 없는 전체 설정은 KIT_CONFIG_JSON이에요. 저장 실패 후 .lease가 남으면 다음 실행은 차단돼요. 공개 artifact·캐시에 토큰/DB를 넣지 마세요.[A046][A155]

지금 할 일 · 먼저 외부 상태 초기화·암호화 안내대로 로컬 상태를 준비하세요. 기본 live=false를 유지하세요.

전자동 전환: A0의 기준을 확인한 뒤 config.json의 mode를 auto로 바꿔요. 로컬 실제 예약 생성 명령에는 --config config.json --live를 붙이고 새 설정으로 등록하세요. 기존 작업을 멈추고 해제한 뒤 새 작업을 등록해 중복을 막아요. Actions는 본인이 AUTO_KIT_LIVE=true를 설정할 때만 정기 live가 켜져요.

schedule은 default branch에서 실행해요. 현재 공식 문서는 IANA timezone을 지원해요. 예: cron: '17 9 * * *' + timezone: Asia/Seoul 또는 UTC 17 0 * * *. 최소 간격 5분, 지연·누락·공개 저장소 60일 비활성 시 예약 중지를 확인하세요.[A044]

코드 없이 돌리는 선택지

기본은 Python이에요. 화면으로 API를 연결하려면 n8n을 비교하세요. 셀프 호스팅은 소프트웨어와 서버·생성 API 비용을 따로 봐요. Instagram 전용 공식 노드가 안 보이면 HTTP Request로 같은 생성→조회→발행을 구성해요. AI 필드가 없으면 HTTP 본문에 is_ai_generated를 명시해요. 커넥터의 Facebook Login 요건을 Instagram Login에 옮기지 마세요.[A057][A060][A150]

Make Free 1,000 credits/월·최소 15분, Zapier Free 100 tasks/월은 게시 편수가 아니에요. 한 게시물의 여러 단계가 각각 사용량이 될 수 있어요. n8n Cloud Starter는 연 €240(월 환산 €20) 표시이며 생성 API는 별도예요. 가져오기 예시는 Python 실행 환경이 있는 셀프 호스팅용이에요.[A131][A062][A055]

따라 하기

터미널은 명령을 입력하는 창이에요. 아래 명령은 auto-kit 폴더에서 실행하세요. A0의 설치를 먼저 마치세요. 새 창을 열면 macOS는 source .venv/bin/activate를 다시 실행해요. RUN_ID는 직전 실행이 출력한 실제 ID로 바꿔요.

.\.venv\Scripts\python.exe -m schedule.install --os windows --flow insta --time 09:17
python -m schedule.install --os macos --flow insta --time 09:17

생성된 install 스크립트를 읽고 출력된 등록 명령을 본인 OS에서 실행하세요. Windows는 Get-ScheduledTask, macOS는 launchctl print로 확인해요. 등록 해제 명령은 생성 파일 끝에 있어요. 아래는 OS 등록 없이 사후 확인·거부를 연습해요.

.\.venv\Scripts\python.exe pipeline.py run --flow insta --provider mock --mode post_review --state private/a7
.\.venv\Scripts\python.exe pipeline.py reject RUN_ID --state private/a7
.\.venv\Scripts\python.exe pipeline.py tick --flow insta --provider mock --mode auto --state private/a7-daily --daily-at 00:00
python pipeline.py run --flow insta --provider mock --mode post_review --state private/a7
python pipeline.py reject RUN_ID --state private/a7
python pipeline.py tick --flow insta --provider mock --mode auto --state private/a7-daily --daily-at 00:00

이렇게 보이면 성공

예약 생성에 예약 파일 생성 완료가 보여요. 사후 확인 run은 scheduled, reject는 rejected예요. tick은 목록에 오늘 새 실행을 한 번만 만들고 같은 날 반복하면 새 실행을 추가하지 않아요. 예시 소스 하나는 이후 날짜에 자동 보충되지 않으므로 실제 운영에는 새 원문 공급이 필요해요.

얼마가 드나요

편당·월 비용 · 2026년 10월

이 장의 mock 명령은 생성 API 사용료가 $0이에요. 실제 카드의 문안 생성비 가정은 편당 $0.00080 × 월 30편 = $0.02400이에요. 입력 3,000·출력 1,000토큰을 Luna 기본 종량 단가 $0.10/$0.50(100만 토큰당)에 곱했어요. 이미지·음성·재시도 없는 가상 계산이에요.[A025]

기존 PC 실행은 생성비 외 전기·인터넷 비용을 확인하세요. 표준 공개 Actions runner는 무료, 비공개 GitHub Free는 월 2,000분 포함이에요. 가상 하루 10분×30일=300분이지만 생성 시간·저장·큰 runner 비용은 별도예요. 상태용 R2도 무료량 초과 과금을 확인하세요.[A045][A048]
