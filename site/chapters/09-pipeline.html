2026년 10월 조사 기준 · 하린과 정 선배는 가상 인물입니다.

?01 · 먼저 답부터

어디부터 어디까지 자동으로 되나요?

이 키트는 소재·문안·카드·릴스를 만들고 사람 검수에서 멈춥니다.

검수와 승인 뒤에도 기본은 실제 전송 없는 요청 미리보기입니다.

하린검수 대기라고 나왔어요. 실패했나요?

정 선배정상입니다. 이제 생성한 파일을 직접 볼 차례입니다.

≡03 · 축별 설명

이 순서로 판단합니다

생성 · 앞의 결과를 다음 입력으로 잇습니다

정의
파이프라인은 작업을 순서대로 연결한 흐름입니다.
흐름
소재 → 문안 → 카드 → 릴스 → REVIEW.md입니다.
기준·예
예: copy.json의 요점을 cards 이미지와 reel.mp4에 담습니다.
조건
기본 offline은 외부 AI를 호출하지 않는 규칙 기반 초안입니다.
언제
같은 소재를 카드와 영상으로 만들 때 씁니다.
지금 할 일
매일 생성 시간과 검수할 시간을 따로 적으세요. 날짜별 폴더는 daily.py가 만듭니다.

승인 · 사람이 파일을 보고 남깁니다

정의
생성된 내용과 권리는 사람이 확인합니다.
흐름
결과 열기 → REVIEW.md 점검 → 승인 → 드라이런입니다.
기준·예
드라이런은 전송하지 않고 요청을 미리 보는 일입니다. dry-run.json은 게시 성공 기록이 아닙니다.
조건
파일이 바뀌면 예전 승인을 쓸 수 없습니다. render는 승인을 지웁니다.
언제
생성 뒤와 수정 뒤마다 합니다.
지금 할 일
인명·숫자·출처·음성 권리를 보고, 바꾸면 재생성 후 다시 승인하세요.

실패·비용 · 끝난 지점에서 원인을 봅니다

정의
모든 실패에서 처음부터 다시 만들 필요는 없습니다.
흐름
마지막 성공 파일 → 오류 원인 수정 → 필요한 단계 재개입니다.
기준·예
예: 카드 글 넘침은 문안을 줄인 뒤 render로 다시 만듭니다.
조건
게시 응답이 끊겼다면 실제 게시 상태부터 확인합니다. 반복 게시도 스팸 제한 대상입니다.[S220]
언제
실패하거나 외부 서비스를 붙일 때 봅니다.
지금 할 일
오류·마지막 성공 단계·다음 행동을 적으세요. 인증 값은 기록하지 않습니다.

코딩 없이도 연결할 수 있지만, 완성 템플릿을 그대로 쓰는 것은 아닙니다. Make의 Sheets→Drive→사진 게시 조합에는 소재 수집·카드 제작·사람 승인을 더 설계해야 합니다.[S153]

Make Free의 월 1,000credits는 게시물 수가 아닙니다. 작업별 소모와 추가 AI 비용을 확인합니다.[S044]

✎06 · 작업실 노트

내 작업 메모를 만드세요

생성·검수·승인·드라이런을 적고, 글 넘침 같은 실패의 재개 위치와 비용을 붙이세요.

매일 정한 시간에 생성 → 사람 검수·승인 → 앱 게시 또는 토큰이 있을 때 실제 전송입니다. 컴퓨터를 켜 두고 실습 9에서 생성 예약을 등록·확인하세요. 다음 날 날짜 폴더가 생겼는지 보고, 실습 6의 검수·승인을 새 파일에 반복합니다. 게시 시간 예약은 앱에서 별도로 정합니다.

틀린 내용이 자동으로 올라가는 건 아닌가요?

기본 흐름은 사람 승인 뒤에도 드라이런입니다.

예: dry-run.json은 전송 계획입니다. 내용과 권리를 확인하고 승인하세요. 설명으로 →

중간에 실패하면 처음부터 다시 해야 하나요?

남아 있는 결과와 실패 단계에 따라 재개합니다.

예: 카드 넘침은 문안을 고친 뒤 render로 잇습니다. 단계표에서 내 오류를 찾으세요. 설명으로 →

코딩 없이 같은 자동화를 만들 수 있나요?

노코드로 연결할 수 있지만 빠진 단계를 더해야 합니다.[S153]

예: 사진 게시 조합에는 카드 제작·승인이 빠져 있습니다. 먼저 내 흐름을 그리세요. 설명으로 →

offline은 새 유료 호출비가 없고 외부 연결은 따로 계산합니다.
