≡03 · 원리

결과물 묶음에 검수 기록 붙이기

파이프라인은 앞 작업의 결과를 다음 작업의 입력으로 잇는 흐름입니다. run_pipeline은 소재 → 문안 → 카드 → 릴스를 만들고 REVIEW.md에서 멈춥니다. 드라이런은 실제 전송 없이 요청을 미리 보는 일입니다. 이 키트의 approve는 승인 기록 뒤 드라이런만 만듭니다.

news.json·copy.json·config.json
소재, 문안, 실행 당시 설정을 보관합니다. config.json은 설정 스냅샷입니다.
cards·reel.mp4·subtitles.srt·audio
이미지·영상·자막·실제 사용 음원입니다. 사람이 열어 보는 대상입니다.
REVIEW.md·manifest.json·APPROVED.json
검수표, 파일 지문 목록, 승인 시점의 기록입니다.
dry-run.json
실제 게시 없이 확인할 요청 계획입니다. 접수증이나 게시 성공 증거가 아닙니다.

해시는 파일의 내용으로 계산하는 지문값입니다. 승인한 문안·이미지·영상·음원 등이 바뀌면 키트는 차이를 확인해 게시 경로를 막습니다. render는 기존 승인을 지우고 새 검수표를 만듭니다. 이것은 로컬 변경 감지이며 사용자 신원 인증 시스템은 아닙니다.

재시도 전에 무엇이 끝났는지 남기기

키트는 이미 있는 출력 폴더에 새 run을 덮어쓰지 않습니다. 다른 이름으로 새 연습을 시작하거나, 기존 문안을 고칠 때 render를 씁니다. 이 보호는 로컬 파일 덮어쓰기 방지입니다. 실제 원격 중복 게시를 막는 완전한 재시도 체계가 구현됐다는 뜻은 아닙니다.

공개 미디어 URL·JPEG 입력·컨테이너 상태·만료·권한·토큰은 실제 게시 실패를 확인할 항목입니다. 중복 재시도 방지와 시간대·승인·오류 기록은 조사 노트의 운영 설계 제안입니다. 실패했다고 무조건 게시 요청을 다시 보내는 습관을 들이지 마세요.[S001][S004][S030][S152]

노코드로 옮겨도 같은 질문을 합니다

Make의 Sheets→Drive→사진 게시, Zapier의 Sheets→사진 게시 공개 조합에는 설명에 없는 RSS 수집·카드 렌더링·승인을 추가 설계해야 합니다. Make·Zapier 커넥터의 계정·연결 페이지·권한 요건을 API 자체 요건과 같은 것으로 일반화하지 마세요.[S153][S154][S155][S156]

Make Free의 월 1000credits는 게시물 1000개가 아닙니다. 액션별 소모와 일부 AI의 가변 과금이 있습니다. n8n도 소스 공개를 무제한 상용 재판매 허용으로 읽으면 안 됩니다. 서버·외부 모델·렌더링 비용을 별도 확인합니다.[S044][S157]

✎06 · 작업실 노트

한 번의 생성, 여섯 항목의 검수

starter-kit 폴더에서 가상환경을 활성화합니다. macOS/Linux는 source .venv/bin/activate, Windows 명령 프롬프트는 .venv\Scriptsctivate.bat입니다. 아래 명령은 Linux의 .venv에서 실행했습니다. Windows/macOS 실기동은 미검증입니다. 시간은 학습 배분입니다.

  1. 통합 생성으로 새 검수 폴더 만들기

    실습 배분 10분 · 준비물: 설치한 키트, 6~8장 경험 · 기대 결과: 카드·릴스·REVIEW.md

    python run_pipeline.py --offline --output output/phase5b-review

    “검수 대기”는 정상 종료입니다. 새 폴더에 카드·릴스·자막·문안과 검수표가 모입니다. 이 명령은 동봉 합성 소재의 새 기본 실행입니다. 6~8장의 수동 편집본을 자동으로 가져오지는 않습니다.

    흔한 오류와 해결: 폴더가 이미 있으면 덮어쓰지 않습니다. 새 연습은 출력 이름을 바꾸세요. 재실행을 실제 게시 재시도와 같은 것으로 보지 않습니다.

  2. 6~8장의 편집을 통합본에 반영하기

    실습 배분 10분 · 준비물: 최종 copy.json·권리 메모 · 기대 결과: 검수할 통합 최종본

    이전 편집본을 쓰려면 output/phase5b-manual/copy.json을 output/phase5b-review/copy.json에 복사합니다. 두 news.json이 같은 동봉 합성 소재인지 확인하세요. 다른 소재의 문안을 섞지 마세요. 테마·길이·음원 선택은 출력 폴더의 config.json을 고칩니다. 테마는 이 파일의 colors 값에 반영해야 하며 config.yaml의 theme만 바꿔도 기존 실행은 변하지 않습니다.

    python run_pipeline.py render output/phase5b-review

    재생성 후에는 새 REVIEW.md를 사용합니다. 음원은 config.json에서 본인 파일의 절대 경로를 지정하면 위치 혼동을 줄일 수 있습니다.

    흔한 오류와 해결: 본문 캡션을 REVIEW.md에서만 고치면 copy.json은 그대로입니다. 문안은 copy.json에서 고치고 render를 실행합니다. render는 실패하더라도 기존 승인을 먼저 지웁니다.

  3. 검수표의 여섯 항목 직접 확인하기

    실습 배분 20분 · 준비물: 모든 PNG/JPEG·MP4·원자료·권리 기록 · 기대 결과: 직접 체크한 REVIEW.md

    REVIEW.md를 열고 원자료의 사실, 모든 PNG/JPEG의 글자·출처, 영상 전체의 움직임·자막·소리, 자료·폰트·사진 권리와 AI 표시, 내레이션·음악·TTS 권리, 최종 caption을 순서대로 확인합니다. 사용하지 않은 음원은 “해당 없음”으로 검토합니다. 완료한 줄만 - [ ]를 - [x]로 고치고 저장합니다.

    합성 피드는 실제 뉴스가 아닙니다. 합성 표시를 유지하고 실제 계정에 게시하지 마세요. 드라이런 검수 결과와 남은 불확실성을 실행 메모에 적습니다.

    흔한 오류와 해결: 체크만 먼저 채우면 의미가 없습니다. 해결하지 못한 사실·권리 항목은 미완료로 두고 승인하지 않습니다. 검수표 자동 체크 명령은 사용하지 않습니다.

  4. 승인 기록과 드라이런 확인하기

    실습 배분 10분 · 준비물: 완료한 여섯 검수 항목 · 기대 결과: APPROVED.json·dry-run.json

    python run_pipeline.py approve output/phase5b-review

    키트는 승인 시각과 파일 해시를 남기고 캐러셀·릴스 요청 계획을 출력합니다. dry-run.json은 실제 전송이 아닙니다. 자리표시자는 실제 계정 값이 아닙니다. 검수 항목이 남아 있으면 오류로 막히는 것이 정상입니다.

    흔한 오류와 해결: 출력에 게시 단계가 있다고 게시 성공으로 기록하지 마세요. 실제 계정의 권한·호스팅·접수 결과는 확인하지 않았습니다.

  5. 수정 후 다시 멈추는지 확인하기

    실습 배분 10분 · 준비물: 승인한 폴더, 수정할 subtitle · 기대 결과: 재검수 흐름 확인

    copy.json의 subtitle 문장 하나를 사실을 바꾸지 않는 범위에서 고치고 아래 render를 실행합니다. APPROVED.json이 사라지고 REVIEW.md의 체크가 다시 비어 있는지 봅니다. 새 영상을 확인한 뒤에만 여섯 칸을 다시 체크하고 approve를 실행합니다.

    python run_pipeline.py render output/phase5b-review
python run_pipeline.py approve output/phase5b-review

    두 줄을 한꺼번에 붙이지 마세요. 첫 줄 뒤에 직접 검수·저장하는 시간이 들어갑니다. 검수 전 두 번째 줄은 차단되어야 합니다. 끝에 실행 메모를 남기고 10장으로 넘깁니다.

    흔한 오류와 해결: 예전 승인 파일을 복사해 복구하지 마세요. 변경된 파일은 새로 검수합니다. 이 키트의 로컬 해시 기록만으로 원격 중복 게시가 해결됐다고 기록하지 않습니다.

✓08 · 핵심 정리

자동화에는 멈출 자리도 들어갑니다

  • credits와 게시 개수를 구분하고 외부 비용·오류 기록을 남깁니다.
