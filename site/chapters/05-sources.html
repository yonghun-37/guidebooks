소재 찾기: 뉴스 소싱과 저작권

소재를 발견하는 통로와 이용 권리를 구분하고, 원문·권리·미확인 상태를 함께 기록합니다.

정책·수치·법률·사례는 2026년 10월 조사 기준입니다. 각주의 확인 범위와 미확인 항목을 함께 읽으세요.

이 장의 흐름

?01 · 일상의 질문

“RSS에 들어온 기사면 카드로 옮겨도 되나요?”

하린“4장의 첫 소재를 찾았어요. 제목·요약이 피드로 오면 사진과 함께 옮겨도 될까요?”

정 선배“소재를 찾는 통로와 이용할 권리는 다른 칸이야. 원문에서 사실을 확인하고 문장·사진의 이용 조건을 따로 보자.”

하린은 계정 기획 시트의 소재 후보 옆에 원문 URL·게시일·사건일·권리·확인일을 적을 자리를 만듭니다.

두 인물과 학습 기록은 가상입니다. 실적을 나타내지 않습니다.

≡03 · 원리

찾을 수 있는 것과 쓸 수 있는 것을 나누기.

RSS는 새 소식을 받는 통로입니다.

RSS를 쓰면 관심 소스의 후보를 모으는 작업을 줄일 수 있습니다. 후보 목록에는 원출처와 확인일을 남기세요. 제목이 같아도 게시일과 사건 발생일을 구분하고, 재전재된 기사들이 같은 원자료를 인용하는지도 살펴봅니다. 이 과정은 교재의 편집 절차입니다.

네이버 뉴스 검색 API는 제목·원문 링크·짧은 설명 등 검색 결과를 제공합니다. 이 필드를 받았다고 기사나 사진을 재게시할 이용허락(라이선스)이 생기는 것은 아닙니다. 기존 개발자센터와 NAVER API HUB는 인증·호스트가 달라 예전 가입 안내를 그대로 따라 하면 안 됩니다. 이 장은 API 키를 발급하거나 호출하지 않습니다.[S120][S010][S159]

정부 보도자료도 개별 공공누리 표식과 첨부물 권리를 확인해야 합니다. RSS·빅카인즈·공공데이터의 개별 상업 재이용 약관을 이번 조사에서 모두 확인한 것은 아닙니다. “공공”이나 “무료 검색”을 전체 복제 허락으로 바꾸지 마세요.[S128][S010]

사실·표현·사진을 따로 보기.

저작권법 제7조제5호는 사실 전달에 불과한 시사보도를 보호 대상에서 제외합니다. 그러나 창작적인 기사 표현과 보도 사진까지 모두 제외하는 규칙은 아닙니다. 사실을 내 말로 설명할 때도 원문 표현이나 도표·사진을 그대로 옮기는지 구분해야 합니다.[S010][S080]

인용은 공표된 저작물을 보도·비평·교육·연구 등을 위해 정당한 범위와 공정한 관행에 맞게 이용하는 조건을 검토합니다. 출처 명시는 별도 의무이므로 링크만 달면 기사 전체를 복제해도 된다는 뜻이 아닙니다.[S010]

공정 이용은 목적·성격, 저작물 종류·용도, 이용 분량과 중요성, 시장·가치 영향을 함께 봅니다. 모두에게 통하는 안전 글자 수·복제 비율·영상 초수는 이번 근거로 확정할 수 없습니다. “짧게 자르면 안전”이라는 규칙을 만들지 마세요.[S010]

기사 제목·본문·RSS·스크린샷·사진·영상·음원·폰트의 권리는 각각 확인할 필요가 있습니다. 특정 매체가 피드를 제공한다는 사실만으로 상업적 뉴스카드 재게시를 허락했다고 볼 근거는 확보하지 못했습니다.[S010]

공공누리도 유형과 저작물을 대조하기.

공공누리의 1유형은 출처 표시와 상업 이용·변경 허용, 2유형은 비상업, 3유형은 변경 금지, 4유형은 비상업·변경 금지 조건을 둡니다. 기관 홈페이지 전체가 같은 허락이라고 가정하지 말고 실제 저작물과 첨부 사진의 표식을 확인하세요.[S128]

위 표는 공공누리 조건을 확인하는 연습입니다. 사진에 등장하는 사람의 초상·사생활과 개인정보는 별도 문제입니다. 공개 장소 촬영이나 공개 SNS 게시만으로 모든 재이용이 적법해지는 것은 아닙니다. 개별 사안의 적용은 확인이 필요합니다.[S081][S078]

허락 확인과 사실 대조는 모두 남깁니다.

교재의 편집 규칙으로 다음을 제안합니다. 원문에서 누가·언제·무엇을·어떤 조건에서 발표했는지 확인합니다. 수치·단위·부정 표현을 대조하고, 원자료를 보지 못하면 “미확인”으로 남깁니다. 필요한 인용은 내 설명과 구별하고 인용 이유·범위·저자·제목·매체·일자·링크를 기록합니다. 사진은 별도 증빙이 없으면 넣지 않고 직접 만든 도식 등 대안을 검토합니다.

AI 학습의 공정이용 안내와 생성 결과물의 침해 예방은 서로 다른 문제입니다. AI를 거쳤다고 기사·사진의 자유 재게시가 허용되는 것은 아닙니다. 또한 조사에서 한국어 뉴스 요약의 오류율이나 오류 제거 보장 수치는 확보하지 못했습니다.[S171][S172][S010][S053]

오류를 발견했다면 원문과 수정 전 기록을 보관하고, 예약을 멈추고, 사실을 재확인한 뒤 정정·삭제 필요성을 검토하는 절차를 제안합니다. 바뀐 내용·이유·확인 시점을 남겨 다른 게시본도 점검하세요.

↔04 · 시뮬레이터

이 소재에서 빠진 확인은 무엇일까요?

소재 이용 검토 흐름도

교육용 가정 모형

Tab으로 입력을 선택하세요. 슬라이더는 방향키·Home·End로 바꿀 수 있습니다. 입력값은 저장하지 않습니다.

게시 허가를 내리는 도구가 아닙니다. 빠진 확인을 찾는 흐름도입니다. 모든 항목은 처음에 미확인입니다.

자바스크립트를 켜면 입력에 따른 결과가 나옵니다. 계산 원리는 아래에 있습니다.

출처 기록 → 허락 범위 또는 인용·공정 이용 검토 → 초상·개인정보 등 다른 권리 → 사실 대조의 학습 순서입니다. 허락과 인용은 서로 다른 근거입니다. 선택값은 사용자의 자기보고이며 계약·법적 적합성·정확성을 자동 판정하지 않습니다. 모두 확인을 골라도 “게시 가능”이나 법률적 면책을 출력하지 않습니다.

◎05 · 실제 사례

기사·사진을 개별적으로 본 역사적 판결.

대법원 2004도5350 판결(2006년 9월 14일)은 기사와 사진을 개별 검토해 단순 사실 전달 수준을 넘는 것의 복제 책임을 판단해야 한다며 원심을 파기환송했습니다. 모든 뉴스가 저작권 밖이라는 사례가 아닙니다. AI 요약 사건도 아니며 환송 후 최종 결과는 이번 조사에서 확인하지 못했습니다.[S080]

기획 시트에 적용할 질문은 하나입니다. “내가 가져오는 것은 사건의 사실인가, 기사 표현인가, 사진인가?” 같은 페이지에 있어도 각각 기록해 봅시다.

✎06 · 작업실 노트

RSS 소스 목록과 내 인용 규칙 남기기.

확인한 실행 명령

키트 설치 안내를 마친 뒤 starter-kit 폴더에서 실행합니다. 아래 명령은 Linux의 starter-kit/.venv에서 실제 실행해 확인했습니다.

.venv/bin/python fetch_news.py --feed fixtures/sample-feed.xml --output output/phase-5a/news.json

Windows 명령 프롬프트(cmd)에서는 Python 실행 파일 경로만 .venv\Scripts\python.exe로 바꿉니다. macOS/Linux는 위 경로를 씁니다. Windows·macOS에서의 실제 실행은 검증하지 않았습니다.

기대 결과는 output/phase-5a/news.json입니다. 키트는 이 경로의 JSON을 다시 실행할 때 덮어쓰므로 직접 편집한 기록은 다른 이름으로 보관하세요. 이번 실습은 로컬 파일만 읽습니다. 키·계정·온라인 API가 필요하지 않습니다.

키트의 현재 수집기는 RSS 2.0의 channel/item 구조를 읽고 최대 세 항목의 제목·링크·짧은 요약만 보관합니다. 다른 피드 형식인 Atom과 기사 전문 수집은 지원하지 않습니다. published는 피드에 적힌 값이며 사실 대조 완료 표식이 아닙니다.

소요 시간은 실습 배분 예시입니다. 메모 본문은 직접 파일로 저장하세요.

  1. 소재 후보와 소스 목록 만들기

    4장의 후보에서 하나를 고릅니다. 아래 목록을 메모에 복사하고 합성 피드와 운영 후보를 구분합니다. 운영 후보의 실제 RSS URL·이용 약관은 확인하기 전까지 “미확인”으로 둡니다.

    배분 10분 · 준비물: 4장 시트와 메모 · 기대 결과: RSS 목록과 확인 대기 후보

    흔한 오류: 검색 결과 페이지나 일반 홈페이지 주소를 RSS URL 칸에 넣지 마세요.

  2. 합성 RSS를 수집해 구조 보기

    스타터 키트 README의 설치를 마친 뒤 starter-kit 폴더에서 위의 확인한 실행 명령을 실행합니다. output/phase-5a/news.json을 메모장으로 열어 title·link·summary·published·synthetic을 찾습니다. 가상 링크를 실제 취재 근거로 쓰지 않습니다.

    배분 10분 · 준비물: 설치된 키트·터미널 · 기대 결과: 합성 news.json

    흔한 오류: 파일을 찾지 못하면 현재 폴더에 fetch_news.py가 있는지 확인하세요. .venv 오류는 README 설치 절로 돌아갑니다.

  3. 실제 후보의 원문과 권리표 채우기

    운영 후보 한 건은 브라우저에서 원문과 이용 조건을 직접 읽습니다. 사실·문장·사진을 나눠 기록하고, 허락을 못 찾으면 미확인·사용 보류로 남깁니다. 이 단계에서는 온라인 수집을 켜지 않습니다.

    배분 15분 · 준비물: 원문·이용 조건 페이지 · 기대 결과: 소재별 확인 기록

    흔한 오류: 공공누리 표식이 본문과 첨부물 모두에 적용되는지 따로 보세요.

  4. 내 인용 규칙을 적고 다음 장에 넘기기

    흐름도에서 “출처만 있음”을 고른 뒤 빠진 확인을 읽습니다. 확인한 사실만 내 말로 적고 인용 이유·범위·출처·사진 허락을 분리합니다. 6장에는 원문 링크와 미확인 상태까지 함께 전달합니다.

    배분 10분 · 준비물: 검토 기록과 흐름도 · 기대 결과: 소스 목록·인용 규칙

    흔한 오류: 미확인 항목을 AI에게 채워 달라고 하지 말고 확인할 질문으로 남기세요.
