게시 버튼을 누르기 전에 요청서를 읽습니다. 계정 연결 없이 드라이런을 확인하고, 예약 도구에 넣을 경로와 시각을 정리합니다.

정책·법·가격·플랫폼 수치는 2026년 10월 조사 기준입니다. 연습 시간과 가상 사례의 숫자는 교육용 설정입니다.

내가 승인한 바로 그 파일이, 정한 시각에 어떤 요청으로 나갈까요?

≡03 · 원리

키트의 기능과 서비스의 조건을 나눠 읽기

게시 통로를 먼저 고르기

공식 API는 앱의 게시 버튼과 다른 통로입니다. 키트는 그중 Instagram Login 경로의 요청서를 보여 줍니다.

Instagram Login은 비즈니스·크리에이터 같은 프로페셔널 계정을 대상으로 하며 Facebook 페이지 연결을 요구하지 않습니다. 게시 권한은 instagram_business_basic·instagram_business_content_publish, 요청 호스트는 graph.instagram.com입니다.[S002·S001]

Facebook Login은 Facebook 페이지에 연결된 프로페셔널 계정이 대상입니다. graph.facebook.com을 쓰며 게시 권한 묶음도 다릅니다. 개인 계정에서 그대로 쓸 수 있는 경로가 아닙니다.[S033·S029·S001]

현재 Overview는 Unified Login도 비교하고 새 통합에 권장합니다. Facebook 페이지 없이 연결할 수 있으나 비즈니스 포트폴리오 등 별도 요건이 있습니다. 이 키트가 Unified 온보딩까지 구현한 것은 아니며 한국 실사용은 미검증입니다.[S033]

본인 소유·관리 계정의 Standard Access와 다른 사업자 계정에 제공하는 Advanced Access를 구분하세요. 후자는 앱 검수와 사업체 인증 요건을 확인해야 합니다. 키트 실행이 앱 검수를 대신하지 않습니다.[S031·S030·S033]

요청서를 세 줄로 읽기

아직 밖으로 보내지 않고 요청 내용을 확인하는 연습을 드라이런이라고 부릅니다. Meta가 제공하는 계정 안전 보증 기능이 아니라 이 키트의 로컬 기능입니다.

게시 흐름은 media로 준비 상자인 컨테이너 생성 → status_code가 FINISHED인지 확인 → media_publish로 발행입니다. URL 가져오기 방식에는 Meta가 읽을 수 있는 공개 미디어 URL이 필요합니다. 내 컴퓨터 경로는 그 URL이 아닙니다.[S001]

API 이미지는 JPEG입니다. 미디어 문서는 최대 8MB, 비율 4:5~1.91:1, 너비 320~1440px를 적습니다. 키트의 cards/*.png는 학습용이고, 함께 생성된 cards/*.jpg가 게시 요청의 입력입니다.[S001·S004]

릴스 API 문서는 MOV/MP4, H.264/HEVC, 23~60fps, 길이 3초~15분, 최대 300MB와 9:16 권장을 안내합니다. 파일 제작 성공과 API의 실제 수용 성공은 따로 확인합니다.[S004]

예약 시각과 API 한도는 다른 질문

공식 문서 안에서도 이동 24시간 발행 한도를 일반 설명은 100건, 캐러셀 절과 한도 레퍼런스는 50건으로 다르게 적고 있습니다. 어느 하나를 확정 기본값으로 삼지 않습니다. 캐러셀 한 묶음은 발행 한 건으로 셉니다. 개별 계정의 실효값은 미확인입니다.[S001·S003]

미발행 컨테이너는 24시간 뒤 만료되며 문서에는 계정당 24시간 400개 생성 제한도 있습니다. 컨테이너 수·발행 수·일반 API 호출 수는 다른 단위입니다. 먼 미래의 게시용 컨테이너를 미리 만드는 방식은 피하고 실행 시 준비하는 설계를 검토하세요.[S004·S001·S035]

이 책의 예약 설계는 시각·시간대 → 승인 버전 → 요청 실행 → 결과 기록입니다. 로컬 키트에 예약 기능은 없습니다. 운영체제의 예약 도구가 검수된 폴더의 드라이런 명령을 호출하도록 따로 설정합니다. 자정이 되면 모든 한도가 초기화된다고 가정하지 마세요.

Instagram 앱과 Business Suite의 예약 메뉴·기간·대상은 별도로 확인해야 합니다. 조사에서 검색 요약은 얻었지만 한국 계정의 현행 화면과 제약은 충분히 검증하지 못했습니다. 고정 예약 가능 일수를 이 실습의 약속으로 쓰지 않습니다.[S037·S039]

Zapier 안내는 Business/Creator와 연결된 Facebook 페이지 등을 요구합니다. Make의 Facebook Login 커넥터는 Business 계정과 연결 페이지 관리 권한을 요구합니다. API의 페이지 불필요 조건을 모든 커넥터에 적용하지 마세요.[S155·S156·S002]

Make credits, Zapier task, n8n workflow executions는 과금 단위가 다릅니다. 승인·상태 조회·재시도·호스팅·외부 AI 비용을 따로 세세요. 무료 처리량을 게시물 수와 같다고 읽으면 안 됩니다.[S044·S045·S041·S046·S048·S001]

승인 후 바뀌면 멈추기

키트는 APPROVED.json에 검수 파일의 해시, 즉 파일 변경을 알아보는 지문을 남깁니다. 수정하면 다시 만들고 검수해야 합니다. 실제 게시 경로는 시작할 때 LIVE_ATTEMPT.json을 남겨 같은 폴더의 재실행을 막습니다. 응답이 끊겨도 일부가 게시됐을 수 있으므로 이 파일을 지워서 재시도하지 마세요. 이 장에서는 실제 게시를 실행하지 않습니다.

인증을 허락받았음을 증명하는 액세스 토큰은 영구 비밀번호가 아닙니다. Instagram Login 장기 토큰은 60일이며 발급 뒤 24시간 이상 지났고 아직 유효할 때 갱신할 수 있습니다. 실제 값은 화면·메모·공개 저장소에 넣지 마세요.[S030·S034]

API는 is_ai_generated=true 자기공개를 지원하고 캐러셀은 부모 컨테이너에만 설정합니다. 키트의 copy.json에서 이 값을 바꾸면 재생성·재검수가 필요합니다.[S032·S001]

파트너십 라벨 파라미터 지원은 문서상 Facebook Login 경로입니다. 같은 기능을 Instagram Login에 가정하지 마세요. 키트는 광고·파트너십 전용 파라미터를 지원하지 않습니다. 필요한 표시를 지원하는 게시 경로를 별도로 고릅니다.[S001·S032]

◎05 · 실제 사례

공개 템플릿에는 어디에 승인이 있을까?

n8n 카탈로그의 20222 템플릿은 폼 → Gemini 초안 → 규칙 검사 → Telegram 사람 승인 → 컨테이너 생성·조회 → Instagram 게시를 설명합니다. 제작자가 제공한 템플릿 설명을 읽은 사례이며 이 책에서 실행한 워크플로는 아닙니다.[S152]

Make와 Zapier의 공개 Sheets→사진 게시 조합에는 설명에 없는 소재 수집·렌더링·승인을 추가로 설계해야 합니다. 템플릿이 있다는 사실만으로 내가 만든 뉴스카드의 전체 흐름이 준비된 것은 아닙니다.[S153·S154]

가져올 패턴은 ‘승인 위치를 눈에 보이게 두기’입니다. 계정 비밀번호나 토큰을 템플릿 메모에 적어 넣는 방식은 피하세요.
