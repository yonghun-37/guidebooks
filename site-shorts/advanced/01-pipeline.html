먼저 답부터

주제·대본·영상·검사·게시 ID를 나눠 저장하세요. 실패하면 같은 실행 ID로 이어 가세요.

월급날 네 칸 영상의 음성이 완성된 뒤 인터넷이 끊겨도 새 영상부터 만들지 않아요. 어느 단계가 끝났는지 기록을 먼저 읽어요.

도윤실패하면 전부 다시 결제하나요?

서진완료한 단계와 파일은 재사용해요. 게시 결과를 모를 때는 기존 세션부터 확인해요.

만드는 순서

원문과 결과를 따로 남겨요

실행 ID 하나가 한 편의 모든 파일을 묶어요.

해시는 파일 내용을 짧은 문자열로 비교하는 지문이에요. 키트는 문안 지문과 대상 채널로 같은 콘텐츠를 다시 게시하는 일을 막아요. DB는 표처럼 기록을 저장하는 파일이에요. 여기서는 SQLite state.sqlite를 써요.

지금 할 일 status로 실제 실행 ID를 메모하세요.

같은 ID를 이어 실행해요

완료한 단계는 건너뛰고 실패 지점부터 처리해요.

예: render를 마쳤다면 MP4와 음성 파일을 다시 만들지 않아요. 렌더 도중 실패했어도 이미 저장된 생성 파일은 재사용해요. 설정은 실행 시작 때 고정해요. 원래 config.json만 고쳐도 옛 실행 내용은 바뀌지 않아요. 문안을 바꿨다면 새 실행에서 검수하세요.

업로드 뒤 응답이 유실되면 uncertain이에요. 세션 주소 Location은 보낸 위치를 다시 물을 비밀 주소예요. 같은 세션의 상태를 조회하고 남은 바이트만 보내요.[A019]

지금 할 일 resume RUN_ID에 원래 ID를 넣으세요.

승인은 최종 결과에 묶어요

문안·파일·채널·공개 범위·AI 표시·예약을 바꾸면 다시 검수해요.

예: 승인한 private를 public으로 고치면 기존 승인을 쓸 수 없어요. 키트는 묶인 해시가 바뀌면 관문 이후 파일·문안·대상이 바뀌었습니다로 막아요. 승인 기록을 직접 편집해 우회하지 마세요. 사후 확인의 scheduled는 거부할 수 있지만, 이미 공개된 영상의 되돌리기까지 뜻하지 않아요.

지금 할 일 승인한 ID·파일·대상 채널을 함께 기록하세요.

해 보기 · 명령 실행

지금 하는 일: 실행 ID·단계·파일을 연결한 내 복구 지도을 확인해요.

왜 하는지: 앞 단계의 실제 파일과 상태를 읽어 다음 작업을 이어 가기 위해서예요.

아래 명령은 auto-kit 폴더에서 실행하세요. A0에서 가상환경을 먼저 준비해요. RUN_ID가 있으면 앞 명령이 출력한 실제 12자리 ID로 바꿔요. Windows와 macOS는 같은 Python 명령을 써요.

python pipeline.py run --flow shorts --provider mock --state private/review-demo
python pipeline.py status --state private/review-demo
python pipeline.py approve RUN_ID --state private/review-demo
python pipeline.py resume RUN_ID --state private/review-demo
python pipeline.py run --flow shorts --provider mock --state private/review-demo
python pipeline.py status --state private/review-demo
python pipeline.py approve RUN_ID --state private/review-demo
python pipeline.py resume RUN_ID --state private/review-demo

이렇게 보이면 성공

RUN_ID 네 글자가 아니라 첫 명령의 12자리 ID를 넣으세요. 처음은 waiting_approval, approve도 같은 상태를 출력해요. resume 뒤 dry_run이에요. 승인만으로 게시하지 않아요.
