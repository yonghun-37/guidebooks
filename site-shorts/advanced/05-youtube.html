먼저 답부터

Desktop OAuth로 내 채널을 확인하고 private 1편부터 보내세요. 중단되면 같은 업로드 세션으로 재개해요.

YouTube는 로컬 MP4를 직접 받아요. 공개 미디어 URL을 만들 필요가 없어요. 업로드 완료·처리 완료·공개·Shorts 분류는 각각 확인해요.[A019][A022]

도윤public으로 요청했는데 왜 비공개인가요?

서진먼저 일반 private인지 제한 잠금인지 확인해요. 잠금은 public 요청을 반복해도 해결되지 않아요.

만드는 순서

브라우저에서 한 번 동의해요

업로드·채널 확인·분석·예약 취소에 필요한 scope를 구분하세요.[A017][A024]

A2에서 Desktop app 파일을 private/client_secret.json에 저장했으면 아래를 본인 PC에서 실행해요. 이 절의 연결 명령은 실제 브라우저 동의와 네트워크를 사용해요. 직접 선택한 채널과 권한을 확인하세요.

python -m pip install --only-binary=:all: -r requirements-live.txt
python oauth_setup.py --config config.json --analytics --post-review
python -m pip install --only-binary=:all: -r requirements-live.txt
python oauth_setup.py --config config.json --analytics --post-review

동의 뒤 정상이라면 OAuth 토큰 저장 완료와 private/google-token.json이 생겨요. 키트는 youtube.upload 외에 실제 대상 확인용 youtube.readonly, 분석 옵션의 yt-analytics.readonly, 예약 취소용 youtube.force-ssl을 요청해요. 수익 보고에는 별도의 monetary scope와 계정 조건이 필요해요.[A017][A024]

지금 할 일 기존 토큰의 scope가 부족하면 비공개 백업 후 재동의하세요.

private·아동용·AI 필드를 명시해요

publishAt 예약은 private이고 공개된 적 없는 영상에 설정해요.[A020]

POST /upload/youtube/v3/videos?uploadType=resumable&part=snippet,status
Authorization: Bearer <REDACTED>
Content-Type: application/json
X-Upload-Content-Type: video/mp4
X-Upload-Content-Length: <실제 파일 바이트 수>

{"snippet":{"title":"월급날 10분, 돈을 네 칸으로 나누기"},
 "status":{"privacyStatus":"private",
 "selfDeclaredMadeForKids":false,"containsSyntheticMedia":true}}

HTTP/1.1 200 OK
Location: <비공개로 저장한 세션 주소>

위는 필드를 읽기 위한 요청 예예요. 토큰·세션 주소는 가렸어요. 아동용 여부와 사실적인 합성 공개 여부는 서로 다른 Boolean(참/거짓)이에요. isShorts는 업로드 필드가 아니에요. 실제 최종 영상으로 판단하세요.[A020][A071]

PUT <같은 세션 주소>
Content-Length: 0
Content-Range: bytes */<전체크기>

HTTP/1.1 308 Resume Incomplete
Range: bytes=0-262143

다음 전송: bytes 262144-.../<전체크기>
완료 응답 예: {"id":"<영상 ID>","status":{"privacyStatus":"private"}}

위 바이트 수는 프로토콜 설명용 가상 예예요. 마지막을 제외한 청크는 256KiB 배수로 보내요. 실패하면 같은 세션에 받은 위치를 묻고 이어 보내세요. Location 자체를 받았는지 불명확하면 새 insert를 만들지 말고 Studio에서 먼저 대조해요.[A019]

지금 할 일 A0 결과의 request-plan.json에서 network_calls: 0과 REDACTED를 확인하세요.

하루 상한은 내 프로젝트에서 확인해요

현행 insert는 전용 버킷 1 unit/호출·기본 100회/일이에요.[A012][A013]

묶음조사 기준 기본량예제 운영
videos.insert100호출/일 · 호출당 1 unit키트 로컬 cap은 1편/일
search.list별도 100호출/일주제용 검색을 쓴다면 별도 계산
그 밖의 호출10,000 units/일조회·수정·취소 비용 확인

과거 1,600·100 unit 업로드 견적으로 계산하지 마세요. 실패 요청도 소모하고 채널 업로드 제한도 따로 있어요. Pacific 자정 리셋을 내 현지 날짜와 구분하세요.[A014][A013]

Cloud 콘솔에서 보통 이런 이름의 API 및 서비스 → YouTube Data API v3 → 할당량/Quotas에서 실제 버킷을 확인해요. 앱이 업데이트되면 버튼 이름이나 위치가 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 공식 도움말을 확인하세요.

config.json의 youtube.quota_daily_insert는 내 실제 한도 이하의 운영 상한으로, quota_confirmed_at은 확인한 UTC 시각으로 채워요. 키트는 30일 넘은 확인 기록이면 연기해요. 이 30일은 키트 설정 동작이에요.

지금 할 일 내 버킷을 확인한 뒤 cap·확인 시각을 기록하세요.

실제 업로드는 새 실행에서 시작해요

mock 결과를 live로 승격하지 말고, 내 원문·소재·설정으로 새 실행하세요.

sources.files를 내 자료로 바꾸고 synthetic:false·rights_reviewed:true는 실제 권리 확인 뒤 설정하세요. providers.llm·tts, 소재·비용 상한·OAuth·quota 기록까지 준비해야 해요. mode는 approval, privacyStatus는 private로 유지하세요.

python doctor.py --config config.json --live --flow shorts
python pipeline.py run --flow shorts --config config.json --live --state private/shorts-live
python pipeline.py approve RUN_ID --state private/shorts-live
python pipeline.py resume RUN_ID --live --state private/shorts-live
python doctor.py --config config.json --live --flow shorts
python pipeline.py run --flow shorts --config config.json --live --state private/shorts-live
python pipeline.py approve RUN_ID --state private/shorts-live
python pipeline.py resume RUN_ID --live --state private/shorts-live

여기의 RUN_ID는 바로 위 live run이 출력한 실제 12자리 ID예요. A0 mock ID와 섞지 말고 private/shorts-live 경로를 계속 쓰세요. 이 명령은 사용자 생성 API 비용과 실제 업로드를 발생시켜요. doctor에 오류가 없으면 run에서 waiting_approval, 직접 확인 후 approve·resume으로 done과 영상 ID가 남는지 확인하세요. Studio에서 처리·공개 범위·제한·라벨·Shorts 분류를 직접 보세요.

사후 확인은 mode:post_review, review.hours 기본 2로 미래 publishAt을 계산해요. 이는 키트의 가상 운영 설정이에요. 예약 취소는 python pipeline.py reject RUN_ID --live --state private/shorts-live로 업로드 영상을 삭제해요. 204 삭제 응답 확인 전 취소 완료로 판단하지 않아요. 실제 예정 시각·시간대도 확인하세요.[A020]

지금 할 일 첫 private 성공 후에 예약·공개 전 거부를 별도로 시험하세요.
