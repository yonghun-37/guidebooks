대본·음성·장면을 API로 만들기

먼저 답부터

LLM 한 개와 TTS 한 개부터 연결하세요. 이미지·영상 API는 같은 대본이 안정된 뒤 더해요.

LLM은 글을 만드는 모델이에요. TTS는 글을 음성으로 읽는 서비스예요. 먼저 월세·생활비·비상금·목표를 설명하는 대본을 정해 같은 장면으로 이어 가요.

도윤JSON으로 달라고 하면 바로 게시해도 되나요?

서진구조와 내용은 따로 검사해요. 형식이 맞아도 원문에 없는 숫자를 만들 수 있어요.

한눈에 보기

만드는 순서

설명문이 섞이면 멈춰요

구조화 출력과 JSON Schema 검증을 모두 통과해야 해요.

스키마는 필수 이름·자료형·길이를 정한 입력 규칙이에요. 키트의 providers/content.schema.json은 title·caption·narration·entities·scenes를 요구해요. 장면은 2~5개가 키트 기본 규칙이에요. 동봉 영상은 훅 1개와 네 칸 설명, 총 5장면이에요.

공급자어댑터가 보내는 구조화 출력 이름근거
OpenAI Responsestext.format → json_schema · strict[A026]
GeminigenerationConfig.responseMimeType · responseJsonSchema[A029]
Anthropicoutput_config.format → json_schema[A033]

키트 스키마가 같아도 공급자 요청 필드는 달라요. 거절·잘림·파싱 실패를 게시 가능한 문안으로 쓰지 마세요. 기본 max_attempts 2는 유료 재시도도 포함한 키트 설정이에요. 지원되는 모델·스키마 부분집합을 확인하세요.

지금 할 일 먼저 아래 명령으로 실제 draft를 읽으세요.

처음엔 Luna와 WaveNet

providers.llm은 openai, providers.tts는 google로 설정해요.

"providers": {"llm":"openai", "image":"mock", "tts":"google", "video":"mock", "llm_check":false, "check_llm":"openai"}

config.json의 해당 부분을 바꾸고 .env에 OPENAI_API_KEY·GOOGLE_TTS_API_KEY를 본인이 넣으세요. model은 기본 gpt-6-luna·ko-KR-Wavenet-A예요. 한국어 지원과 내가 원하는 발음은 다르니 짧은 음성을 먼저 들어 보세요.[A025][A038][A039]

보유 소재는 media.scenes_dir, 본인 녹음은 media.recording에 경로를 넣어요. 실제 API 사용은 --live가 필요해요. 그 명령은 생성과 업로드까지 이어질 수 있으니 A5의 인증·승인제 설정까지 마친 뒤 실행하세요.

지금 할 일 mock의 신호음을 실제 낭독으로 착각하지 말고 전체를 들어 보세요.

그림·영상은 필요한 장면에만 더해요

이미지 API는 장면 수만큼, 영상 API는 선택한 초수만큼 비용이 붙어요.

키트의 media.image_api: true와 providers.image: "gemini"는 글자 없는 장면 그림을 만들어요. 한글 자막은 이미지에 그리지 않고 렌더러가 폰트로 얹어요. media.video_api: true·providers.video: "runway"는 장면 그림을 짧은 클립으로 만들어요. 이 키트는 영상 옵션을 켜면 모든 장면에 적용하므로, 한 장면만 생성하려면 미리 만든 소재를 scenes_dir에 모으세요.

모델 수명도 확인하세요. Gemini API의 Imagen 4·Veo 3.1 Preview, OpenAI GPT Image 1은 조사 시점에 종료됐어요. 기본값에 옛 모델을 다시 넣지 말고 현재 지원 목록·종료 안내·단가를 함께 바꾸세요.[A077][A036][A100]

지금 할 일 생성 task ID가 있으면 새 요청을 보내지 말고 같은 작업을 확인하세요.

원문이 매일 들어올 길을 열어요

전자동 주제 선정에는 새 원문 후보가 계속 필요해요.

직접 입력은 private/my-sources.json에 목록으로 저장하고 sources.files를 그 경로로 바꿔요. 아래는 직접 작성하는 원문 형식의 예예요. 내 실제 자료로 바꾼 뒤 사용권을 확인하고 rights_reviewed를 true로 정하세요. false인 채로는 live 생성·게시가 차단돼요.

[{
  "flow":"shorts",
  "title":"월급날 10분, 돈을 네 칸으로 나누기",
  "text":"월급날에는 네 칸 메모로 내 지출을 살펴봐요.\n월세: 고정 지출을 적어요.\n생활비: 일상 지출을 적어요.\n비상금: 예상 밖 지출을 준비해요.\n목표: 내 목적을 적어요.",
  "url":"", "entities":[],
  "synthetic":false, "rights_reviewed":false,
  "category":"자취 생활"
}]

RSS는 새 글 목록을 받는 주소예요. sources.rss에는 본인이 권리를 확인한 피드 주소와 category·flow·rights_reviewed를 넣어요. 예: {"url":"내 피드 주소", "flow":"shorts", "category":"자취 생활", "rights_reviewed":true}. 공개 피드라는 이유만으로 문장·사진을 재사용할 권리가 생기지는 않아요. 원문에 적힌 명령은 신뢰하지 않는 자료로 취급하고 생성 지시로 실행하지 않아요.

키 없이 연습할 때는 RSS XML을 로컬로 저장해요. 키트의 sources/shorts-feed.xml을 쓰려면 sources.files를 []로 두고 sources.rss를 [{"url":"sources/shorts-feed.xml", "flow":"shorts", "synthetic":true, "rights_reviewed":false, "category":"자취 생활"}]로 설정해요. pipeline.py run에 --config config.json --provider mock --state private/rss-demo를 넣고 실행하세요. 외부 RSS는 live에서만 읽어요.

지금 할 일 원문이 없으면 「새 주제가 없습니다」에서 멈추는지 확인하세요. 빈 후보를 새 사실로 채우게 만들지 마세요.

지금 하는 일: 스키마로 검사한 대본과 음성·장면 입력을 확인해요.

왜 하는지: 앞 단계의 실제 파일과 상태를 읽어 다음 작업을 이어 가기 위해서예요.

아래 명령은 auto-kit 폴더에서 실행하세요. A0에서 가상환경을 먼저 준비해요. RUN_ID가 있으면 앞 명령이 출력한 실제 12자리 ID로 바꿔요. Windows와 macOS는 같은 Python 명령을 써요.

python -c "from pathlib import Path; import json; d=json.loads(next(Path('private/state').glob('*/draft.json')).read_text()); print(d['title']); print(len(d['scenes']))"
