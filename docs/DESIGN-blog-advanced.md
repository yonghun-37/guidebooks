# BlogBook 심화편 설계서: 육아·교육 블로그를 코드로 운영하기

작성: 2026-10-27, Claude Code. 사용자 지시: "블로그 심화편으로 육아/교육 컨셉으로 운영하는 걸 코드 레벨로 운영하는 걸 교육 과정 설계해서 교과서 내용 추가. 육아용품 협찬도 받고 광고도 달고. **핵심은 교육 과정이 재현 가능해야 하고 가독성이 좋아야 한다.**"

BlogBook(`site-blog/`)에 세 번째 트랙 **심화편(코드 운영)** 을 추가한다. 이론편·실습편은 그대로 둔다. 문체는 docs/STYLE-GUIDE.md, 건강 정보는 docs/DESIGN-baby.md 8절(건강 정보 안전 규칙)을 그대로 따른다. 구조는 docs/DESIGN-advanced.md(인스타·쇼츠 심화편)의 장 형식을 이어받되 코드는 블로그 전용 키트로 따로 만든다.

## 1. 목표와 성공 기준

심화편을 끝낸 독자 손에 남는 것:

1. **코드로 돌아가는 육아·교육 블로그 1개**: 글감 → 출처 노트 → LLM 초안(JSON) → 사람 경험·사진 슬롯 → 자동 품질 관문 → WordPress REST API로 초안·예약 발행 → 지표 수집 → 다음 글감 점수. 기본은 키 없이 도는 **mock WordPress 서버**에서 끝까지 완주하고, 같은 명령에 설정만 바꿔 로컬 WordPress(Docker) → 실제 호스팅으로 옮긴다.
2. **광고**: 필수 페이지(소개·개인정보처리방침·문의·광고/협찬 정책) 자동 생성, AdSense 신청 준비 점검표, `ads.txt`, 광고 코드 위치를 템플릿으로 관리, 수익 보고서 수집.
3. **제휴**: 쿠팡 파트너스 등 제휴 링크 등록부, 대가성 문구 자동 삽입·위치 검사, 깨진 링크·가격 문구 검사, 영유아 제품 광고 규제 검사.
4. **협찬**: 미디어킷 자동 생성(지표 → HTML/PDF), 협찬 문의 접수 → 검토 → 계약 → 제품 수령 → 작성 → 광고주 확인 → 발행 → 성과 보고 → 정산까지의 **협찬 대장(상태 기계)**, 거절 기준, 협찬 글 관문, 광고주용 결과 보고서, 세금 기록.
5. **운영**: 예약 실행(작업 스케줄러·cron·GitHub Actions), 승인 알림, 백업·복구, 키 교체, 비용 상한, 주간 보고.

### 1.1 운영 원칙: 위험 등급별 자동화 (인스타·쇼츠 심화편과 다른 점)

육아 블로그는 아이 건강·안전과 아이 사생활을 다룬다. 그래서 "전자동"을 목표로 하지 않는다. 글 유형마다 자동화 수준을 고정한다.

| 글 유형 | 예 | 기본 운영 모드 |
|---|---|---|
| 건강·안전 정보 | 발열, 수면, 수유, 접종 | **항상 사람 승인**. 관문 통과해도 자동 발행 금지 |
| 협찬·제휴 글 | 협찬 받은 아기띠 사용 후기, 육아용품 비교 | **항상 사람 승인** + 광고주 확인 단계 |
| 아이 사진·경험이 들어간 글 | 백일 기록, 놀이 기록 | **항상 사람 승인**(사진 사생활 확인) |
| 제도·지원금 정리 | 2026 부모급여 정리 | 사람 승인으로 시작 → 관문 안정 후 **사후 확인**(예약 발행 후 공개 전 거부 가능) |
| 놀이·교육 활동, 그림책 목록 | 월령별 집 놀이, 그림책 주제 목록 | 승인제로 시작 → 관문 안정 후 사후 확인 → 선택적으로 전자동 |
| 기존 글 갱신 | 금액·날짜가 바뀐 글 고치기 | 자동 탐지 + 사람 승인 |

코드가 대신하는 일: 글감 수집·점수, 출처 정리, 초안 구조, 검사, 발행 API 호출, 링크·문구 삽입, 지표 수집, 보고서, 알림, 백업. 사람이 하는 일: 아이와의 경험·사진, 건강 정보 최종 확인, 협찬 수락·계약, 승인 버튼.

AI가 경험을 지어내지 않게 한다: 초안 스키마에 `experience` 칸은 비워 두고, 사람이 채우지 않으면 관문이 막는다("직접 써 본 후기"를 AI가 만들면 표시광고법상 거짓 후기 위험).

### 1.2 이 과정의 두 가지 약속 (사용자 핵심 요구)

**재현 가능**: 같은 명령을 같은 순서로 실행하면 누구나 같은 결과를 본다.

- 키트는 **Python 3.11 이상 + 표준 라이브러리 우선**. 필요한 외부 패키지는 `requirements.lock`에 정확한 버전으로 고정한다. Docker 이미지도 태그(버전)로 고정한다.
- 기본 실행은 네트워크·계정·키 없이 끝난다: mock LLM(고정 응답), **mock WordPress 서버**(표준 라이브러리로 만든 REST 일부 흉내, 로컬 포트), mock 지표·mock 제휴 API.
- 시간·난수 고정: `--today 2026-10-27`과 고정 시드로 날짜·ID가 같게 나온다. 기본값으로 고정 날짜를 쓰고 실제 날짜는 옵션.
- **장별 체크포인트**: `python course.py check A5`가 그 장에서 만들어야 할 파일·상태·출력이 맞는지 검사하고 무엇이 다른지 한국어로 알려 준다. `python course.py start A5`는 그 장의 시작 상태(앞 장까지 완료한 상태)를 만들어 준다. 중간 장부터 시작하거나 꼬였을 때 다시 시작할 수 있다.
- 장마다 **예상 출력(expected/)** 을 저장소에 두고, 본문의 "이렇게 보이면 성공"은 그 파일에서 가져온다(본문과 실제 출력이 어긋나지 않게).
- **클린룸 재현 검사**: `scripts/repro_blog_advanced.sh`가 키트를 빈 폴더에 복사해 A1→E2E의 본문 명령을 차례로 실행하고 체크포인트와 예상 출력을 비교한다. 독립 검토자도 같은 방식으로 본문만 보고 따라 한다.
- Windows PowerShell / macOS·Linux 명령을 나란히 둔다(검증 가능한 것은 Linux에서 실행, Windows는 명령 표기 검사).

**가독성**: 코드도 본문도 처음 보는 사람이 읽힌다.

- 장 하나 = 결과물 하나. 장 머리에 "이 장에서 만드는 것(파일 이름)"과 "끝나면 되는 것" 한 문장.
- 본문의 코드 발췌는 **한 번에 25줄 이하**, 줄마다 무엇을 하는지 주석이 아니라 발췌 아래 "읽는 법" 표(줄 번호 → 하는 일)로 설명한다.
- 키트 파일 하나 = 개념 하나, **파일당 200줄 이하**, 함수 이름은 하는 일 그대로(`check_disclosure`, `publish_draft`). 한국어 docstring 한 줄.
- 흐름은 그림으로: 전체 시스템도, 글 한 편의 상태 흐름, 관문 판정 흐름, 협찬 대장 상태 기계, API 요청·응답 순서, 폴더 구조, 하루·한 주 운영 타임라인.
- 장마다 같은 순서: 먼저 답부터 → 한눈에 보기(그림) → 시작 상태 확인 → 단계(명령 → 이렇게 보이면 성공) → 코드 읽기 → 바꿔 보기(설정 한 줄 바꾸고 결과 차이 보기) → 흔한 오류 표 → 체크포인트 → 정리.

## 2. 인물과 예시 블로그 (STYLE-GUIDE 7절)

- **서윤**: BabyBook의 엄마. 육아휴직 중 봄이를 키우며 블로그를 시작한 초보 개발자(파이썬 기초 정도). 질문하는 쪽.
- **태오**: BlogBook의 블로그 6년 차 운영자. 이번에는 코드 운영 멘토. 직답하는 쪽.
- 예시 블로그: 가상 「봄이랑 크는 집」 — 0~3세 육아 정보·집 놀이·그림책·지원 제도. 장을 관통하는 실제로 검색될 만한 글 4편:
  1. 정보 글: "2026 부모급여·아동수당 한 번에 정리"(공식 자료, 기준일 표시, 금액이 바뀌면 갱신 대상)
  2. 놀이·교육 글: "생후 3~4개월 집에서 하는 터미타임 놀이 5가지"(건강 정보 안전 규칙 적용, 공식 권고 범위만)
  3. 제휴 비교 글: "신생아 손톱깎이 vs 전동 손톱갈이 비교"(제품은 범주·가상 이름, 대가성 문구 위치 시연)
  4. 협찬 후기: 가상 브랜드 「포근담요」의 아기 낮잠 이불 협찬 → **안전 수면 원칙과 충돌하는 협찬은 거절하는 사례**와, 수락 가능한 협찬(가상 「도담」 원목 그림책 꽂이)의 전 과정
- 브랜드·광고주·대행사는 모두 가상이다. 실존 브랜드·체험단 플랫폼 이름은 조사 출처를 단 비교 표에서만 쓰고 사칭하지 않는다.

## 3. 심화편 목차 (`site-blog/advanced/`)

| 장 | 제목(가제) | 이 장에서 만드는 것 | 학습자의 가장 큰 질문 |
|---|---|---|---|
| A0 | 심화편 안내: 코드로 운영하는 육아 블로그 전체 그림 | 운영 계획 1장(글 유형별 자동화 수준) | 어디까지 자동이고 무엇은 내가 하나? 한 달 비용·시간은? 수익은 어떤 순서로 붙나? |
| A1 | 같은 결과가 나오는 작업 환경 | `.venv`, `course.py doctor` 통과, mock WordPress 실행 | 내 컴퓨터에서도 책과 똑같이 되나? 꼬이면 어떻게 되돌리나? |
| A2 | 블로그 서버와 필수 페이지 | 로컬/실제 WordPress 연결 설정, 소개·개인정보처리방침·문의·광고/협찬 정책 페이지 | 왜 네이버·티스토리가 아니라 WordPress인가? 호스팅·도메인 비용은? 애플리케이션 비밀번호는? |
| A3 | 글감과 콘텐츠 설계 | 주제 지도(월령·발달·제도·놀이), 글 유형 4종 스키마, 출처 노트 | 무엇을 써야 검색되고 안전한가? 공공 자료는 어디서 가져오나? |
| A4 | AI 초안 생성 | 프롬프트 파일, JSON 초안, 경험 슬롯, 비용 기록 | LLM API를 얼마에 어떻게 부르나? AI가 경험을 지어내지 않게 하려면? |
| A5 | 자동 품질 관문 | 관문 보고서와 예외 대기열 | 건강 정보·아이 사진·대가성 표기·중복을 코드로 어떻게 검사하나? |
| A6 | 발행 자동화 | 초안 저장 → 예약 발행, 이미지 업로드, 중복 방지 | REST API로 글·이미지·태그를 어떻게 올리나? 두 번 올라가면? |
| A7 | 광고 붙이기 | 신청 준비 점검표, `ads.txt`, 광고 위치 템플릿, 수익 보고서 | 애드센스 승인 조건은? 광고는 어디에 몇 개? 육아 블로그에서 막을 광고는? |
| A8 | 제휴 링크 운영 | 제휴 링크 등록부, 대가성 문구 자동 삽입, 링크 점검 | 쿠팡 파트너스 API는 언제부터 쓰나? 문구는 어디에 어떻게? 아기 제품에서 조심할 광고 규제는? |
| A9 | 육아용품 협찬 받기 | 미디어킷, 협찬 대장, 거절 기준, 광고주 보고서 | 협찬은 어떻게 받나? 무엇을 거절하나? 계약서·표시·세금은? |
| A10 | 숫자 모으기와 개선 | 주간 보고서·대시보드, 다음 글감 점수, 갱신할 글 목록 | 방문·검색·광고·제휴 숫자를 한곳에서 보려면? 어떤 글을 고치나? |
| A11 | 예약 실행과 운영 | 예약 실행 설정, 승인 알림, 백업·복구, 키 교체 | 매일 몇 시에 무엇이 도나? 실패하면? 서버가 날아가면? |
| A12 | 정책·법·세금 점검 | 출시 전 점검표 | 구글 스팸 정책·표시광고법·아이 개인정보·저작권·세금에서 무엇을 지키나? |
| E2E | 심화 진행표 | mock 완주 / 로컬 WordPress / 실제 블로그 기록 | 순서대로 다 했나? |

수익 장치의 순서는 본문에서 분명히 한다: 글 20~30편과 필수 페이지 → 광고 신청(승인 조건은 조사로 확정) → 제휴(조건·실적 요건 조사) → 협찬(지표가 쌓인 뒤 미디어킷). 숫자 기준은 조사 근거가 있을 때만 쓰고, 없으면 "공식 기준 없음"이라고 쓴다.

## 4. 코드: `blog-auto-kit/` (새 폴더, BlogBook 심화편 전용)

blog-kit(입문용, 수동 편집기 중심)과 auto-kit(인스타·쇼츠)은 고치지 않는다. 필요한 아이디어(해시 승인, 상태 저장, 알림, 예약 생성기)는 읽고 **새로 짧게** 구현한다(두 키트를 import하지 않는다 — 폴더 하나만 복사해도 실행되어야 재현이 쉽다).

```
blog-auto-kit/
  README.md            시작 3단계와 장별 명령 색인
  course.py            doctor / start <장> / check <장> / reset (체크포인트)
  blog.py              하나의 진입점: topics, draft, gate, publish, ads, affiliate, sponsor, report, run
  config.example.toml  사람이 읽기 쉬운 설정(주석 포함). 비밀은 .env만
  requirements.lock    고정 버전(외부 패키지가 필요할 때만)
  core/                설정 읽기, 상태 저장(SQLite), 콘텐츠 해시, 로그, 고정 시계
  content/             주제 지도, 글 유형 스키마(JSON Schema), 출처 노트, 마크다운→HTML
  providers/           llm(mock + 실제 1~2개), 비용 기록·상한
  gates/               health_safety, child_privacy(EXIF·이름·위치), disclosure, product_rules, duplicate, seo, sources
  wordpress/           REST 클라이언트(애플리케이션 비밀번호), mock 서버, 미디어 업로드, 예약
  monetize/            pages(필수 페이지), ads(ads.txt·광고 위치), affiliate(링크 등록부·문구), sponsor(대장·미디어킷·보고서)
  analytics/           mock + GA4 Data API·Search Console API·광고 보고서 수집기(선택), 주간 보고서
  ops/                 알림(디스코드·텔레그램), 백업·복구, 예약 실행 생성기, GitHub Actions 예시
  course/              장별 시작 상태, 검사 규칙, expected/ 예상 출력
  samples/             「봄이랑 크는 집」 글 4편의 원자료·사람 경험 메모·사진(직접 만든 그림, EXIF 시연용 파일 포함)
  tests/               pytest, 모든 외부 호출 모킹
```

- 실제 발행·광고·제휴·지표 API 연결은 **기본 드라이런**. `--live`는 사용자가 `.env`를 직접 넣었을 때만. 작업자는 실계정·유료 키를 쓰지 않는다.
- 로컬 WordPress는 `ops/docker-compose.yml`(이미지 태그 고정)로 선택 제공. Docker가 없으면 mock 서버로 모든 장을 끝낼 수 있어야 한다.
- 협찬 대장은 SQLite 1파일 + CSV 내보내기. 상태 전이는 표 하나(`sponsor/states.py`)로 정의해 본문 그림과 같은 이름을 쓴다.
- 이미지: 키트 샘플 사진은 직접 그린 그림 또는 코드 생성 이미지. 실제 아이 사진은 넣지 않는다. EXIF(위치·기기) 제거 시연용 파일은 가짜 메타데이터를 넣은 그림으로 만든다.

## 8. BX2 조사 반영 (Claude 검수, 2026-10-27)

research-blog-advanced/BRIEFING.md ⑨의 제안 1~12를 모두 채택한다. 3절의 "글 20~30편 → 광고 신청"은 **공식 조건이 아니다**(AdSense 공식 최소 글 수·방문자 기준 없음). 콘텐츠·필수 페이지·정책 준비 기준으로 바꾸고, 광고→제휴→협찬은 학습 순서일 뿐 법이나 플랫폼이 정한 단계가 아님을 쓴다.
- A1·A2: mock / Docker 로컬 / 실제 호스팅의 "성공 화면"을 구별한다. WordPress 7.1.3, 공식 이미지 `wordpress:7.1.3-php8.3-apache`(DB 이미지는 BX3k에서 실행 후 고정). 저가 호스팅은 플러그인·SSH·REST 인증 제한부터 확인하는 진단 과제, DB·미디어 백업 복구 과제를 넣는다.
- A3: 공공자료를 CSV 집계 / 기관 주소록 / API로 구별하고 글감 스키마에 이용 허락(공공누리 유형)·기준일 칸. 터미타임 예시 글은 건강·안전 등급(항상 사람 승인).
- A4·A9: **계약·플랫폼의 AI 사용 허용 여부를 초안 생성보다 먼저 확인**. `ai_allowed=false/unknown`이면 사람 작성·보류 경로로 완주 가능해야 한다. 허용이어도 쓰지 않은 경험은 막는다.
- A5·A8: 제품 정보를 `product_type, intended_use, model, maker, certification_scheme, recall_check, ad_review_scope`로 나누고, 판정을 **법적 금지 / 프로젝트 거절 / 자료 보류** 세 가지로 구분한다(단순 키워드 일괄 금지 금지). 조제유류 제휴·협찬, 의료기기 사용자 체험담 광고, 안전 수면 충돌 제품은 기본 차단.
