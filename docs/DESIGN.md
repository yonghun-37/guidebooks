# ReelsBook 설계서

작성: 2026-10-26, Claude Code (설계). 구현은 Codex가 docs/PLAN.md에 따라 수행한다.

## 1. 목표

AI 도구로 인스타그램 **릴스**와 **뉴스카드(캐러셀 이미지)** 를 자동 생성하고, 포스팅을 자동화하고, 수익화까지 가는 과정을 **사전 지식 없는 초보자**가 장 순서대로 따라 하면 실제 결과물(첫 뉴스카드, 첫 릴스, 자동 포스팅 파이프라인, 30일 운영 계획)을 손에 쥐도록 하는 웹 교과서를 만든다.

성공 기준:

1. 초보자가 1장부터 순서대로 읽고 "직접 해 보기"를 따라 하면, 14장이 끝날 때 다음 네 가지가 실제로 만들어져 있다.
   - 니치와 계정 콘셉트가 적힌 기획 시트
   - 스타터 키트로 생성한 뉴스카드 PNG 묶음(캐러셀 1세트)
   - 스타터 키트로 생성한 15~30초 릴스 MP4 1개
   - 예약 실행되는 생성→(검수)→업로드 파이프라인 설정과 30일 운영 계획표
2. 모든 정책·수치 주장에 출처와 조사 기준일이 있다.
3. 휴대폰 화면(360px)에서도 읽고 시뮬레이터를 조작할 수 있다.

## 2. 참고 형식: ColorBook(art.euiyun.com/color)에서 가져올 것

구조와 학습 설계만 차용하고 내용·코드·디자인 자산은 새로 만든다.

| 차용 요소 | ReelsBook 적용 |
|---|---|
| 표지: 시리즈명, 장 수, 시뮬레이터 수, 대상 독자, "사전 지식 필요 없음", 시작 링크 2개 | 표지에 "1장부터 시작하기" + "자동화 실험실" 링크, 독자 유형별 추천 경로 |
| 1장 = 전체 지도, 끝에서 두 번째 = 실험실, 마지막 = 용어집 | 동일. 1장은 파이프라인 전체 지도, 15장 실험실, 16장 용어집 |
| 장 내부 고정 흐름 | 아래 3절의 9단계 흐름 |
| 연속 인물 서사가 모든 장을 관통 | 아래 4절의 두 인물 |
| 장마다 "직접 해 보기" | 장마다 "작업실 노트"에 번호 매긴 실습 단계와 완료 체크 |
| 단순화 모형은 교육용이라고 표시 | 수익 계산기 등은 "교육용 가정 모형" 배지와 가정값 표시 |
| 크레딧 페이지 | 출처·크레딧 페이지(17장 성격의 부록) |

REA 분석(Phase 2)으로 레이아웃, 내비게이션, 시뮬레이터 상호작용 패턴, 반응형 처리, 퀴즈 방식 같은 구현 패턴을 추가로 파악해 docs/reference-analysis.md에 기록하고 이 설계를 보완한다.

## 3. 장 페이지 템플릿(9단계)

모든 본문 장(2~14장)은 아래 순서를 지킨다. 각 블록은 고정 CSS 클래스와 아이콘을 가진다.

1. **일상의 질문**: 독자가 실제로 품는 질문 한 줄과 짧은 장면(인물 서사).
2. **만져 보는 그림**: 장 핵심을 보여 주는 작은 인터랙티브 도식(SVG + JS). 예: 파이프라인 블록을 눌러 각 단계 설명 펼치기.
3. **원리**: 개념 설명. 용어는 처음 나올 때 풀어 쓰고 용어집으로 링크한다. 정책·수치에는 각주 출처.
4. **시뮬레이터**: 값을 바꾸며 결과를 보는 도구(장마다 1~2개). "교육용 가정 모형" 배지와 가정값 공개.
5. **실제 사례**: 공개된 계정·사례 유형 분석(출처 링크). 특정 실존 계정을 비방하거나 사칭하지 않는다.
6. **작업실 노트(직접 해 보기)**: 번호 매긴 실습 단계. 각 단계에 소요 시간, 필요한 것, 기대 결과, 흔한 오류와 해결. 스타터 키트 명령은 복사 버튼이 있는 코드 블록으로 준다. 마지막에 "이 장의 결과물" 체크리스트(localStorage에 체크 상태 저장, 실패해도 동작).
7. **인물 작업 노트**: 주인공의 실습 기록과 실수, 멘토의 피드백.
8. **핵심 정리**: 3~5줄 요약.
9. **퀴즈**: 3~5문항 객관식, 즉시 채점과 해설.

장 상단에는 "이 장을 마치면 만들어지는 것", 예상 소요 시간, 난이도, 선행 장을 표시한다. 하단에는 이전/다음 장 내비게이션을 둔다.

## 4. 연속 인물

- **하린**(31, 중소기업 마케팅팀 직원): 코딩 경험이 거의 없다. 퇴근 후 하루 1시간으로 "AI·테크 뉴스 한 장 요약" 계정을 시작한다. 목표는 6개월 안에 월 30만 원의 부수입이다.
- **정 선배**(44, 전 잡지 편집장, 현재 1인 콘텐츠 스튜디오 운영): 하린의 멘토. 편집 감각, 저작권, 꾸준함, 수익 구조의 현실을 짚어 준다.

두 인물은 가상이다. 하린의 계정 성장 수치는 교육용 시나리오임을 명시한다.

### 반드시 다룰 사실 영역(조사 대상)

- 인스타그램 추천 시스템 공식 설명, 릴스 길이·비율·해상도 권장, 캐러셀 장수 한도, 오리지널 콘텐츠 정책과 재게시·워터마크 불이익.
- 수익화: 한국에서 사용 가능한 Meta 수익화 기능(구독, 선물/Stars, 보너스 등)과 자격 요건, 브랜디드 콘텐츠(유료 파트너십 라벨), 제휴 마케팅(쿠팡 파트너스 등), 자체 상품, 외부 트래픽. 국가별 가용성을 구분한다.
- Instagram Graph API 콘텐츠 게시: 비즈니스/크리에이터 계정, Facebook 페이지 연결 여부, 앱 권한, 24시간 게시 한도, 지원 미디어 형식, 릴스 업로드, 앱 검수.
- 예약·자동화 도구: Meta Business Suite 예약, n8n/Make/Zapier, Python 스크립트, 무료/유료 구분.
- AI 생성 도구: 글(LLM), 이미지 생성, TTS(무료·오픈소스 포함), 자막(Whisper 등), 영상 편집 자동화(FFmpeg, MoviePy, Remotion), 카드 렌더링(HTML→PNG, Canva 대량 생성). 라이선스와 상업적 이용 가능 여부.
- AI 생성물 라벨링(Meta "AI 정보" 라벨) 정책, 한국 AI 기본법 등 표시 의무 동향.
- 한국 법: 저작권(뉴스 기사 인용, 사진·영상, 공정 이용), 초상권·퍼블리시티권, 표시광고법·공정위 추천보증 심사지침(뒷광고), 개인정보, 부업 소득 세금(사업자등록, 종합소득세, 원천징수) 기초.
- 현실적 기대치: 팔로워 단계별 협찬 단가 범위, 제휴 전환율, 성장 속도에 대한 공개 자료. 근거가 약하면 범위와 불확실성을 밝힌다.
- 실패 사례와 위험: 대량 AI 콘텐츠 계정의 도달 저하, 계정 제한, 스팸 판정.

## 6. 스타터 키트(starter-kit/)

초보자가 복사-붙여넣기로 실행할 수 있는 최소 예제. 장의 작업실 노트가 이 키트를 단계별로 사용한다.

- 언어: Python 3.11+ 하나로 통일한다. 설치는 `uv` 또는 `pip` 중 하나를 권장하고 두 경로를 모두 안내한다.
- 구성(예정):
  - `config.example.yaml`: 계정 이름, 색, 폰트, RSS 목록, LLM 설정.
  - `fetch_news.py`: RSS에서 기사 제목·링크·요약을 가져와 JSON으로 저장한다(본문 전체 복제 금지).
  - `write_copy.py`: LLM으로 카드 문안·릴스 대본 생성. API 키가 없으면 **오프라인 모드**(규칙 기반 요약 + 직접 편집용 템플릿)로 동작해 무료로 끝까지 따라 할 수 있다.
  - `render_cards.py`: HTML/CSS 템플릿 → 1080×1350 PNG 캐러셀(Playwright 또는 대체 렌더러).
  - `make_reel.py`: 카드 이미지 + TTS(무료 경로 우선) + 자막 → 1080×1920 MP4(FFmpeg).
  - `publish.py`: Instagram Graph API 업로드. 기본은 **드라이런**이며 실제 업로드는 사용자가 토큰을 넣고 플래그를 명시할 때만 한다.
  - `run_pipeline.py`: 전체 실행, 결과물 폴더 생성, 사람 검수 대기 단계 포함.
  - `samples/`: 오프라인 모드로 실제 생성한 샘플 카드 PNG와 릴스 MP4(교과서 그림으로 사용).
- 테스트: 오프라인 모드 전체 실행이 통과해야 한다. 외부 API 호출은 테스트에서 하지 않는다.

## 7. 사이트 구현

- 정적 HTML/CSS/바닐라 JS. 빌드 도구 없이 `site/`를 그대로 열거나 정적 호스팅할 수 있다. 공통 헤더·내비·장 목록은 `site/assets/book.js`가 하나의 데이터(`chapters.json` 또는 JS 객체)에서 그린다.
- 경로: `site/index.html`, `site/chapters/<slug>.html`, `site/lab.html`(또는 chapters/lab.html), `site/glossary.html`, `site/credits.html`, `site/assets/{book.css,book.js,sim/*.js,img/*}`.
- 디자인: 읽기 좋은 본문 폭(약 680~720px), 한국어 웹폰트(Pretendard 등, CDN 버전 고정), 라이트·다크 모드, 9단계 블록별 시각 구분, 인쇄 시 시뮬레이터 숨김.
- 접근성: 시뮬레이터는 키보드로 조작 가능하고 결과를 텍스트로도 표시한다. 색만으로 의미를 전달하지 않는다.
- 외부 의존 최소화: 차트가 필요하면 직접 SVG로 그린다.

## 8. 품질 게이트(Phase 6)

- 모든 내부 링크와 앵커가 유효하다.
- 각 장이 9단계 블록을 모두 갖췄다(자동 검사 스크립트).
- 각 장의 정책·수치 주장에 출처 각주가 있다. research/ 노트에 없는 출처는 없다.
- 데스크톱(1280px)과 모바일(375px) 스크린샷에서 가로 스크롤이 없다.
- 스타터 키트 오프라인 전체 실행이 성공하고 샘플이 재생성된다.
- 퀴즈 정답·해설이 본문과 일치한다.
- 초보자 관점 독립 검토(Codex 별도 세션): 1장→14장 실습을 처음 하는 사람처럼 따라가며 막히는 곳을 목록화하고 수정한다.
