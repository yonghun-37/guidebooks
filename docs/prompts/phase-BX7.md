## 1. 안전 구조를 "기본 거부"로 바꾼다 (B01·B02·B06의 근본 수정 — 키워드 추가만으로 닫지 마라)
- **자동 발행은 허용 목록일 때만**: `auto`/사후 확인 모드에서 사람 승인 없이 예약할 수 있는 조건을 한 함수(`gates/risk.py`의 `may_auto_publish`)에 모은다 — (a) 글 유형이 허용 유형(놀이·교육 활동, 제도 정리 중 설정으로 허용한 것)이고 (b) 관문 결과가 **전부 pass**(review·hold·block이 하나라도 있으면 사람 승인)이고 (c) 건강·아이 정보·상업 관계·사진·갱신 신호가 **제목·설명·본문·경험 칸·이미지 전부**에서 없고 (d) 서버에 같은 글이 없을 때(신규). 하나라도 확인하지 못하면 사람 승인. 발행 함수는 관문 결과와 이 함수만 보고 판단한다(별도 위험 판정 경로 제거).
- **갱신 글은 서버 기록으로 판단**(B02): prepare·publish가 서버의 기존 post_id/slug/상태를 조회해 이미 존재하면 갱신으로 기록(JSON 자가 선언에 의존하지 않음), 갱신 이력은 prepare·재조회·재시도 후에도 보존, 갱신은 언제나 새 최종본 사람 승인 후에만 예약.
- **건강 분류는 본문까지**(B06): 건강 어휘 분류를 본문 전체에 적용하고, 건강으로 분류되거나 응급 관련 어휘가 있으면 공통 응급 문구 확인 항목을 띄운다. 약 이름은 목록으로 다 잡을 수 없다는 사실을 인정하고 **본문 문장을 실제 보장 수준에 맞춘다**: "약 이름·용량을 찾는 검사는 보조 장치예요. 건강으로 분류된 글은 사람이 읽고 승인해야만 발행돼요." 약 일반 접미어·용량 단위(mg, ml, 정, 포 등) 패턴은 검사 보조로 넓힌다.
- 아이 식별 정보(B01 후반): 고정 양식 밖의 이름·병원·어린이집 표현도 의심 신호로 잡고, 의심이면 사람 승인. "모든 표현을 잡는다"고 쓰지 않는다.

## 2. 제품·표시·사진 관문 (B03·B04·B05)
- B03: 의료기기는 `comparison_only` 플래그가 아니라 **경험 칸·본문의 1인칭 사용 소감 유무**로 체험담을 판정(있으면 법적 금지 차단). 화장품·건강기능식품·일반 제품의 **질병 예방·치료·완화 표현**(예방합니다, 낫게, 치료 등) 검사 추가 → 규제 품목이면 차단, 분류 불명이면 자료 보류. R03: "리콜 확인 결과 없음"을 리콜로 오판하지 않게 리콜 여부를 별도 값(`recall_status: none_found/recalled/unchecked`)으로, 문자열 하나로 조제유류 확정 금지(분류 근거 칸 확인, 불명이면 보류), 근거 ID를 판정 사유와 맞춘다.
- B04: 관계별 표시 — 등록부·계약의 관계(수수료/제품 제공/광고비/대여)마다 첫머리 표시에 해당 내용이 있는지 각각 검사, 관계 메타데이터가 비면 상업 유형은 자료 보류. 쿠팡 지정 문구는 쿠팡 수수료 관계에만, 다른 관계는 관계별 문구 생성. **본문은 키트가 마크다운에서 만든 HTML만 허용**하고 원고의 raw HTML·style·hidden·class 숨김은 차단(또는 숨김 속성 검사) — 텍스트 일치만으로 승인하지 않는다.
- B05·R04: 파일 형식은 확장자가 아니라 **매직 바이트**로 판별. JPEG(APP1 EXIF·XMP 모두), PNG(eXIf·tEXt/iTXt/zTXt의 XMP) 검사·제거 구현, 그 밖의 형식은 보류. **업로드는 메타데이터를 제거한 공개용 사본만** 쓰고, 사본을 다시 검사해 비어 있어야 업로드. 시연 파일 `samples/fake-exif.jpg`는 정상 디코딩되는 JPEG로 다시 만들고(표준 라이브러리로 만들 수 없으면 정상 JPEG 바이트를 고정 파일로 두고 가짜 EXIF·XMP만 삽입), 원본·제거본 모두 정상으로 열리고 Make·GPS가 사라지는지 테스트(Pillow가 dev lock에 있으면 엄격 디코딩 테스트, 없으면 dev lock에 고정 버전으로 추가).
