# Y4k — 독립 쇼츠 스타터 키트

## 요구사항·구현 계획

사용자가 승인한 Y3 샘플의 도윤·서진, 직답·행동 중심 문체를 따른다. 담당 범위는 `shorts-kit/`와 이 단계 결과 기록이다. `starter-kit/`, `site/`, 공통 사이트 파일과 통합 상태 문서는 수정하지 않는다.

- [x] 오프라인/붙여넣기/명시적 API 대본과 프롬프트를 구현한다.
- [x] 사용자 녹음·사진·클립·음악 또는 자체 타이틀·무음으로 세로 MP4와 SRT·번인 자막을 만든다.
- [x] 해시 기반 사람 검수·승인과 기본 드라이런, OAuth 설정이 있어야 가능한 재개 업로드를 구현한다.
- [x] 기존 날짜별 생성·예약 안내를 독립 복사해 조정한다.
- [x] 깨끗한 임시 복사본에서 명령·pytest·미디어 규격·브라우저·정적 검사를 실행한다.
- [x] 작은 샘플·초보자 README·화면과 실제 결과를 남기고 디스코드에 보고한다.

새로운 서비스나 저장 방식을 도입하지 않는다. 기존 common의 JSON·해시·CLI, review의 승인 방식, daily와 schedule_setup의 중복 방지·경로·인용 처리를 재사용한다. ffmpeg는 pip 바이너리를 사용한다. 무료 오프라인 경로에서 네트워크 호출은 없다. 자동 자막은 대본 기반이며 음성 인식·강제 정렬을 가장하지 않는다. 정책 근거는 research-shorts/FACT-SHEET와 기존 [Y###] 출처이며 API 프로토콜은 공식 재개 업로드 문서를 대조한다.

## 구현 결과

- `shorts-kit/`는 다른 책·키트 모듈을 런타임에 가져오지 않는다. `common.py`의 JSON·해시·CLI, `review.py`의 승인 방식, `daily.py`·`schedule_setup.py`의 날짜·경로·중복 방지·명령 인용 처리를 복사해 조정했다. 기존 RSS·릴스·카드 관련 분기는 가져오지 않았다. 폰트와 OFL·기존 MIT 고지를 동봉했다.
- `run_pipeline.py`·`write_script.py`: 오프라인 가상 대본, 웹 채팅용 훅 3종/대본/메타데이터 프롬프트, JSON 붙여넣기 검증·출력, 사용자가 직접 허용한 기존 호환 API 호출을 지원한다. 키·응답 오류 본문을 산출물에 남기지 않고 인증 헤더가 실린 리다이렉트를 막는다. 실제 API를 호출하지 않았다.
- `render.py`: 사용자 녹음(M4A 포함)을 우선하고 없으면 무음 AAC를 넣는다. 사용자 사진·클립을 파일명 순서로 받아 가운데 크롭·짧은 클립 반복으로 맞춘다. 원본 클립 소리는 넣지 않는다. 입력이 없으면 자체 도형과 타이틀을 만든다. 장면 수와 입력 파일 수가 다르거나 녹음이 더 길면 오류로 멈춘다.
- 자막은 대본 기반 SRT와 영상에 구운 글자로 자동 생성한다. 긴 글은 너비에 맞춰 나누며 프레임 경계에 시간을 배분한다. 음성 인식·강제 정렬 기능은 없다. 크기·여백·음량은 키트 시작값이며 공식 필수값으로 쓰지 않는다. 음악은 사용자 파일·이용 조건 메모·확인·증빙을 요구하고 필요한 표시문구를 설명에도 포함해야 한다.
- 출력은 9:16·1080×1920·30fps H.264/yuv420p·AAC/48kHz/stereo MP4다. 실제 파일 정보를 읽어 규격·길이·최대 3분을 검사한다. 기본 대본은 36초다. `video.duration`은 대본 생성 시 사용하고 재출력 길이는 장면 길이 합으로 결정한다.
- 생성된 `preview.html`은 도윤·서진의 작업실이다. 첫 재생 후 장면 선택·반복·이전/다음 프레임·안전 영역·음원 개별 듣기를 제공한다. 플랫폼 로고·UI를 복제하지 않았다. 자체 HTML/CSS/JS이며 공통 사이트 자산을 수정하지 않았다.
- `review.py`: 여섯 체크와 아동용·AI 공개 판단이 끝나야 승인한다. 결과 영상·대본·설정·자막·프레임·음원·증빙·검수 문서를 해시로 묶는다. 재출력 실패 전에도 이전 승인을 지우며 파일 변경·목록 누락·우회 경로를 거부한다. 초안의 두 공개 판단값은 null로 남긴다.
- `upload.py`: 기본 드라이런은 네트워크 0회, 세션 시작 POST/청크 PUT/중단 시 상태 조회 PUT과 실제 메타데이터·공개 관련 필드의 출처를 보여 준다. `--live`는 사용자 데스크톱 OAuth 파일과 토큰이 모두 있어야 한다. `oauth_setup.py`는 사용자가 직접 브라우저에서 인증을 준비하는 선택 명령이다.
- 재개 업로드는 청크·308 Range·일시 오류 재조회/제한된 대기·서버 위치 기준 재개·세션/완료 기록·중복 전송 방지를 구현했다. 외부 호스트 세션·리다이렉트를 거부한다. 토큰·세션은 임시 파일 단계부터 제한된 권한으로 저장한다. 완료 응답은 요청 상태와 함께 저장하고 Studio 확인을 안내한다. 업로드 이력이 있는 폴더를 재렌더하지 않는다.
- `daily.py`는 오프라인 초안·검수 대기까지만 실행한다. 예약 도구는 두 OS의 등록/확인/실행/삭제 안내만 출력하며 등록·승인·게시를 실행하지 않는다.
- `README.md`는 Windows/macOS 설치, 파일·명령·성공 결과·오류 해결, 대본·자막 수정, OAuth 준비, 검수와 실제 게시 경로를 안내한다. 통합 상태 갱신 제안과 용어는 별도 요청 문서에 남겼다.

샘플 전체는 **213,530바이트**로 10MB 이하다. `samples/short.mp4`는 직접 쓴 가상 대본과 자체 타이틀·무음이며 사용자 미디어·토큰·개인 설정·승인 기록을 포함하지 않는다.

## 발견과 수정

- 기존 키트의 Pillow 13.0.0은 현재 연결된 패키지 저장소에 없었다. 새 키트만 설치 가능한 12.3.0으로 고정해 설치·렌더링을 검증했다. 기존 키트는 수정하지 않았다.
- 외부 설정으로 render할 때 결과 폴더의 설정 사본이 누락되는 실패를 재현하고 정규화한 설정을 항상 보존하도록 고쳤다.
- 첫 미디어 탐색이 준비되기 전 프레임 버튼이 0초에 머무는 경우를 확인했다. 재생 후 탐색이 준비되어야 버튼을 활성화하고 처음 행동을 화면에 안내했다. 검사는 기본 안내인 로컬 HTML 직접 열기로 했다.
- 375px에서 flex의 빈 열로 시간표가 밀려나는 문제를 발견해 작은 화면을 세로 배치로 바꿨다. 시간 표시도 한 줄로 유지했다.
- 구간 반복이 정지 상태의 프레임 이동을 재생으로 바꾸지 않게 수정했다. 마지막 장면의 자연 종료도 반복하도록 확인했다.

- 깨끗한 임시 복사본 **명령 9개 통과**. 공백·한글 경로와 다른 작업 폴더에서 실행했다. 기록은 [clean-copy-check.json](phase-Y4k/clean-copy-check.json).

- `style_lint`: 사이트·키트 미리보기·두 README 변환본 **23개 통과**. 금지어 0·내부 용어 0·상자 밖 단서 0. 새 키트이므로 기존 이론 분량 기준선은 적용하지 않았다.

## 남은 확인

- 실제 사용자 OAuth 로그인·YouTube 전송·공개·쇼츠 분류·API 프로젝트별 제한은 실행하지 않았다. 실제 전송은 사용자가 로컬에서 명시적으로 실행하는 경로다.
- Linux의 pip 바이너리·Chromium 검증이다. Windows/macOS의 설치·녹음·브라우저·예약 등록과 모바일 실기기 검증은 남는다.
- 대본 기반 자동 자막의 음성 시점·인물 동의·소재/음악 사용권은 사람이 확인해야 한다. API 성공 응답을 공개/권리 검토 완료로 인정하지 않는다.
- 공통 상태·용어·서가·배포 통합은 담당 작업자의 검수가 남는다. 요청 문서에 실제 구현 기준을 남겼다.
