## 구현과 선택 근거

| 구성 | 실제 구현 |
|---|---|
| `render_cards.py` | 1080×1350 PNG/JPEG. cover는 큰 헤드라인·강조색·계정 브랜딩, body는 번호 요점 1~3개, closing은 원출처·저장/공유 안내·계정명. `**강조**`를 색으로 표현. 표지/본문에 사용자 로컬 이미지 슬롯, 없으면 자체 기하 패턴 |
| `config.example.yaml`, `common.py` | forest / ink / coral 프리셋과 선택적 색 덮어쓰기. 사용자 이미지·음원·폰트 경로의 설정 파일 기준 해석. 기본은 offline·silent |
| `make_reel.py` | 1080×1920·24fps. 카드별 짧은 페이드, 느린 줌/팬, 카드와 분리한 자막 페이드/슬라이드 등장, 전체 진행 막대. 장면 MP4를 연결하고 SRT도 생성. 기본은 무음 AAC |
| `audio.py`, `tts_backends/README.md` | 직접 녹음 MP3/WAV, 사용자 제공 음악 MP3/WAV. 내레이션 1.0배·음악 0.18배 믹싱. 짧은 음원은 무음으로 채우고 긴 음원은 영상 끝에서 자름. 명시적 `module:function` TTS 플러그는 WAV 출력 계약, 기본 백엔드·모델·다운로드 없음 |
| `write_copy.py`, `prompts/` | offline 후보 추출, prompt.md 생성 후 웹 채팅 답변 JSON 붙여 넣기, OpenAI 호환 api 경로. 카드 문안·릴스 대본·캡션+해시태그 템플릿에 사실 추가 금지·출처 유지·과장 금지 포함 |
| `run_pipeline.py` | prompt는 문안 대기에서 종료한 뒤 JSON 검증→render로 재개. api는 환경변수와 `--allow-api` 필요. 오프라인 run은 API·TTS 플러그 차단. render는 원자료와 JSON 계약을 검증하고 기존 승인 폐기 |
| `review.py` | 여섯 항목 검수. 내레이션·음악·TTS 라이선스와 AI 표시 확인. 실제 사용 음원·자막 PNG·장면 MP4도 해시 검수 대상에 포함 |

오프라인 문안은 기존의 최대 3개 RSS 항목을 유지하며 **표지 1장 + 본문 3장 + 마무리 1장**을 만든다. 각 요약의 문장을 그대로 나누어 번호 요점으로 배치한다. 합성 표시는 합성 피드의 카드 하단에 작게 유지하며 실제 RSS 카드에 합성 배지를 붙이지 않는다. 본문은 points를 렌더링하므로 README에서 body와 함께 편집하도록 안내했다.

JSON 검증은 필드·자료형·장면 순서·요점 수·합성 표시·원출처 링크 보존을 확인한다. 사실 검증·저작권 판정은 수행하지 않는다. prompt 생성은 기존 copy.json을 덮어쓰지 않으며, API 실패·중단 응답·잘못된 JSON·출처 누락 때도 기존 문안을 보존한다. 키·모델·엔드포인트는 환경변수로 받고 인증 헤더만 사용한다. 인증 값·응답 전문은 출력하지 않고 리다이렉트는 거부한다. 실제 공급자 호출 없이 모킹으로 계약을 검증했다.

정책 설명은 **2026년 10월 조사 기준**이며 [FACT-SHEET](../../research/FACT-SHEET.md)의 META-06, ALG-03·04, LABEL-03, VIDEO-01~10을 따른다. META-06은 Hermes의 원문 일부 보고이며 Codex의 독립 본문 확인 한계를 함께 안내했다. 애니메이션·TTS 추가가 독창성·추천·수익화 적격을 보장한다고 설명하지 않는다. README에 **연습용이며 수익화 적격을 보장하지 않음, 직접 촬영·내레이션 등 독창적 요소 추가**를 명시했다. TTS 엔진·모델·화자·출력물의 이용 조건은 사용자가 확인하며, 가장 권장하는 음성 경로는 본인 녹음이다.

## 실제 검증

환경: Ubuntu 22.04 x86_64, Python 3.11.15, Pillow 13.0.0, PyYAML 6.0.3, imageio-ffmpeg 0.6.0, pytest 9.1.1. 기존 가상환경과 pip 동봉 FFmpeg 7.0.2 사용. 추가 패키지·모델·시스템 도구를 설치하지 않았다.

저장소 루트에서 실행:

```bash
starter-kit/.venv/bin/python -m pytest -q -c starter-kit/pytest.ini --basetemp=starter-kit/.cache/pytest-phase4b-verified
```

**55 passed in 25.94s.** 최종 코드·테스트와 재생성 샘플 기준이다. 보완 중 추가한 실패 시나리오의 테스트 준비 폴더 누락을 수정한 후 전체를 다시 실행했다.

| 검증 범위 | 확인 내용 |
|---|---|
| 기본 전체 흐름 | socket·urlopen 차단 상태에서 합성 RSS→문안→PNG/JPEG→MP4→검수 대기→테스트용 검수표 처리→승인→드라이런 |
| 카드 | 3가지 테마·레이아웃, 본문 요점 3개, 실제 강조색 픽셀, 사용자 이미지의 슬롯 반영, 누락 이미지·원격 이미지 경로·글 넘침 거부 |
| 영상 | 실제 MP4 디코딩: 1080×1920, 24fps, 20초, 480프레임, H.264/AAC. 같은 장면의 카드/자막/막대 영역이 시간에 따라 달라지고 경계에서 페이드됨. 기본 오디오 PCM이 무음임을 확인 |

| LLM | 프롬프트 3종·기존 문안 보존, 웹 채팅 응답 검증, 잘못된 자료형/장면/요점·합성 표시 제거·원출처 누락 거부. 모킹한 API 요청·성공·중단·형식 오류·통신 실패·인증 값 비노출·명시적 활성화 확인 |
| 승인 회귀 | 승인 없음·체크 누락·문안/PNG/MP4/검수표/manifest 변경·재렌더링 실패 차단. 5장 캐러셀과 릴스 요청 계획 16단계 |
| 샘플 | PNG 5장과 MP4 규격 및 실제 모션·무음 확인. samples 전체 **1,575,617바이트**, 10MB 이하 |

실제 CLI에서도 offline 생성, prompt 모드의 문안 대기, 답변 JSON 저장→`write_copy.py --validate`→render→approve→독립 publish 드라이런을 실행했다. 웹 채팅 답변은 재현 검증을 위해 로컬 합성 문안으로 대체했으며 외부 LLM을 사용했다고 표현하지 않는다. 검수표 자동 체크도 테스트용이다. approve와 publish의 드라이런 출력이 일치하고 요청은 16단계임을 확인했다. Python 컴파일 검사와 `git diff --check`도 통과했다.
