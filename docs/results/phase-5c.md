## 사실과 구현의 경계

정책·법·플랫폼 수치에는 기존 FACT-SHEET ID·SOURCES 번호·원문 URL·조사 기준일을 붙였다. 총 86개 사실 참조 문단이며 장별 17/12/33/16/8개다. 새 사실 ID·출처는 만들지 않았다. 공식 안내·역사적 발표·Hermes 간접 확인·실계정 미검증을 본문과 각주에서 구분했다. 광고 현행 지침·국세청 창작자 안내·YouTube YPP 원문을 이번에도 열어 기존 연구 범위를 대조했다.

- 10장은 API의 50/100 충돌, Instagram/Facebook/Unified 경로, JPEG·공개 URL, 컨테이너·발행·호출 단위, AI/파트너십 지원 차이를 다룬다. 키트에 예약기·토큰 발급·호스팅·광고 라벨이 구현됐다고 설명하지 않았다. 실제 게시는 독자의 별도 선택이며 실행하지 않는다.
- 11장은 측정한 0과 미게시/측정 불가를 구분한다. 같은 기간·플랫폼·광고·합산 범위만 비교하고 연습 비율의 분모·식·한계를 공개했다. Buffer 관찰연구와 Socialinsider의 미래 기간·표본 혼재도 설명했다.
- 12장은 권리·광고·AI/가상인물·정확성·보안·세무를 별도로 점검한다. 법 적용 주체·계도 발표 한계, 원천징수/최종세금·면세/소득세 신고를 구분한다. 위험 점수나 적법성 보증을 만들지 않는다.
- 13장은 팔로워 이정표를 수입 보장선으로 쓰지 않는다. YouTube 초기/광고 기준, TikTok 1만/5만 상충, 클립 검색 발췌·Threads 한국 지급 미확인, 음원 반출 조건을 설명했다. 현금 잔액과 세무상 순이익은 구분한다.
- 14장은 입력 시간에 점검을 먼저 배정하고, 휴식·미완료를 보존한다. 성장 예측·정답 게시 시각을 제시하지 않는다. 공식 학습 경로에는 확인일·언어·인증·미확인 조건을 함께 적었다.

10장의 n8n 공개 템플릿, 11장의 뉴닉, 12장의 Stanford Facebook 관찰, 13장의 국내 미디어·해외 스튜디오·가상인물은 조사 근거 범위만 사용했다. 14장은 실제 운영 사례 근거 대신 ‘가상 사례 유형 분석’이라고 명시했다.

## 실제 키트 실행

기존 `starter-kit/.venv`의 Python 3.11과 설치된 Pillow·FFmpeg를 사용했다. 별도 의존성·모델·유료 키를 추가하지 않았다. 출력은 Git 제외 경로 `starter-kit/output/phase5c-dryrun`이다. [실행 증거](phase-5c/starter-check.json).

1. `python run_pipeline.py --offline --output output/phase5c-dryrun`: 성공, 검수 대기에서 종료.
2. 승인 전 `python publish.py output/phase5c-dryrun`: exit1, 검수 대기 차단이 예상대로 동작.
3. 원자료·문안과 카드 전체 축소본·영상 표본 프레임을 확인한 뒤 **명령 검증용 합성 fixture**의 체크를 채웠다. 실제 사람의 영상 전체 재생 검수나 실게시 승인을 수행했다는 뜻이 아니다. 교과서에는 자동 체크 명령을 싣지 않고 독자의 직접 검수를 요구했다.
4. `python run_pipeline.py approve output/phase5c-dryrun`, 승인 후 `python publish.py output/phase5c-dryrun`, `python publish.py --help`: 모두 성공. 승인 출력과 publish 재실행 JSON이 일치하고 JPEG 자식 5개·발행 단계 2개·토큰 비출력을 확인했다.
5. 1080×1920·20초·24fps·무음 릴스를 FFmpeg로 끝까지 디코딩해 exit0을 확인했다. 카드·영상 표본에서 한글·출처·합성 표시를 확인했다. 디코딩은 사람이 영상을 끝까지 보는 검수를 대체하지 않는다.

장에는 가상환경 활성화 뒤 `python` 명령으로 표기하고 Windows 실행 파일과 macOS/Linux 실행 파일의 차이를 짧게 병기했다. Windows/macOS 실행과 OS 예약 등록·정시 기동은 검증하지 않았다. cron은 설정안, Windows는 설정 절차이며 독자에게도 미검증 범위를 밝혔다. 이 환경의 crontab에는 비설치 문법검사 옵션이 없어 시스템 예약을 등록하는 검증으로 넓히지 않았다. 실제 게시 플래그·토큰 발급·로그인·유료 호출은 수행하지 않았다.

정적 서버 `python3 -m http.server 8513 --bind 127.0.0.1 --directory site`와 기존 `/tmp/ai-insta-phase3-browser/node_modules/playwright-core`, Chromium 1228을 사용했다. 새 설치 없이 확인했다.

- 최종 **152개 동작 검사와 내부 URL·앵커 265개 통과**, 콘솔·페이지 오류 0. [브라우저 증거](phase-5c/browser-check.json).
- 다섯 장 모두 1280px·375px에서 문서 폭이 뷰포트와 일치한다. 본문·용어 포커스·도구 입력에서도 가로 넘침이 없다. 첫 검사에서 10장 482px 넘침을 발견해 로컬 모바일 툴팁 스타일로 수정했다. 공통 적용은 requests에 남겼다.
- 장별 9블록, 퀴즈 4문항의 오답/정답·해설·재시작, 그림 방향키, 숫자/선택 입력 키보드 조작, Enter 프리셋, 체크 재로딩 저장을 확인했다.
- 10장 발행 2건/묶음·한국 21시→UTC 12시·빈 입력 보류, 11장 5%/3%·0 분모·빈칸·범위 불일치·해석 피드백, 12장 표시 완료에도 권리/오류/노출 3항목 보류, 13장 현금 잔액·시간당 계산·손실·시간 0 보류를 확인했다.
- 14장 30개 날짜, 확보 시간 0·활동일 0·점검만 가능한 5분, 미배치 작업·텍스트 복사를 확인했다. 저장 접근 차단에서도 체크 가능, 다크 모드, 인쇄 시 도구 숨김, JS 비활성 시 9블록·퀴즈 해설 유지도 확인했다.
- [정적 검사](phase-5c/static-check.json): 기존 사실 ID·각주 연결·절 앵커·중복 ID 없음·상대 스크립트 경로를 확인했다. JS 5개 `node --check` 통과.
- [보호 파일 확인](phase-5c/protected-files.json): 공통 6개 파일과 PROJECT_STATE는 HEAD와 동일하다. 다른 작업자의 2~9장·결과 문서와 기존 미추적 prompts 파일을 수정하지 않았다. commit·push를 시도하지 않았다.
