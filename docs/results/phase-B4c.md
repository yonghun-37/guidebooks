# B4c — 이론 10~13장 집필·검증

## 요구사항과 실행 계획

사용자가 지정한 DESIGN-blog·STYLE-GUIDE와 B3 샘플을 적용한다. 담당 파일은 `site-blog/chapters/10-automation.html`, `11-analytics.html`, `12-policy.html`, `13-plan.html`, 각 장의 `assets/ch10~13.js|css`, 이 결과·검증 폴더·통합 요청·용어 요청이다. 공통 자산·부록·프로젝트 상태는 통합 담당자가 반영한다. 기존 미추적 `auto-kit/`은 보존한다.

- [x] 지침·설계·학습자 질문·조사·샘플·blog-kit README와 B3k 결과 확인
- [x] 10장: 세 글 유형의 자료 틀, AI 재사용 요청, 공식 예약과 API 구분, 실제 키트 명령 재현
- [x] 11장: 같은 기간·분모의 지표, 유입 검색어·CTR·RPM 해석 도구와 경계값
- [x] 12장: 광고 첫 부분·권리·AI 조건·수익원별 세금 확인, 표시 위치 도구
- [x] 13장: 하루 60분의 30일 운영표, 자료 준비 상태·수정·기록·다음 달 판단
- [x] 문체·정적 검사, 3폭×2테마·키보드·오류·링크·JS 없는 본문 검증
- [x] 통합 diff·용어·검증 결과·스크린샷 정리와 완료 알림

구현은 기존 정적 HTML·CSS·바닐라 JS를 쓴다. 새 의존성·외부 AI/API 호출은 추가하지 않는다. 각 장은 9블록, 동일 축 틀, FAQ 5개, 퀴즈 3개로 구성한다. 그림은 직접 그린 흐름·표시 위치·전후 비교이며 CSS 변수로 두 테마를 지원한다. 유료가격·세금·정책은 기존 B출처만 쓴다. 수업 시간·가상 계산은 해당 묶음 머리에 표시한다.

검증은 사용자 행동 중심으로 먼저 작성한다. 검색/광고 0분모·미집계·잘못된 값, 관계별 표시 위치, 날짜·예산·경험 없는 후기 계획을 중점 점검한다. 샘플의 반복 단서는 재사용하지 않고 각 축 끝 확인 상자로 모은다. 기존 장 데이터는 준비중 상태이므로 본문 직접 링크를 쓰고 book.js 변경은 요청 diff로 남긴다.

## 구현 결과

- [10장](../../site-blog/chapters/10-automation.html): 지원 제도·생활 가전 후기·당일치기 여행의 자료 틀, ChatGPT 새 대화에 넣는 요청문, 좋은/나쁜 결과, Canva·미리캔버스 디자인 재사용, 공식 예약과 API 초안을 연결했다. Blogger OAuth·설치형 WordPress 전용 비밀번호·.com의 별도 인증을 구분했다. 네이버·티스토리 API 종료와 매크로 금지를 설명했다. 키트는 선택 ‘자동화·무료 대안’으로 두며 변환·승인·드라이런·daily·예약 안내를 실제 출력에 맞췄다.
- [11장](../../site-blog/chapters/11-analytics.html): 방문자/방문/PV, 검색 CTR·CPC·페이지 RPM, 주문/취소/확정/입금을 분리했다. 가상 검색어 표는 합계와 유입 구성이 어떻게 달라지는지 보여 준다. 도구는 같은 기간의 CTR·RPM을 계산하고 유입 질문에 맞춘 다음 행동을 제시한다. 비활성 지표 입력은 숨기고 빈칸·음수·소수 건수·클릭 초과·0분모·계산 범위 초과를 처리한다.
- [12장](../../site-blog/chapters/12-policy.html): 실제 관계별 첫 부분 예문, 파일별 이용 권리·AI 약관/표시·가짜 체험, 광고 클릭 부탁 금지, 수익원별 정산·원천징수·한국 신고·미국 세금 정보를 설명했다. 표시 위치 도구는 세 관계×네 위치를 직접 그린 글 구조로 보여 주며 위치 판단과 실제 관계·크기·색·접힘 확인을 연결한다. 세율 확정 계산기는 만들지 않았다.
- [13장](../../site-blog/chapters/13-plan.html): 첫 공개→반복→보완→다음 달 판단으로 하루 60분의 30일 계획을 만들었다. 시작일·작업분·글 유형·실제 사용 메모 여부를 받아 날짜별 30행·남길 것·체크·전체 복사를 제공한다. 후기 자료가 없으면 공식 사양·실제 사용 기록 준비로 바꾸고, 검수·기록 시간을 남긴다. 날짜·시간 오류 시 이전 표/복사 내용을 비운다. 체크는 현재 화면에서만 유지한다.
- 각 장은 9블록·같은 축 틀·FAQ 5개·퀴즈 3개다. 수아·태오와 같은 블로그의 세 소재를 이어 썼고 성과를 만들지 않았다. 직접 그린 흐름·글 구조·전후 비교는 두 테마의 CSS 변수에 맞춘다. 그림 수를 목표로 삼지 않았다.
- 복사 버튼은 클립보드가 차단되면 문구 선택 또는 읽기 전용 텍스트 선택으로 전환한다. JavaScript 없이 본문·FAQ·출처·30일 기본 표를 읽을 수 있다. 새 서비스 호출·의존성·저장은 추가하지 않았다.

## 근거 대조·실행 범위

기존 BRIEFING·FACT-SHEET·SOURCES·QUESTION-MAP·관련 노트와 B3/B3k 결과를 대조했다. 공정위 현행 지침(B037), 국세청 신고 기간(B086)·사업자등록(B154), RPM 정의(B058), Blogger insert(B012), 티스토리 API 종료(B007), 네이버 현행 약관(B158), 애드센스 미국 세금 정보(B087)는 공식 웹 원문도 다시 열어 주요 내용을 확인했다. 새 정책·사실표 항목을 만들지 않았다. 조사 노트의 키트 ‘설계 제안’ 표시는 B3k 실제 구현 결과와 README를 우선해 설명했다.

[키트 재현 코드](phase-B4c/verify-kit.py)·[명령과 출력](phase-B4c/kit-check.json): Linux의 깨끗한 임시 복사본에서 본문 명령 11개 성공. 모든 Python socket 연결을 차단하고 인증 파일·LIVE_ATTEMPT가 생기지 않았음을 확인했다. 체크·변환·daily 시작/재개·연습 검수표 입력 모사·승인·Blogger/WordPress 드라이런·네이버/티스토리 복사 안내·두 OS 예약 안내를 실행했다. 실제 경험 검증·live·토큰 발급·OS 등록 성공의 기록은 아니다.

## 통합 요청·남은 범위

- [공통 반영 diff](phase-B4c-requests.md): 장 10~13 status, 원본 도구 4개, credits 인용 추가. 공통 장 데이터가 준비중이어서 전체 목차·이전/다음은 아직 준비중 경로다. 본문 직접 링크와 묶음 하단 링크는 정상 동작한다. 실험실 최종 등록 후 전체 iframe 검증은 통합 담당자가 수행한다.
- [용어 요청](phase-B4c-glossary.md): 기존 UV/PV/RPM과 중복되지 않도록 템플릿·API·OAuth·인증 토큰·드라이런·방문·CTR·CPC·광고 표시·원천징수 등을 정리했다.
- PROJECT_STATE·서가·공통 자산·부록·연구 파일은 수정하지 않았다. 담당하지 않은 병렬 B4a/B4b/B5 산출물과 기존 `auto-kit/`은 보존했다.
- 실계정 가입/발행/예약·유료 API·결제·인증 발급·live·OS 예약 등록·Windows/macOS 실기기는 미실행이다. 정책·세무의 개별 적용은 실제 계약·정산 기록으로 확인할 항목이다.
- 새 의존성·아키텍처 변경이 없으므로 ADR은 추가하지 않았다. commit/push하지 않았다.

`scripts/notify.py`로 대표 30일 계획 화면을 첨부해 완료 알림을 전송했고 HTTP 200을 확인했다.
