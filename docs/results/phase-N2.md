## Hermes 실행·품질표

- 총 **23회 / 상한 32회**: 기본 20회와 제공자 오류 3회의 각 1회 재시도다. 기본 실행은 최대 4개, 재시도는 최대 3개를 병렬 운영했다. 새 API 키·결제·서비스 설정 변경은 없었다.
- 명령: `hermes chat --query-file … -Q --provider openai-codex -t web -s guidebook-research --max-turns 40`. 컨테이너 사용자 `1000:1000`, `HOME=/opt/data`, 호스트 제한시간 900초다. 기존 컨테이너를 사용했다.
- 기본 실행의 근거 없는 실패는 **3/20회(15.0%)**다. 재시도 3회는 모두 근거가 포함된 응답을 반환했다. 전체 호출의 실패는 **3/23회(13.0%)**, 최종 20주제는 모두 근거 응답을 확보했다. 모든 주장이나 원문 접근이 검증됐다는 뜻은 아니다.
- 물리적 빈 응답(0바이트/공백만)은 **0회**다. 오류문만 있고 근거 URL이 0개인 **근거 빈 응답 3회**(02·05·08)를 별도로 실패 처리했다.
- 원응답에서 `403`은 **22회 등장**한다. “403 없음” 문장도 포함한 문자 집계다. 실제 403 발생을 서술한 기본 질의는 **4회(01·03·04·06)**다. HTTP 요청별 로그가 없어 문자 등장 수를 실제 403 요청 건수로 사용하지 않는다.
- T는 `timeout / timed out / 시간 초과 / didn't respond in time`, B는 `blocked / 검색 실패 / 접근 실패`의 패턴 수다. 오류가 없다는 서술도 검출될 수 있고 서술형 오류가 누락될 수도 있다. 따라서 0을 성공으로 읽지 않고 본문·URL·수치·한계 보고를 함께 점검했다.

## 설계 조정·실습 7·계산기 결론
