# Phase 5b 용어 통합 요청

담당 장은 6~9장이다. 용어집은 병행 작업의 공유 파일이므로 수정하지 않았다. 기존 `api`·`carousel`·`pipeline` 앵커는 사용하고, 새 용어는 현재 용어집 페이지 자체에 연결하며 `data-term`으로 아래 설명을 제공한다. 통합자가 용어를 추가한 뒤 아래 제안 앵커로 링크를 바꿀 수 있다. 키트의 필드·파일 형식 설명은 실행한 구현에 근거하며 별도 정책 사실 ID를 만들지 않았다.

| 용어 | 쉬운 설명 | 처음 나온 장 | 관련 사실 ID |
|---|---|---|---|
| 프롬프트 | AI에게 작업 목적·자료·제약·출력 형식을 알려 주는 지시문 | 6장 | AI-01·AI-07 |
| JSON | 항목 이름과 값을 정해진 문법으로 저장하는 텍스트 파일 형식 | 6장 | 해당 없음 — write_copy.py의 출력 계약 |
| 템플릿 | 제목·요점·이미지·출처 자리와 모양을 미리 정한 틀 | 7장 | 해당 없음 — render_cards.py의 구현 |
| 렌더링 | 문안과 배치 규칙을 실제 이미지나 영상 파일로 만드는 과정 | 7장 | VIDEO-06·VIDEO-08 |
| 프레임 | 영상을 이루는 한 장의 화면. fps는 1초에 보여 주는 화면 수 | 8장 | 해당 없음 — make_reel.py의 구현 |
| TTS | Text to Speech. 글을 기계가 읽는 음성으로 바꾸는 기능 | 8장 | VIDEO-01~04·PRICE-01~03 |
| SRT | 자막 문장과 시작·끝 시간을 적는 텍스트 파일 형식 | 8장 | 해당 없음 — make_reel.py의 구현 |
| 드라이런 | 실제 전송 없이 실행할 요청과 순서를 확인하는 예행 연습 | 9장 | 해당 없음 — publish.py·run_pipeline.py의 구현 |
| 해시 | 파일 내용으로 계산하는 지문값. 내용 변경을 비교할 때 사용 | 9장 | 해당 없음 — review.py·common.py의 구현 |
| 노코드 | 코드를 직접 쓰는 대신 화면에서 작업 블록을 연결하는 방식 | 9장 | NOCODE-01~04 |
| 커넥터 | 외부 서비스와 연결해 자료나 요청을 주고받는 작업 블록 | 9장 | NOCODE-02·NOCODE-03 |

제안 앵커: `prompt`, `json`, `template`, `rendering`, `frame`, `tts`, `srt`, `dry-run`, `hash`, `no-code`, `connector`. 용어집 담당자가 같은 의미의 기존 항목을 만들었다면 그 항목으로 통합한다.
