## 실험실 목록 생성

가중치·현금 장부·니치 자기평가 도구를 새 질문 도구로 교체했다. 기존 JS(`map.js`, `ch02.js`, `ch03.js`, `ch04.js`)는 수정하지 않고 HTML에서 연결만 끊었다. 새 전용 JS는 저장이 필요 없는 DOM 도구다. 현재 목록 생성기는 `ReelsSim.mount`만 찾아 새 도구를 누락하므로, 명시적 루트 `document.querySelector('#도구ID')`도 읽게 한다. 아래 변경은 임시 실행으로 1~4장 도구 4개의 ID·제목·절을 추출해 확인했다.

+++ b/scripts/build_appendices.py

이후 전체 개편을 모아 `scripts/build_appendices.py`로 공통 목록·출처를 갱신한다. 이 작업자는 생성기를 실행하지 않았다. 1~4장의 예상 새 항목:

| 장 | ID | 제목 | 절 |
|---|---|---|---|
| 1 | time-budget | 이번 주에 몇 편을 연습할까요? | simulator |
| 2 | signal-sim | 내 설명은 카드 몇 장이 되나요? | simulator |
| 3 | ledger-sim | 쿠팡 인정 구매 수를 바꿔 보세요 | simulator |
| 4 | niche-sim | 내 기획에 빠진 항목을 찾습니다 | simulator |

기존 8개 실험실 진입 ID는 원래 주소로 열리며, 정적 축 카드나 새 도구를 보여 준다(브라우저 검증 완료). 목록 갱신 전에는 이전 도구 이름이 남는다. 출처 페이지의 기존 링크가 깨지지 않도록 각 장의 ‘이전 판의 참고자료’에 이전 출처 앵커도 보존했다.

## 한 달 요약과 상태 문서

3·4장의 새 도구는 입력을 저장하지 않는다. `lab.js`와 `build_appendices.py`의 한 달 요약은 아직 예전 ‘현금 장부·니치 자기평가’ 저장값과 안내를 읽는다. 새 입력을 그 구조에 억지로 저장하지 않았다. 통합 단계에서 이 두 카드를 새 도구 바로가기(구매 수수료 계산·기획 점검)로 바꾸고, 옛 저장값을 현재 계산 결과로 표시하지 않도록 정리해야 한다. 새 결과의 자동 합산은 요구하지 않는다. 14장 요약은 담당 작업자의 최종 구현에 맞춘다.

`PROJECT_STATE.md`는 병렬 작업 규칙에 따라 수정하지 않았다. 통합 담당자가 이론 1~4장 개편·새 도구 4개·검증 결과와 공통 목록 미통합 상태를 반영한다. 실제 앱 기능 노출·개설·지급과 쿠팡 실시간 요율은 기존 연구의 남은 확인 항목이다.
