## 바뀐 행동과 근거

- **시작·계정:** 결과물을 첫 줄에서 알리고 카드/릴스 하나부터 올리는 경로를 제시했다. 계정 추가의 실제 시작 메뉴, 앱 동시 로그인 **10개**와 계정 센터 연결 **25개**의 차이, 프로 전환의 공개·대기 요청 수락 효과를 반영했다. 별칭 가입 성공을 가정하지 않고 별도 이메일로 안내한다. 인증 앱·백업 코드·새 코드 받기, 보관·삭제·복원 경로도 보강했다. 근거: R2-ACC/SEC/MANAGE, S180~182·S203~206·S228~231.
- **설치·제작:** 기존 명령·출력 폴더를 이어 쓰는 흐름을 유지했다. 작성자 면책·본문 사실 ID·반복 주의를 제거했다. 문안 직접 편집 경로, 실제 자료로 바꾸는 새 피드, 카드의 points, 현재 config.json, 무음/녹음 선택과 영상 수익화 포맷을 직답한다. 예제의 5장·1080×1350·20초·1080×1920은 플랫폼 규격으로 오해하지 않게 구분했다.
- **검수·앱 게시:** `AI 레이블 추가`, `파트너십 레이블 및 광고 → 협찬 광고 레이블 추가`, 브랜드명 승인 효과를 반영했다. 캐러셀 재정렬, OS별 릴스 시작·커버 수정·선택 캡션·보이스오버, 게시물/릴스 링크 복사 경로를 출처와 함께 안내한다. 게시 후 필수 표시 수정에 의존하지 않고 공유 전에 확인한다. 근거: R2-LABEL/PUB/POLICY, S012·S068·S183·S237~246.
- **API·예약·관찰:** 첫 게시와 선택 API를 구분하고, 실제 live 명령의 무심코 복사를 줄이기 위해 조건을 읽는 README 경로로 연결했다. API 한도 100/50 충돌은 보수적으로 계획하고 계정별 조회로 확인하게 했다. 예약은 현재 도움말의 **30일 전·하루 25개**와 `옵션 더 보기`, `예약됨`, `일정 조정`을 채택했다. Suite는 데스크톱의 `게시물 만들기`, `게시할 위치`, `예약 옵션`, `플래너`를 쓴다. 인사이트는 실제 진입 경로와 최근 90일/기본 기간 5개를 반영했다. 근거: R2-API/SCHED/SUITE/INSIGHT/TESTER.
- **구성·인터랙션:** 각 실습에 FAQ 5개와 본문 첫 답에 근거한 확인 퀴즈 1개를 추가했다. 단계표는 실습 0·8·E2E의 경로/상태 판단에 쓴다. 실습에 별도 시뮬레이터는 없어 불필요한 모형을 추가하지 않았다. 기존 실험실용 JS와 도식 파일은 삭제하지 않았다. 내용과 중복되는 일반 휴대폰 도식의 연결만 정리했다.
- **이어 하기:** 기존 절 주소·35단계 체크 키·브라우저 저장 키·게시물 주소 필드를 유지했다. 실습 9의 선행은 검수/게시 화면, 10은 첫 게시로 고쳐 선택 API·예약을 필수로 보이게 하지 않았다. 실습 7에서 바로 10으로 갈 수 있다. 실습 끝의 다음 버튼과 전체 진행표를 유지했다.

앱 표준 안내는 해당 메뉴 경로 옆에 페이지당 한 번 쓴다. 시간·기기 차이 안내는 실습 0에 모았다. [메뉴 확인표](phase-7w-verify-list.md)는 원래 후보 문구를 이력으로 보존하고 현재 반영 본문을 새 열에 연결한다. **18개의 실기기 확인 속성은 모두 유지**한다. 문서 근거를 실기기 성공으로 바꾸지 않았다.

실행 명령은 첫 생성 → prompt.md와 기존 copy 보존 → 직접 편집/구조 검증 → 카드/영상 재생성 → 녹음 입력 경로 → fixture 검수 → approve → publish 드라이런 → 공개 미디어 준비 → URL 지정 드라이런 → 새 로컬 피드다. 승인 후 copy.json 변경 시 게시 거부도 확인했다. 자동 검수 체크 처리는 검증 fixture에만 사용했다. 본문 성공 문자열 `검수 대기`, `구조 검증 OK`, `mode: dry-run`, `공개 준비 완료: 6개 JPEG/MP4`와 실제 출력을 대조했다.

최초 시스템 Python 3.10 설치 시도는 고정 패키지의 호환 배포본을 찾지 못했다. 요구 버전인 3.11로 새 환경을 만든 뒤 같은 requirements 설치와 후속 명령이 통과했다. 패키지 버전이나 키트 파일은 바꾸지 않았다. Windows/macOS의 설치기·PowerShell·기기 조작을 실제 실행했다고 보고하지 않는다.

재현은 저장소 루트에서 다음을 실행한다. 기준선은 재생성하지 않는다.

```sh
python3 scripts/style_lint.py site/practice/[0-9][0-9]-*.html --baseline docs/results/phase-9/baseline.json
python3 scripts/style_lint.py site/practice/e2e.html
python3 docs/results/phase-9d/check.py
starter-kit/.venv/bin/python docs/results/phase-9d/walkthrough.py
# 별도 창에서 저장소 루트를 http.server로 제공하고 그 주소를 지정한다.
SITE_URL=http://127.0.0.1:포트/ node docs/results/phase-9d/verify.mjs
```

E2E는 기존 공통 기준선에 없으므로 별도로 문체 검사한다. Chromium 1228·기존 Playwright Core를 사용했다. 외부 폰트는 빈 CSS로 대체해 시스템 폰트로 검증했다. 브라우저 검사기는 `/tmp/ai-insta-phase3-browser` 경로를 사용하므로 다른 환경에서는 경로를 맞춘다.

## 남은 문제와 인계

실제 계정 로그인·가입·전송·게시·테스터 초대 수락·토큰 발급/갱신·예약 발행·인사이트 조회와 Windows/macOS·다른 브라우저·독립 초보자 검수는 수행하지 않았다. 유료 API·결제·호스팅 업로드는 하지 않았다. 테스터 수락, AI 토글의 정확한 계층·게시 후 변경, 라벨/음원/예약 조합, 계정별 한도·한국 기능 노출은 지정된 확인표에서 계속 확인한다.

기존 생성기는 개편 이전 내용을 덮어쓴다. **`scripts/build_practice.py`를 재실행하지 않는다.** [통합 요청](phase-9d-requests.md)에 보호 diff·현재 상태 반영 문구를 남겼다. `PROJECT_STATE.md`·공통 스타일/JS·부록·현황 페이지는 파일 소유 범위에 따라 통합 작업자가 갱신한다. 담당 12 HTML·전용 결과 기록·사용자가 지정한 확인표 외에는 수정하지 않았다. commit·push는 하지 않았다.
