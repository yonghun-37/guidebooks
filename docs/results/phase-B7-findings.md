# B7 블로그 독립 검토 — 발견 사항

검토일: 2026-10-26. 검토자: Codex, 블로그 경험이 없는 학습자 역할의 독립 검토자.

**결론: 조건부 — 본인 자료가 준비된 독자는 PC의 무료 AI·공식 편집기 경로로 오늘 첫 발행을 시도할 수 있다. 다만 자료가 없는 초보자를 이끌 완성 사례와 일부 질문의 직답·화면 안내를 보완해야 한다.**

발견은 **차단 0 · 혼란 8 · 사소 3, 총 11건**이다. 차단은 기본 수동 발행 경로를 진행할 수 없는 문제, 혼란은 추가 추측·도움말 탐색·시행착오가 필요한 문제, 사소는 완주에 영향이 작은 표현·참조 문제로 구분했다. 선택 기능의 불편을 첫 발행 차단으로 세지 않았다.

## 검토 범위와 확인한 장점

AGENTS.md, STYLE-GUIDE 5·6·7절, 학습자 질문 120개를 읽고 **표지 → 이론 1~13 → 실습 0~10 → E2E → 실험실·용어집·프롬프트·모델/비용·출처 부록** 순서로 읽었다. 샘플 원고·미리보기·README와 두 이전 주소 안내 페이지도 확인했다. 기존 B6 결과의 판정을 답습하지 않고 본문과 실행 결과로 판단했다.

- 어떤 AI를 쓰는지: ChatGPT Free의 주소·가입·새 대화·입력·복사·저장까지 실습 2가 연결한다. 같은 AI로 개요·초안·교정을 이어 가므로 도구 선택 부담이 작다.
- 얼마가 드는지: 추가 구독 0원 조합, 미리캔버스 월 구독 예, 앱/API의 별도 과금과 편당 배분 계산을 구분한다. 무료 한도 소진 시 직접 이어 쓰는 길도 있다.
- 수익이 어떻게 생기는지: 광고·구매 제휴·협찬·내 상품의 돈 흐름, 승인 전 광고 수입 0원, 취소 반영, 예상·확정·입금 차이를 직답한다. 방문자만으로 수익을 보장하지 않는 설명은 유지할 만하다.
- 발행: 실습 7은 네이버의 설정 창 열기와 최종 발행, 티스토리 임시저장과 공개를 구분한다. 공개 주소를 로그아웃한 휴대폰에서 확인하도록 한다. 검색·광고 승인을 첫 발행의 필수 조건으로 두지 않는다.
- 키트: Python 3.11.15 깨끗한 임시 복사본과 동봉 ZIP에서 샘플 실행이 성공했다. 원본/ZIP 각각 pytest **97 passed**. 미승인 거부·날짜 중복 보호·승인 후 변경 거부·재변환 시 검수 초기화를 확인했다.

실제 AI 웹 서비스의 가입·생성, 네이버/티스토리 계정 로그인·게시, 광고 신청·입금은 실행하지 않았다. Windows/macOS 실기기와 실제 OS 예약 등록도 확인하지 않았다. 따라서 이 결론은 실계정 발행 성공 인증이 아니라, 학습자 관점의 원고 검토와 로컬 실행 결과다. 상세 채점·실행 범위는 [채점표](phase-B7-scorecard.md)에 남겼다.

## 발견 사항

### B7-01 [혼란] 대표 정보 글에서 실제 자료를 넣어 완성하는 한 바퀴를 볼 수 없다

- **위치:** [이론 6장](../../site-blog/chapters/06-writing.html#info) ‘정보 글 / 결과물 예시·단계별 입력과 출력’, [실습 4](../../site-blog/practice/04-draft.html#materials) ‘지원 제도 정보 글’, [샘플](../../blog-kit/samples/article.md).
- **학습자 말:** “공식 공고를 넣으라는데, 어느 사이트에서 무엇을 골라 어느 문장을 메모하나요? 완성 예시에도 실제 제도와 출처가 없어서 제가 제대로 채웠는지 모르겠어요.”
- **근거:** 입력은 `[원문 제목 / URL / 확인일]` 등 빈칸이다. 결과물 예시도 ‘공식 원문 링크·확인일·해당 지역은 실제 조사한 내용으로 채웁니다’로 끝난다. 동봉 완성 샘플은 특정 제도·금액을 안내하지 않는 ‘공고 읽는 법’이다. 장르는 현실적이지만 구체적인 조사 메모 → AI 자료표 → 손질한 완성 글의 대응을 확인하기 어렵다. 실제 정책·지원금 글을 따라 만들 기대와 차이가 있다.
- **제안:** 실제 공식 원문 하나를 확인해 짧은 발췌/자기 말 메모, 채운 요청문, 자료표, 수정 표시, 출처가 들어간 완성 글을 같은 자료로 연결한다. 신청 종료 자료라면 기준일과 학습용임을 분명히 한다. 제도 자체를 예시로 쓰기 어렵다면 ‘공고 찾기·읽기’가 결과물임을 제목부터 일치시키고, 실제 공식 공고 목록에 도달하는 경로와 채운 준비표를 보여 준다. 학습자의 허위 체험은 만들지 않는다.

### B7-02 [혼란] 따라가던 후기 제품과 첫 글이 장 사이에서 바뀐다

- **위치:** [이론 6장](../../site-blog/chapters/06-writing.html#review)·[7장](../../site-blog/chapters/07-images.html#photo), [실습 3](../../site-blog/practice/03-keywords.html#candidates), [실습 5](../../site-blog/practice/05-images.html#choose-image), [13장](../../site-blog/chapters/13-plan.html#first).
- **학습자 말:** “제습기 물통 후기를 준비했는데 키워드는 공기청정기, 사진은 필터 청소예요. 같은 글을 이어 쓰는 건가요? 첫 글도 지원 제도에서 여행으로 바뀌네요.”
- **근거:** 이론 6·7장은 소형 제습기·물통 손잡이·밤 작동음을 연결한다. 실습 3의 후기 후보는 소형 공기청정기·필터 청소, 실습 5도 분리한 필터 사진이다. 이론 1장 대표 첫 글은 지원 제도지만 13장의 기본 첫 공개는 여행이다. 여행을 더 쉬운 선택으로 권하는 이유는 실습 0에 있으나, 같은 인물의 원고를 넘겨받는 흐름이 끊긴다.
- **제안:** 정보/후기/여행 각 경로에 고정 제목·메모·사진 파일명을 두고 실습 끝까지 재사용한다. 후기는 제습기 또는 공기청정기 하나로 통일한다. 첫 글을 여행으로 바꿔 권할 때는 ‘자료가 있는 독자는 앞서 고른 글을 유지한다’는 연결을 붙인다. STYLE-GUIDE 7절의 예시 연속성 보완이다.

### B7-03 [혼란] ‘위치 안내도’가 실제로는 절차 목록이다

- **위치:** [실습 2](../../site-blog/practice/02-setup.html#ai) AI 입력 위치, [실습 5](../../site-blog/practice/05-images.html#template) 템플릿 편집, [실습 6](../../site-blog/practice/06-editor.html#editor) 편집기 위치, [실습 8](../../site-blog/practice/08-search.html#google) 검색 도구 위치.
- **학습자 말:** “그림에 ‘본문·서식 도구’라고 써 있지만 화면 어디에서 사진과 링크를 넣는지는 아직 모르겠어요.”
- **근거:** 360px 렌더링에서 실습 6 그림은 ‘1 제목 영역 / 2 본문·서식 도구 / 3 발행 설정 영역’을 세로 상자에 적었다. 실습 5도 ‘소재·업로드 / 작업 / 저장’의 같은 모양이다. 본문 단계 목록과 비교해 얻는 공간 정보가 작다. 흐름도와 광고 표시 구조 그림은 도움이 되지만, 화면 위치를 알려야 할 곳에서는 STYLE-GUIDE 6절의 목적을 충분히 달성하지 못한다.
- **제안:** 중요한 화면에만 왼쪽 도구 영역·가운데 캔버스·위쪽 저장 버튼 등을 가진 단순 화면 틀과 번호를 그린다. 편집기에는 제목칸·본문·사진/링크 도구·발행 버튼의 관계를 표시한다. 서비스 화면·로고를 복제할 필요는 없다. 공간 정보가 없는 기존 도식은 절차 목록과 합쳐 반복을 줄인다.

### B7-04 [혼란] 일반 텍스트로 보관한 AI 원고의 Markdown 기호를 어떻게 처리하는지 빠져 있다

- **위치:** [실습 4](../../site-blog/practice/04-draft.html#success) `draft.txt` 저장, [실습 6](../../site-blog/practice/06-editor.html#editor) 제목·본문 붙이기, [키트 프롬프트](../../blog-kit/brief.py) 초안 요청, [실습 10](../../site-blog/practice/10-automation.html#repeat).
- **학습자 말:** “AI 답을 메모장에 저장했더니 `## 신청 대상`, `**준비물**`이 남아요. 이 기호도 글에 넣나요? 표의 세로줄은 지우나요?”
- **근거:** 기본 경로는 AI 답 → 일반 텍스트 파일 → 공식 편집기다. 실습 6은 중복 제목·코드 울타리·검수표 제거와 소제목 서식 적용을 설명하지만, `#`·`**`·파이프 표를 본문으로 정리하는 예는 없다. 선택 키트의 `brief.py`는 실제로 Markdown 초안을 요청한다. 기본 서비스 AI가 언제나 Markdown으로 답한다고 단정하는 것은 아니며, 그 형식이 나왔을 때의 대응 공백이다.
- **제안:** ‘기호가 보이면’ 짧은 전/후 예를 추가한다. `## 신청 대상` → `신청 대상` 선택 후 편집기 소제목 적용, `**준비물**` → 기호 제거 후 굵게, 긴 파이프 표 → 항목별 문단으로 바꾸는 방법을 보여 준다. 또는 기본 프롬프트에 일반 텍스트 출력 조건을 넣고 키트 경로와 구분한다.

### B7-05 [혼란] 사이트맵은 주소 예가 있지만 RSS는 찾을 위치가 없다

- **위치:** [실습 8](../../site-blog/practice/08-search.html#advisor) ‘RSS 제출 / 사이트맵 제출’, 같은 장 FAQ 세 번째, 질문 **P08-3**.
- **학습자 말:** “사이트맵은 제 주소 뒤에 무엇을 붙일지 알겠는데 RSS는 어디서 복사하나요? 제 블로그 화면에서는 그 링크를 못 찾겠어요.”
- **근거:** 티스토리 사이트맵은 전체 주소 예가 있다. RSS는 ‘사이트가 제공하는 RSS 링크를 복사해 열어 봐요’에 머물며 링크가 있는 메뉴/설정이나 채운 주소 예가 없다. 상태 기록 양식에도 RSS URL 칸이 있다. ‘무엇을 제출하나’라는 질문에 RSS 부분은 관련 설명만 있는 부분 답변이다. 외부 사이트의 선택 검색 등록 경로이므로 첫 발행 차단은 아니다.
- **제안:** 공식 근거로 확인한 티스토리 RSS 주소 예와 해당 링크·공개 설정을 찾는 메뉴를 제공한다. 사이트별로 다르면 플랫폼별로 한 줄씩 적고, 생성되지 않거나 제출을 건너뛸 때 기록할 상태도 정한다.

### B7-06 [혼란] ‘수익 장치를 같이 써도 되나’에 조합별 답이 없다

- **위치:** [이론 9장](../../site-blog/chapters/09-monetize.html#affiliate) 확인할 점과 FAQ 네 번째, 질문 **T09-4**.
- **학습자 말:** “애드포스트가 붙으면 제습기 글의 제휴 링크를 빼야 하나요? ‘각각 약관을 확인’하라는 말만으로는 제 조합을 정하지 못하겠어요.”
- **근거:** 첫 답은 ‘매체와 광고 형식별 약관을 각각 확인해야 합니다’다. AdFit 신규 연동 종료는 명확히 답하지만, 광고망과 구매 제휴를 함께 쓰는 구체 조합·조건의 예는 없다. 이미 알려 준 서비스 이름들을 연결하는 질문에서 다시 외부 약관 읽기로 돌아간다.
- **제안:** 근거를 확인해 ‘네이버 광고+구매 제휴’, ‘티스토리 광고+구매 제휴’, ‘새 티스토리의 AdFit’ 등 실제 선택 조합을 표로 답한다. 허용되는 조합은 표시·매체 등록·광고 형식 등 조건을 함께 쓴다. 확인되지 않은 조합은 어디의 어떤 조항/지원 창구를 볼지 지정한다. 미확인 허용 여부를 지어내지는 않는다.

### B7-07 [혼란] CPC 계산에서 누구의 돈인지 다시 구분해야 한다

- **위치:** [이론 11장](../../site-blog/chapters/11-analytics.html#money) ‘광고·제휴’, FAQ 두 번째, [용어집](../../site-blog/glossary.html#cpc).
- **학습자 말:** “블로그 수입을 읽고 있었는데 CPC 예는 제가 낸 광고비인가요, 받은 광고 수입인가요? 제 광고 보고서의 무엇을 넣어야 하나요?”
- **근거:** RPM은 게시자 예상 수입으로 계산한다. 이어지는 CPC는 ‘광고 클릭당 비용·보고 단가’, 예는 ‘클릭에 따른 비용 1,000원 ÷ 10클릭 = 클릭당 비용 100원’이다. 광고주의 입찰가를 내 수입으로 바꾸지 말라는 설명은 좋지만, 수입을 배우는 독자가 이 비용 계산을 사용할 상황·보고서를 알기 어렵다. 계산식 자체가 틀렸다는 지적은 아니다.
- **제안:** ‘광고주가 내는 비용’과 ‘게시자가 확인할 보고서 값’을 구분해 예에 주체를 적는다. 블로그 초보자가 지금 CPC를 직접 계산할 필요가 없다면 그렇게 답하고 자신의 서비스에서 확인할 항목으로 연결한다. 가상 예라는 표시도 계산 옆에 두면 더 분명하다.

### B7-08 [혼란] 웹에 동봉한 README의 샘플 링크와 단독 ZIP의 조사 노트 링크가 끊긴다

- **위치:** [웹 동봉 README](../../site-blog/samples/blog-kit/README.md) 첫 문단·4~6절, [키트 README](../../blog-kit/README.md) 4~6절.
- **학습자 말:** “표지에서 README를 열고 ‘샘플 글’과 ‘완성 미리보기’를 눌렀는데 파일이 없어요. ZIP만 받았더니 API 조사 노트도 못 열어요.”
- **근거:** 웹 README는 키트 원본과 같은 상대 경로 `samples/article.md`, `samples/rendered/preview.html`을 쓴다. 실제 웹 동봉 파일은 같은 디렉터리의 `draft.md`, `preview.html`이다. 또한 단독 ZIP에는 `../research-blog/08-policy-copyright.md`, `../research-blog/07-api-automation.md`가 없다. 저장소 전체를 받았을 때만 조사 노트 상대 링크가 유효하다. 공식 외부 링크와 실행 명령은 동작하므로 우회 가능하다.
- **제안:** 웹 README의 샘플 링크를 배포 위치에 맞추고, 단독 ZIP에서도 열리는 공개 책의 출처/설명 주소 또는 공식 원문 링크를 제공한다. 저장소용 문서와 배포용 문서의 상대 링크를 함께 검사한다. Markdown 예시 코드 안의 가짜 링크 문법은 깨진 실제 링크 수에 넣지 않는다.

### B7-09 [사소] 애드센스 계정 만들기 출처 번호의 목적지가 서로 다르다

- **위치:** [실습 9](../../site-blog/practice/09-monetize.html#source-b179) B179, [출처 부록](../../site-blog/credits.html#source-b179) B179.
- **학습자 말:** “계정 만들기 안내를 눌렀는데 사이트 연결 안내로 가요. 같은 출처 번호가 부록에서는 다른 주소예요.”
- **근거:** 실습 9의 B179 링크는 `answer/7584263`, 이론 9장·출처 부록의 B179는 `answer/7402253`이다. `7584263`은 책에서 B180 ‘사이트 연결·검토 요청’에도 사용한다.
- **제안:** 실습 9의 B179를 출처표의 계정 만들기 주소와 일치시키고 링크 제목도 확인한다.

### B7-10 [사소] 완성된 장에 샘플 검토용 문구가 남아 있다

- **위치:** [이론 2장](../../site-blog/chapters/02-revenue.html)·[실습 7](../../site-blog/practice/07-publish.html) 제목 위 ‘함께 읽어 볼 샘플’.
- **학습자 말:** “표지에서는 완성이라고 했는데, 지금 읽는 수익 장과 발행 장은 아직 샘플인가요?”
- **근거:** 현재 렌더링에도 두 페이지에 샘플 배지가 남는다. 다른 완성 장과 상태 표기가 다르다.

### B7-11 [사소] 30일 계획표에 조사가 어색한 문장이 반복된다
