# 초보자 역할의 실제 작업실 메모

2026-10-26 독립 검토 중 직접 작성했다. 가상 독자·기획·가격·향후 일정이며 실제 계정·고객·수입은 없다. 기관 응답이나 사용자 피드백을 받았다고 쓰지 않았다. 각 이론 장의 `#workshop`에서 요구한 내용을 아래에 채웠다.

## 1장 · 목표와 시간

- 도울 사람 / 질문: 퇴근 뒤 읽을거리를 찾는 31세 사무직 동료 / 도서관의 독서 모임에서 어떤 책을 읽나요?
- 첫 형식 / 내가 확인할 것: 카드 / 참가자가 책을 고르는지, 신청 조건이 있는지, 원문에 없는 시간·가격을 쓰지 않았는지.
- 이번 주 확보 시간 / 한 편 실제 시간: 가상 예산 300분. 설치·작성·검수·브라우저 검토가 섞인 이번 세션 전체 시간을 일반 독자의 한 편 제작 시간으로 쓰지 않음. 사람의 순수 제작 시간은 미측정.
- 시도할 수익 경로 / 오늘 할 일: 내 요약 카드 제작 서비스와 자체 독서 기록 시트. 오늘은 합성 문안을 고쳐 PNG·MP4·드라이런까지 확인. 유료 거래 없음.

## 2장 · 형식과 관찰 계획

- 첫 형식 / 이유: 질문과 조건을 앞뒤로 비교할 카드.
- 카드 구성: 질문 표지 → 독서 모임·종이 재사용·산책의 세 합성 소식 → 출처/마무리. 이는 키트 사용 연습이며, 실제 기획의 첫 게시물은 독서 모임 하나에 집중해야 함.
- 첫 장면: ‘도서관 모임에서는 무엇을 읽나요?’
- 가상 게시 시각 / 비교 기간 / 태그: 다음 게시를 한다면 점심과 퇴근 후를 나누어 비교, 각 24시간 및 7일 뒤 관찰. 태그는 주제에 맞는 두 개를 고정할 계획. 성과를 보장하는 설정이 아님.
- 조회·도달·저장·공유: 전부 **미게시**. 0회로 적지 않음.

## 3장 · 수익 경로 두 개

| 경로 | 누가 무엇을 사면 얼마 | 가격·건수 근거 | 샘플 / 상대 / 오늘 할 일 |
| --- | --- | --- | --- |
| 직접 제작 서비스 | 가상 의뢰자가 설명 카드 한 세트 제작을 맡기면 100,000원 | 검토용 가상 제안액, 실제 거래 단가 아님. 100,000원×1건=100,000원 매출, 비용·세금 전 | 도서관 모임 설명 카드 / 실제 상대는 미선정 / 전달 범위·수정 횟수 메모 |
| 내 기록 시트 | 가상 독자가 독서 기록 시트를 사면 5,000원 | 5,000원×2건=10,000원 가상 매출. 아직 상품·결제 경로·구매 없음 | 직접 만든 질문/기록 양식 / 실제 상대는 미선정 / 필요한 칸 질문 작성 |

플랫폼 보너스는 계획 수입에 넣지 않았다. 브랜드나 동료에게 연락하지 않았다.

기획 시트는 실제로 작성됐다. 이 이름이 키트 기본값에 자동 반영되는 것은 아니다. 생성 파일의 `account_name`은 여전히 ‘하린의 한 장 실험실’인 것을 확인했다(F09).

## 5장 · 소재·권리·출처

- 다룰 질문 / 원문: 참가자가 어떤 책을 읽는가 / 위 합성 피드 첫 item.
- 핵심 사실: 모임을 준비한다는 가상 설정, 참가자가 읽고 싶은 책을 직접 고른다는 가상 설정. 날짜·모집 인원·성과를 추가하지 않음.
- 이용 근거: 동봉 코드·합성 피드의 MIT 범위와 동봉 폰트 OFL 고지를 확인. 외부 기사 사진·음악·인물 없음.
- 출처 문구: ‘합성 데이터 · 실제 뉴스 아님 / 동봉 합성 피드, 가상 별빛도서관 / https://example.invalid/library’. 링크는 실제 기관 주소가 아님.
- 실제 게시용 소재: 미선정. 별도의 한 항목 XML은 기사 수에 따른 생성 장수만 검증하는 로컬 명령 시험 자료다. 실제 뉴스·권리 확보·원격 게시 성공으로 세지 않음.

## 6장 · 지시문과 대조

실습 3의 prompt 명령으로 `output/first-post/prompt.md`를 만들었다. 웹 채팅에는 보내지 않고 허용된 오프라인 직접 편집 경로를 택했다.

> 퇴근 뒤 읽을거리를 찾는 동료에게 설명합니다. 동봉 합성 자료만 사용하고 없는 날짜·가격·효과를 만들지 마세요. title·body·points·subtitle을 쉬운 문장으로 바꾸고 원출처·합성 표시·JSON 구조는 유지하세요.

바꾼 필드: 표지 title, 첫 본문 title·body·points·subtitle. 표지는 ‘도서관 모임에서는 무엇을 읽나요?’, 첫 본문은 ‘읽고 싶은 책을 직접 골라요’로 수정했다. body와 points를 함께 맞췄고 구조 검증을 통과했다.

보존한 것: synthetic=true, label, source URL, 나머지 장면, caption의 합성 고지, is_ai_generated=false. 숫자·인명·부정·조건을 원자료와 비교했다. 다른 장면의 합성 이야기 세 개를 실제 도서관 사실로 합치지 않았다.

## 7장 · 카드 역할·자산

- 표지: 질문을 큰 글씨로 제시.
- 본문 1: 참가자가 책을 직접 고른다는 답. body·points 동시 수정.
- 본문 2·3: 나머지 합성 소식은 연습용 원자료를 유지.
- 마지막 행동: 저장·공유 안내와 원출처. 실제 홍보·구매를 요청하지 않음.
- 자산 기록: 동봉 Noto Sans KR, `assets/fonts/README.md`·`OFL.txt` 확인, 외부 사진 없음, 자체 기하 무늬, 음원 없음.
- 실제 결과: `output/first-post/cards/`의 PNG 5개 및 JPEG 5개, 1080×1350. 원본과 JPEG를 모두 열어 한글·출처·합성 고지·순서를 확인.

| 장면 | 보여 줄 것 / subtitle | 시간 | 음성 조건 |
| --- | --- | --- | --- |
| 1 | 표지 질문 / 합성 피드로 카드와 릴스를 만드는 연습입니다. | 0~4초 | 무음 |
| 2 | 책 선택 답 / 읽고 싶은 책은 참가자가 직접 골라요. | 4~8초 | 무음 |

| 4 | 산책 지도 합성 소식 / 원래 가상 제목 | 12~16초 | 무음 |

실제 `reel.mp4`를 Chromium에서 끝까지 재생하고 2·6·10·14·18초의 화면도 확인했다. FFmpeg의 무음 트랙 최대/평균은 -91dB였다. TTS·녹음·배경음악은 선택하지 않았다. 합성 표시를 실제적인 AI 목소리 표시로 오해하지 않았고, 영상 제작을 수익화 자격으로 세지 않았다.

## 9장 · 파이프라인과 실패 대응

생성 → REVIEW.md 대기 → 파일/원문/권리/표시 확인 → 검수표 저장 → approve → dry-run.json 순서로 실행했다. 영상과 모든 PNG/JPEG·캡션을 확인한 후 여섯 칸을 편집해 저장했다.

실패 대응 메모: JSON 구조 오류는 수정 후 검증, 카드 넘침은 points·body 수정 후 render, 음성 파일이 없으면 null/무음, 게시 응답 유실은 원격 게시 확인 전 재실행 보류. 이 실행에서는 live 요청을 하지 않았다.

외부 호출비: offline을 선택했으므로 새 유료 호출 0건. 인건비·전기·통신의 실제 비용은 계산하지 않았다. 타 서비스의 사용량이나 월 비용을 실제 지출로 만들지 않았다.

## 10장 · 게시 경로와 예약 확인

- 고른 경로: 향후 첫 게시를 한다면 앱 수동 게시. 현재 검토에서는 외부 작업 미실행.
- 대상 계정: 없음. 토큰·ID도 입력하지 않음.
- 시각·시간대: 향후 계획은 한국 시간으로 메모. 실제 예약 없음.
- 필수 표시: 현재 파일은 합성 연습임을 확인. 실제 기사처럼 게시 금지. 협찬/제휴 관계 없음.
- 실패 시 확인할 곳: 대상 계정 프로필·게시물 주소·예약됨·원격 미디어 상태.
- 요청 미리보기: `APPROVED.json`과 `dry-run.json` 생성. `hosting/first-post/`에 JPEG 5개·MP4 1개만 준비. 공개 업로드는 하지 않음.
- 예약 생성 파이프라인 설정: **없음.** 앱의 완성 파일 예약에 대한 안내를 이 설정이라고 적지 않음.

## 12장 · 검수·대응·증빙

- 자료·허용 범위: 동봉 합성 피드, 자체 렌더링, 폰트 고지 확인. 실제 뉴스 없음.
- 제공 관계·표시: 돈·제품 제공·제휴 없음. 현재 연습 파일의 합성 고지는 유지.
- AI 유형: 외부 생성 AI·합성 음성 미사용, 규칙 기반 초안과 직접 편집. 영상 기본 무음.
- 오류 대응: 게시/예약을 멈추고 원자료와 대조, 바꾸면 render·새 검수·승인.
- 계정 복구 준비: 계정 없음. 실제 독자는 인증앱·백업 코드를 준비해야 함. 코드나 토큰을 이 문서에 적지 않음.
- 수입·지출 증빙: 거래 없음. 실제 입금·등록·신고를 했다고 쓰지 않음.

## 13장 · 첫 제안과 거래 수

- 도울 독자: 퇴근 독서·모임 조건을 알고 싶은 동료.
- 샘플 주소: 로컬 `output/first-post/cards/`. 공개 샘플 URL 없음.
- 제안할 브랜드: 미선정. 실제 브랜드에 연락하지 않음.
- 제작 범위: 가상 카드 한 세트, 수정 한 번, 광고 재사용 범위는 협의 항목.
- 내 가상 제안액 / 비용: 건당 100,000원 / 월 100,000원 가정.
- 목표 계산: (세금 전 목표 300,000원+가상 비용 100,000원)÷100,000원=4건. 실제 주문 0건과 혼동하지 않음.
- 오늘 할 일: 먼저 단일 독자 질문의 샘플로 다시 묶을 준비. 반복 DM이나 실제 판매는 하지 않음.

## 14장 · 완료·미완료와 주간 점검

완료: 기획 시트, 문안 편집·구조 검증, 합성 PNG/JPEG·MP4, 검수·승인·드라이런, 호스팅용 파일 준비.

미완료: 실제 계정·실제 게시용 자료의 권리 확인·휴대폰 전송·게시·예약·관찰. 예약 생성→검수→업로드 설정은 책만으로 완성할 수 없음.

주간 점검일: 아래 가상 계획의 5·12·19·26일. 매번 권리 보류, 실제 제작 시간, 독자 질문, 수입·지출, 계속/축소/중단 이유를 확인할 계획이다. 아직 실행한 주간 점검이 아니다.

## 30일 운영 계획

도구 입력은 2026-10-27 시작·하루 30분·7일 중 5일이다. 도구의 배분대로 매 7일의 앞 5일을 활동일로 삼으면 22일×30분=660분, 점검 220분을 뺀 제작 예산은 440분이다. **다음 표는 도구가 만든 일정이 아니라 작업실 지시를 보고 별도 작성한 계획**이다. 각 활동일은 점검 10분+작업 20분이며, 실제 시간·완료는 진행한 다음에 적는다. 이 일정은 납기나 실제 게시를 보장하지 않는다.
