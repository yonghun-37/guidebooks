# A5r 심화편 독립 검토 — 발견 사항

2026-10-26 · Codex · Python 기초만 아는 초보 개발자 역할로 검토.

**결론: mock 학습은 가능하지만, 이 심화편만으로 초보자가 거의 손대지 않는 실운영을 구축하기에는 수정이 필요하다.**

- 원본 `auto-kit/`을 `/tmp/a5r-review-kln23lkj/` 아래 README용·인스타용·쇼츠용으로 각각 복사했다. 기존 private·가상환경·캐시는 제외했다. Python **3.11.15**, 새 venv, README의 바이너리 설치 명령으로 준비했다.

- Chromium에서 **22페이지 × 3폭(1280/375/360) × 2테마 = 132화면**을 확인했다. 가로 넘침·깨진 이미지·JS 실행 오류 0, 본문 내부 링크/앵커 **504개 오류 0**. 비용 극단값, 관문 분기, 두 책 체크 저장·삭제, 샘플 영상 재생도 확인했다.
- 실제 키·유료 API·실계정·메신저 전송·R2/Actions 원격 실행은 사용하지 않았다. Windows/macOS 실기기는 미실행이다. 외부 공식 문서는 읽기만 했다. Meta 시작 문서 직접 열람은 429로 실패했으므로 실제 콘솔 발급 성공으로 기록하지 않는다.

## 차단

### F01 [차단] [인스타·키트] 필수 공개 호스팅을 실제로 연결하는 절차가 끊긴다

- **위치:** [인스타 A5 ‘URL은 파일 자체가 열려야 해요’](../../site/advanced/05-publish.html#build), [실제 연결](../../site/advanced/05-publish.html#live), `auto-kit/README.md` 5절, `config.example.json`의 `hosting`.
- **학습자의 말:** “R2나 Pages를 고르라는 건 알겠어요. 그런데 버킷과 토큰은 어디서 만들고, 화면의 어느 값을 설정 파일 어디에 옮기나요?”
- **확인:** 본문과 README는 선택지·조건을 설명하지만 완성된 설정 예와 발급값 대응표가 없다. R2에는 `adapter/base_url/r2_bucket/r2_endpoint`와 두 비밀 값이 필요하다. Pages에는 저장소·브랜치·배포 설정·토큰 권한이 필요하다. 시작 문서 링크만으로 Python 초보가 이 키트 설정을 완성해야 한다. `local`은 live에서 거절되므로 인스타에서는 생략할 수 없다.
- **고치는 방법:** **인스타** A5에 R2 한 경로를 끝까지 따라 하는 절차와 비밀 없는 완성 JSON을 넣는다. 버킷 생성 → 공개 주소 연결 → R2 자격 발급 → 각 설정/`.env` 필드 → 로그인 없는 파일 GET 성공을 한 예로 잇는다. **키트** README도 같은 예를 가리킨다. Pages는 대안으로 두되 필요한 권한과 브랜치 배포 조건을 명시한다. **쇼츠**는 게시용 공개 호스팅이 불필요하다는 현재 구분을 유지한다.
- **보완 근거:** 직접 읽은 [R2 시작 안내](https://developers.cloudflare.com/r2/get-started/)와 [R2 인증 안내](https://developers.cloudflare.com/r2/api/tokens/)는 가입·자격 발급·Access Key ID/Secret·S3 endpoint를 각각 설명한다. 이 값과 키트 필드를 연결하는 단계가 책에 필요하다. 원격 업로드 실패를 재현한 주장은 아니다.

### F02 [차단] [쇼츠·키트] 권장 음성의 키를 어디서 발급하는지 알 수 없다

- **위치:** [쇼츠 A2](../../site-shorts/advanced/02-credentials.html#build), [A3 ‘처음엔 Luna와 WaveNet’](../../site-shorts/advanced/03-generation.html#providers), `auto-kit/README.md` 4절.
- **학습자의 말:** “`GOOGLE_TTS_API_KEY`에 뭘 넣나요? 유튜브 OAuth 파일인가요, AI Studio의 Gemini 키인가요? 음성 서비스를 켜는 단계도 있나요?”
- **확인:** 권장 경로는 Google WaveNet인데, 책은 키 이름과 모델 이름을 알려 준 뒤 ‘본인이 넣으세요’로 넘어간다. Google Cloud TTS 프로젝트·API 활성화·결제 연결·자격 발급/제한을 이 키트의 인증 방식과 연결하지 않는다. YouTube OAuth는 상세하게 설명하므로 둘을 같은 인증으로 오해하기도 쉽다. doctor는 키의 존재만 검사하고 발급 경로를 해결하지 않는다.
- **고치는 방법:** **쇼츠** A2/A3에 Cloud TTS 준비를 YouTube OAuth·Gemini와 구별해 설명한다. 현재 어댑터의 `x-goog-api-key` 방식과 맞는 발급·제한 절차를 공식 근거로 확인해 한 경로로 확정하고, `.env` 입력과 짧은 음성 생성 성공까지 잇는다. **키트**도 그 절차를 링크한다. **인스타**는 선택 릴스 음성 연결에서 같은 절차를 참조한다. 본인 녹음을 선택할 때 매일 새 대본의 녹음도 새로 필요하다는 점을 구분한다.
- **보완 근거:** 직접 읽은 [Cloud TTS 시작 안내](https://docs.cloud.google.com/text-to-speech/docs/get-started)는 프로젝트·결제·API 활성화·인증을 요구한다. [인증 안내](https://docs.cloud.google.com/text-to-speech/docs/authentication)와 [Cloud API 키 관리](https://docs.cloud.google.com/docs/authentication/api-keys)까지 대조해 키트와 일치하는 절차를 써야 한다. 실제 키의 성공/실패는 시험하지 않았다.

### F03 [차단] [쇼츠] 일부 Windows 명령이 기본 인코딩에 따라 실패한다

- **위치:** [쇼츠 A3 실행 명령](../../site-shorts/advanced/03-generation.html#try), [A5 실행 명령](../../site-shorts/advanced/05-youtube.html#try), [A6 실행 명령](../../site-shorts/advanced/06-gates.html#try)의 `Path(...).read_text()`.
- **학습자의 말:** “Windows 명령을 그대로 복사했는데 한글 JSON을 못 읽는다는 오류가 나요. Python 설치부터 잘못한 건가요?”
- **재현:** UTF-8인 새 `draft.json`을 CP949로 읽으면 `UnicodeDecodeError: 'cp949' codec can't decode byte 0xec in position 14`가 발생했다. Linux에서도 `LC_ALL=C PYTHONUTF8=0 PYTHONCOERCECLOCALE=0`으로 **본문 A3 명령 그대로** 실행하면 ASCII 디코딩 오류와 exit 1이 발생했다. `encoding='utf-8'`을 지정하면 제목과 장면 수를 읽는다.
- **범위:** Windows 실기기 재현은 아니다. UTF-8 모드를 켜지 않은 비 UTF-8 기본 인코딩의 Python 3.11에서 발생하는 조건부 차단이다. [Python 3.11 공식 설명](https://docs.python.org/3.11/library/io.html#text-encoding)도 Windows의 기본 인코딩과 UTF-8 파일을 구분한다.
- **고치는 방법:** **쇼츠** 세 장의 모든 JSON 읽기 명령에 `encoding='utf-8'` 또는 키트와 같은 `utf-8-sig`를 명시한다. **키트**의 `common.read_json`은 이미 인코딩을 지정하므로 본문 명령을 그 방식과 맞춘다. **인스타**의 A4 명령은 이미 명시되어 있다.

### F04 [차단] [쇼츠·공용 키트] README 뒤에 쇼츠를 읽으면 인스타 결과를 집는다

- **위치:** [쇼츠 A3](../../site-shorts/advanced/03-generation.html#try), [A5](../../site-shorts/advanced/05-youtube.html#try), [A6](../../site-shorts/advanced/06-gates.html#try)의 `next(Path('private/state').glob('*/...'))`; `auto-kit/README.md` 2절.
- **학습자의 말:** “README대로 카드와 쇼츠를 둘 다 만들었어요. 그런데 쇼츠 장에서 지원금 카드 제목이 나오고, 다음에는 `metadata`가 없대요.”
- **재현:** README 순서대로 insta → shorts를 같은 기본 상태에 실행했다. 그 뒤 A3의 명령은 `청년 지원금, 신청 전 확인할 3가지`와 `5`를 출력했다. A5의 명령은 `dry-run 0` 다음에 **`KeyError: 'metadata'`, exit 1**로 끝났다. `glob`의 첫 파일은 ‘이번 쇼츠 실행’이라는 보장이 없다. 각 책만 깨끗하게 시작하면 이 문제는 드러나지 않는다.
- **고치는 방법:** **쇼츠**는 A0에서 얻은 쇼츠 ID를 A3~A6에서도 직접 넣어 `private/state/RUN_ID/...`를 읽게 한다. 새 `--state`로 반복 연습했다면 그 경로도 계속 사용하도록 잇는다. **인스타·키트** 공통 안내에 두 흐름의 ID/상태를 구별하는 예를 둔다. 첫 파일 또는 가장 최신 파일이라는 추정으로 선택하지 않는다.

## 혼란

### F05 [혼란] [키트] 실패를 복구했는데 성공 출력에 옛 오류가 남는다

- **위치:** `auto-kit/pipeline.py`의 `resume` 성공 처리와 CLI 출력, 두 책 A1의 재개 안내.
- **학습자의 말:** “`dry_run`인데 바로 아래에 ‘파일 처리 실패’가 있어요. 고쳐진 건가요, 아직 실패인가요?”
- **재현:** 없는 폰트 경로로 run → `failed`를 만든 뒤 해당 경로에 폰트를 복구하고 같은 ID를 resume했다. 실제 렌더와 관문은 완료됐고 원문·대본은 유지됐다. 그러나 출력은 다음과 같았다.

```text
fa7548df8f65 · insta · dry_run
파일 처리 실패. 경로·권한을 확인하세요.
```

- **원인/고치는 방법:** **키트**는 성공 시 현재 실패 사유 `reason`과 `failed_step`을 정리하고 과거 실패는 로그에 남긴다. 현재 구현은 성공 상태만 바꾸고 옛 사유를 유지한다. **두 책**은 복구 성공 시 출력·상태·파일이 어떻게 보여야 하는지 그 결과와 맞춘다.

### F06 [혼란] [두 책·키트] 고친 예외를 대기열에서 끝내는 실습이 없다

- **위치:** 두 책 [인스타 A6](../../site/advanced/06-gates.html#run)·[쇼츠 A6](../../site-shorts/advanced/06-gates.html#try), 전자동 전환의 ‘미해결 예외 0건’, `ops/report.py`.
- **학습자의 말:** “문제를 고쳐 새 실행은 성공했는데 예외가 계속 1개예요. 0건이 되려면 DB를 지워야 하나요?”
- **재현:** 인스타 민감 단어에 `신청`, 쇼츠에는 `월세`를 추가해 각각 실제 `exception`을 만들었다. approve는 거절됐고 resume도 예외를 유지했다. 설정을 복구한 **새 실행은 성공했지만 report에는 옛 예외 ID가 남았다**. 옛 ID를 `reject`하자 `exceptions: []`가 됐다. 본문 실습은 정상 실행과 단위 테스트 위주여서 이 정리 순서를 가르치지 않는다.
- **고치는 방법:** **두 책** A6에 테스트 설정 → exception → reasons 확인 → approve 거절 → 원인 수정·새 실행 → 폐기할 옛 실행 `reject` → report 0건을 한 번 따라 하게 한다. **키트** README에 `reject`가 미게시 예외를 종결하고 기록을 보존한다는 뜻을 설명한다. 원격 결과가 불명인 실행을 같은 방식으로 정리하도록 안내하지 않는다.

### F07 [혼란] [인스타·키트] 사후 확인 2시간의 시작점이 본문과 다르다

- **위치:** [인스타 A7 타임라인](../../site/advanced/07-operations.html#visual-daily-timeline), 인스타 A0/A1의 대기 설명, `pipeline.py`의 `run`.
- **학습자의 말:** “검사가 끝난 뒤 2시간 동안 볼 수 있다고 이해했는데, 제작에 쓴 시간까지 대기 시간에서 빠지나요?”
- **확인:** 인스타 그림은 09:17 시작 → 09:20 관문 완료 → **11:20 공개 예정** → 11:32 tick을 제시한다. 실제 키트는 run 시작 때 `publish_at = now() + review.hours`를 저장한다. 실습 기록도 시작 `10:49:21.783630Z`, 예정 `12:49:21.783656Z`였다. 쇼츠 A7은 **시작부터 2시간**이라고 정확히 설명한다.
- **고치는 방법:** **인스타**를 현재 구현에 맞춰 시작 기준으로 고치고 제작 시간이 검토 여유를 줄인다는 점을 설명한다. 또는 **키트**를 관문 완료 기준으로 바꿀 의도라면 두 플랫폼의 동작·승인 묶음·예약 테스트를 함께 맞춘다. 책만 서로 다른 시계를 설명하지 않게 한다.

### F08 [혼란] [두 책·키트] 메신저 자격을 만드는 곳과 수신 운영이 빠져 있다

- **위치:** [인스타 A7 알림](../../site/advanced/07-operations.html#build), [쇼츠 A7 알림](../../site-shorts/advanced/07-operations.html#alerts), README 7절.
- **학습자의 말:** “웹훅 URL, 봇 토큰, chat ID, allowed user는 각각 어디서 얻나요? 버튼을 누르려면 25초짜리 명령을 매번 켜야 하나요?”
- **확인:** 전송·승인 권한의 구분은 좋다. 하지만 Discord 웹훅 생성, Telegram 봇 생성과 사용자/채팅 ID 조회, `.env` 필드 대응을 따라 할 수 없다. `telegram --live`는 한 번 polling 후 끝나며 OS 예약 생성기는 tick만 호출한다. 지속적으로 버튼 응답을 받을 운영 방식도 정해야 한다.
- **고치는 방법:** **두 책**은 기본 알림 한 경로의 발급 → `.env` → 시험 알림 → 예외 이유 확인을 완성한다. 휴대폰 승인을 선택할 때만 별도로 봇·ID 조회와 polling 실행 주체/주기를 안내한다. **키트**는 실제 지원하는 방식과 명령을 README에 명시한다. Discord 알림만으로 승인을 받을 수 없다는 현재 설명은 유지한다.

### F09 [혼란] [인스타·키트] 토큰을 새로 넣어도 저장된 옛 토큰이 우선한다

- **위치:** [인스타 A2 만료 오류 안내](../../site/advanced/02-keys.html#success), [A9 키 교체](../../site/advanced/09-safety.html#build), README 10절, `ops/tokens.py:10`.
- **학습자의 말:** “재인증해서 `.env`를 바꿨는데 계속 만료라고 나와요. 발급을 잘못했나요?”
- **재현:** 임시 private 파일에 **가짜 만료 토큰**을 저장하고 환경변수에는 가짜 새 토큰·미래 만료일을 넣었다. 원격 옵션 없이 doctor를 실행해도 `Instagram 토큰 만료. 재인증하세요.`가 남았다. 옛 private 파일을 백업 위치로 옮긴 뒤 같은 검사에서는 그 오류가 사라졌다. 토큰 값은 출력하지 않았다.
- **고치는 방법:** **인스타**에 `.env/Secrets`와 `ops.instagram_token_file`의 우선순위, 재인증·키 회전 때 실제로 교체할 저장 위치를 명시한다. **키트**도 새 자격을 안전하게 적용하는 한 절차를 제공한다. A2의 ‘private 파일이 쓰일 수 있다’는 설명만으로는 만료 후 복구를 수행하기 어렵다.

### F10 [혼란] [쇼츠·키트] 보유 소재 경로는 매일 장면 수가 같다는 보장이 없다

- **위치:** [쇼츠 A3 권장 조합](../../site-shorts/advanced/03-generation.html#providers), [A4 장면 준비](../../site-shorts/advanced/04-render.html#build), `providers/adapters.py`, `rendering/media.py:63`.
- **학습자의 말:** “사진 5장을 넣어 두면 매일 돌 줄 알았어요. 모델이 오늘 3장면을 쓰면 제가 폴더를 매번 고쳐야 하나요?”
- **재현:** 소재 5개를 준비하고 스키마에 맞는 3장면 원문을 mock으로 실행했다. `failed`, `소재 파일 수와 장면 수를 맞추세요. 파일명 순서로 사용합니다.`, exit 2가 됐다. 실제 LLM 요청도 장면을 **2~5개**로 지시한다. 본문은 수가 바뀌면 맞추라고 하므로 무인 운영의 빈틈을 독자에게 넘긴다.
- **고치는 방법:** **쇼츠**는 보유 소재를 쓰는 무인 경로에서 장면 수를 어떻게 고정/대응할지 구체적으로 정한다. **키트**는 선택한 소재 수와 생성 장면 수를 일치시키는 최소 기능을 제공하거나, 현재 자동 운영 가능한 다른 구성을 명확히 권한다. ‘소재 폴더를 넣었다’와 ‘매일 수작업 없이 조립된다’를 구분한다. 인스타에서 같은 소재 옵션을 사용할 때도 적용된다.

### F11 [혼란] [두 책] 같은 전자동 전환을 다른 기준으로 설명한다

- **위치:** 인스타 [A6 전환 그림](../../site/advanced/06-gates.html#build)·E2E, 쇼츠 [A0 전환표](../../site-shorts/advanced/00-overview.html#build)·A6.
- **학습자의 말:** “둘 다 같은 키트를 쓰는데 다음 10편 모두 통과인가요, 최근 20편 중 19편인가요?”
- **확인:** 승인제 진입 기준 9/10은 같지만 다음 단계는 인스타 **10/10·거부/오류 0**, 쇼츠 **19/20·잘못 공개 0**이다. 두 책 모두 편집 권장값이라고 표시했으므로 플랫폼 정책의 모순은 아니다. 다르게 운영할 이유와 ‘미해결 예외’ 집계·종결 방법이 연결되지 않는다.
- **고치는 방법:** **두 책**에서 공통 연습 기준을 맞추거나 플랫폼별 차이를 의도한 이유와 집계 예를 쓴다. **키트**가 자동으로 승격시키지 않는다는 설명은 유지한다. 플랫폼의 안전 보장 수치로 바꾸지 않는다.

### F12 [혼란] [두 책·질문표] 장 주제와 학습자 질문의 대응이 어긋난다

- **위치:** `docs/learner-questions-advanced.md` A6/A7, [인스타 A6 FAQ](../../site/advanced/06-gates.html#faq), [A8 FAQ 4](../../site/advanced/08-insights.html#faq), [쇼츠 A6 FAQ](../../site-shorts/advanced/06-gates.html#faq).
- **학습자의 말:** “품질 검사 장을 읽었는데 자주 묻는 질문은 예약 지연·절전·메신저 얘기예요. 왜 제 플랫폼에서 필요한 질문 대신 다른 책 질문이 반복되나요?”
- **확인:** 질문표의 A6는 일정·승인·복구, 설계와 실제 A6는 품질 관문이다. 인스타는 옛 일정 FAQ를 그대로 유지하고, 쇼츠는 관문 FAQ로 바꿔 질문표와 달라졌다. 인스타 A8의 YouTube views/engagedViews 질문도 ‘서로 다르다’고만 해 각각 무엇인지 직답하지 않는다. STYLE-GUIDE 5절의 질문별 엄격 채점을 그대로 적용할 기준이 일치하지 않는다.
- **고치는 방법:** **질문표**를 설계의 A6 관문/A7 운영에 맞춰 플랫폼별로 대응시킨다. **인스타** A6는 실제 예외 생성·오탐·처리·종결 질문으로 바꾸고, 운영 질문은 A7로 연결한다. **쇼츠**는 현재 관문 질문을 질문표에 반영한다. 다른 플랫폼 질문은 실제 정의·예·할 일을 주거나 정확한 상대 책 절로 연결한다.

### F13 [혼란] [두 책] ‘무료 모델로 매일 가능한가’에는 아직 직답이 부족하다

- **위치:** 인스타 [A3 FAQ 3](../../site/advanced/03-generate.html#faq), 쇼츠 [A3 FAQ 3](../../site-shorts/advanced/03-generation.html#faq).
- **학습자의 말:** “무료로 실제 한국어 파이프라인을 돌릴 수 있는지 물었는데, mock은 무료이고 나머지는 확인하라는 답만 들었어요.”
- **확인:** 관련 무료 등급·발음 조건 설명은 있다. 그러나 실제 무료 운영의 가능 범위와 선택할 모델/확인 위치/최소 시험이 한 답으로 연결되지 않는다. 키트는 무료량이 있어도 유료 단가로 비용 예약을 하므로 ‘API 청구 0’과 ‘키트 예약비 0’도 다르다.
- **고치는 방법:** **두 책**에 조사 기준으로 가능한 무료 구성의 범위, 무료가 보장되지 않는 단계, 현재 모델의 무료 등급·한도·데이터 조건을 확인할 정확한 위치를 한 예로 묶는다. 확인하지 못한 범위는 그 사실과 다음 행동을 직답한다. **키트**의 보수적 비용 예약이 무료량을 자동 차감하지 않는다는 설명도 연결한다. 새 무료 한도 수치를 임의로 만들지 않는다.

### F14 [혼란] [쇼츠 중심·인스타 릴스] 기술 샘플과 게시할 만한 완성 견본 사이가 비어 있다

- **위치:** [쇼츠 A4 실제 MP4](../../site-shorts/advanced/04-render.html#build), [인스타 A4 릴스](../../site/advanced/04-render.html#build), `auto-kit/samples/`.
- **학습자의 말:** “주제는 만들어 보고 싶어요. 그런데 도형과 신호음 다음에 어떤 완성도를 목표로 해야 할지, 낭독과 자막이 잘 맞는 예는 아직 못 봤어요.”
- **확인:** 월급날 네 칸·생활 뉴스 소재는 STYLE-GUIDE 7절 방향에 맞고 두 책 안에서 이어진다. 실제 렌더 프레임도 보여 준다. 다만 동봉 영상은 연습용 도형·신호음이어서 낭독 속도·강조·장면과 말의 관계를 배우는 완성 견본이 아니다. 신호음이라는 고지는 정확하다. 공개용 완성 예의 품질까지 검증한 것으로 점수 줄 수는 없다.
- **고치는 방법:** **쇼츠**는 같은 대본에 본인 녹음 등 추가 API 결제 없는 낭독·권리 확인 소재를 붙인 완성 견본 한 편과 필요한 설정을 제공한다. **인스타** 릴스도 같은 방식으로 최종 목표를 보여 준다. **키트**의 키 없는 기능 시험 샘플은 유지하되 두 샘플의 목적을 구분한다. 새로운 API·편집 도구를 필수로 늘릴 필요는 없다.
