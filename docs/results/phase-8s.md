# Phase 8s · 이론편 문체·구성 샘플 3안

상태: **샘플 작성·작성자 검증 완료, Claude Code/사용자 구성 선택 대기**. 2026-10-26. 요구사항은 [작업 지시](../prompts/phase-8s.md), 편집 기준은 [문체 초안](../style-guide.md)을 따른다. 책 전체 개편이나 기존 3장 교체를 완료한 것이 아니다.

## 문제와 구현

기존 3장은 지급자·대가·장부와 근거의 한계를 먼저 설명해 “무엇을 하면 얼마를 버나”라는 질문의 답이 늦었다. 같은 사실을 서로 다른 읽기 순서로 비교할 수 있게 만들었다.

- [x] **A 수익 축 정의형** — 조회수 보상·광고/협찬·제휴·내 상품/서비스. 각 축에 정의·돈의 흐름·조건/시작 시점·숫자·행동, 끝에 팔로워 단계표. 축별 계산기 하나.
- [x] **B 질문 답변형** — 조회수·팔로워·협찬·AI·쿠팡·선물·구독/상품·쇼츠·틱톡·세금의 질문 10개. 직답·이유·숫자·행동, 질문 선택 답 카드 하나.
- [x] **C 성장 단계형** — 하린 0→500→1천→1만→10만, 정 선배 대화·조건·공개 계산식·가상 월수입표·할 일, 단계 슬라이더 하나. 1만 명 장면에서 수입이 전 단계보다 줄어들도록 해 팔로워와 자동 수입의 혼동을 줄였다.
- [x] 비교 페이지에 장점·단점·대상 독자·책 전체 적용 시 변화·현재 3장 링크 제공.
- [x] 1~14장 실제 원고의 질문 5개씩 총 70개를 판정. **답함 41 / 부분 29 / 안 함 0**. 관련 설명의 존재와 직답·예시 부족을 구별했다. 원고별 SHA256과 근거 앵커를 보존했다.

사이트 산출물은 **`site/drafts/` 새 파일 6개뿐**이다. HTML 4개와 전용 CSS/JS를 만들고 `../assets/book.css`를 링크한다. 공통 `book.js`를 불러오지 않아 기존 목차·진도·실습 동작에 연결되지 않는다. 기존 페이지 주소와 공통 CSS/JS는 수정하지 않았다. 실습편·키트도 이번 작업에서 변경하지 않았다.

## 사실 보강과 판단

[보강 노트](../../research/monetization-explainer.md)에 URL·게시/갱신일·접근일·본문 확인 범위를 남겼다. `SOURCES.md`에 **S196~S202(총 202개)**, `FACT-SHEET.md`에 **EXPL-01~08**을 추가했다. 기존 META·REV·XPLAT·TAX 기록은 지우지 않았다. 기존 FACT-SHEET에는 MON-* 대신 REV-*가 있다.

- 쿠팡의 새 공식 공개 PDF에서 **별도 요율이 없는 상품의 기본 3%**를 직접 확인했다. 24시간·자가 구매 제외·취소/반품·상품별 예외도 읽었다. 2026년 실시간 전체 요율표를 검증했다는 뜻은 아니다.
- 국내 태그바이 공개 안내에서 팔로워 구간별 보상 범위를 확보했다. 1천~1만의 1~10만 원은 **현금이 아닌 제공 제품 가격**이다. 사업자 참고 안내를 한국 전체 평균으로 쓰지 않았다.
- Shorts는 음악 비용 반영 후 풀→유효 조회 배분→배분금 45% 구조와 YPP 광고 기준을 공식 본문에서 다시 읽었다. AIR의 공개 국가평균 RPM은 **2025년 표**로 구분했다.
- 선물은 **받은 Stars 1,000개=$10**으로 썼다. 선물 1,000개와 혼동하지 않는다. Gifts 500명·구독 1만 명의 기존 보고는 2026년 신뢰 사업자 자료와 일치하지만 공식 도움말 본문 재확인은 차단됐다.
- TikTok은 2026년 한국 공지의 1만 명·1분 조건과 2025년 일한 약관의 5만 명 차이를 끝 확인 상자에 남겼다. 고정 RPM을 만들지 않았다.

**요구 예시에서 조정한 점:** “한국에는 조회수 기반 지급이 없다”를 전면 종료 사실로 입증하지 못했다. 따라서 모든 안의 직답은 **“보너스 초대 없는 한국 새 계정은 100만 조회만으로 받을 돈이 0원”**으로 한정했다. 과거 한국 초대형 보너스와 2026년 2차 자료를 확인했으나 현재 신규 초대·전면 종료는 미확인이다. 사실보다 강한 결론을 문체 개선 명목으로 쓰지 않았다.

## 검증

실행 환경: Linux·실제 Chromium. 로그인·결제·실제 게시·유료 API 호출 없음.

```sh
python3 -m http.server 8528 --bind 127.0.0.1 --directory site
python3 docs/results/phase-8s/static_check.py
node docs/results/phase-8s/verify.mjs
```

브라우저 스크립트의 Playwright/Chromium 경로는 이 환경의 기존 설치를 사용한다. 다른 환경에서는 경로를 맞춰야 한다. 저장소 의존성은 추가하지 않았다.

- **385개 브라우저 검사 통과**: HTML 4개×1280/375px. 문서·개별 요소 가로 넘침 0, 콘솔/페이지 오류 0, 실패 네트워크 요청 0. 외부 폰트를 모킹하지 않고 로딩 완료 후 촬영했다.
- A 계약/구매/상품 산수·상품별 요율 변경·빈칸·음수·100% 초과·0건, B 질문 10개, C 단계 5개와 방향키, 퀴즈 키보드, 저장 차단 시 메시지와 계산 동작을 확인했다.
- **내부 링크·자산·문서 근거 255개** 존재/앵커 검사 통과. 외부 Meta 원문은 접근 제한을 연구 노트에 따로 기록했으며 전부 접근 성공했다고 주장하지 않는다.
- 샘플마다 9블록·시뮬레이터 1개·확인 문제 3개. HTML 텍스트 길이(각주 포함, CSS/JS 제외): 현재 3장 **9,844자**, A **6,259자**, B **8,012자**, C **6,380자**. 모두 짧다.
- 작업 중 보존 스냅샷 **기존 site 파일 75개**의 해시 변화 0. 원래 작업 트리의 수정 파일은 보존했다. 초기 아이콘 자동 요청 404는 샘플의 빈 favicon 선언으로 수정한 후 전 검사를 다시 통과했다.

## 남은 일과 제한

- 세 안 중 본문에 적용할 구성 선택과 Claude Code 검수. 책 전체 개편은 실행하지 않았다.
- 한국 Gifts/구독 활성화·지급, Instagram 보너스 현행 한국 운영, 쿠팡 실시간 상품별 요율, TikTok 공지/약관 적용 차이는 여전히 확인이 필요하다.
- 70개 질문 판정은 작성자 검토이며 독립 초보자 실험이 아니다. 다른 작업자가 원고를 바꾸면 기록한 SHA256 기준과 달라질 수 있다.
- 공통 구조나 배포 방식의 변경이 없어 새 ADR·architecture 문서를 만들지 않았다. 기존 단계 결과·문체 초안·질문표를 feature 기록으로 재사용했다. commit·push·배포를 하지 않았다.
