# Phase 9c · 공통 파일 통합 요청

10~14장과 전용 JS만 수정했다. 공통 파일·부록·연구·PROJECT_STATE·진행 현황은 변경하지 않았다. 아래는 통합 작업자가 적용할 요청이며 **현재 적용된 변경이 아니다**.

## 실험실·출처 통합

- 활성 계산기는 `analytics-v2.js`의 `analytics-sim`, `roadmap-v2.js`의 `roadmap-sim`, `plan-v2.js`의 `planner-sim` 세 개다. 새 출력은 각각 비율·목표 거래 수·30일 제작 시간이다.
- `publishing.js`·`safety.js`·`analytics.js`·`roadmap.js`·`plan.js`는 파일을 그대로 남기고 장의 연결만 끊었다. 옛 도구·그림·각주를 포함한 기존 앵커 313개를 보존했다. 제거된 도구의 `?embed=publishing-sim`·`?embed=safety-sim`도 현재 대응 연습 절로 열린다.
- `catalog.js`·`lab.html`의 옛 도구명·개수를 갱신해야 한다. 통합 시 `scripts/build_appendices.py`의 catalog/lab 부분을 재생성하되, 전체 실행은 다른 장·용어집·출처에도 쓰므로 담당 작업자가 변경 범위를 확인해야 한다.
- `planner-sim`의 `plan-start`·`plan-minutes`·`plan-days`와 기존 저장 방식은 유지했다. 실험실의 한 달 요약으로 새 시간 결과가 전달되는 것을 확인했다. 날짜는 기록용이며 복사 가능한 전체 자동 캘린더는 이제 생성하지 않는다. 직접 옮길 단계표·메모를 본문에 둔다.
- 이 장들이 인용한 신규 S번호를 `credits.html`에 통합할 때, 내부 사실 ID가 학습자 화면에 다시 나타나지 않게 한다. 새 각주는 `source-s###`를 사용하며 이전 `source-사실ID` 앵커도 남겼다.

## 상태 인계

PROJECT_STATE의 개편 완료 범위에 10~14장·결과 [phase-9c.md](phase-9c.md)를 추가하고, 도구 개수·14장 결과물·옛 설명을 통합 결과로 갱신해 주세요. 이 단계는 작성자 검증 완료이며 독립 초보자 검수·실계정 앱 검증·Claude Code 검수·커밋은 완료로 표시하지 않습니다.
