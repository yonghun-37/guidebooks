# Phase B3k 결과 — blog-kit

완료: 2026-10-26. 분류: 기능 구현(Level 2). 구현·검증 범위는 `blog-kit/`과 이 결과 문서다. `docs/DESIGN-blog.md` 8·11절(11절 우선), B2 결과·조사 노트, STYLE-GUIDE 7절을 따랐다.

## 문제·요구사항과 구현 전략

블로그 초보자가 유료 API·외부 패키지 없이 자료 정리부터 발행 요청 미리보기까지 완주할 독립 키트가 필요했다. 표준 라이브러리와 JSON 설정으로 구현하고, AI 서비스는 복사할 프롬프트 생성만 지원한다. 사람 작성·원문 대조·승인을 단계 사이에 둔다. 공식 발행 API가 가능한 Blogger와 설치형 WordPress만 선택 연결하고 기본 상태를 초안으로 고정한다.

## 구현 결과

- `brief.py`: 키워드·정보/후기/경험·플랫폼·로컬 메모 → 프롬프트 7종 Markdown. 과제·독자·자료/근거·제약·출력 형식·검수 기준을 각 요청에 포함한다. 실제 사용·관찰과 공식 사양을 구분하며 경험·제도·숫자·출처 생성 금지를 명시한다.
- `check.py`, `config.example.json`: 제목 길이·제목/소제목 구조·본문 글자 수·이미지 alt·제휴 표시·숫자 문장의 출처/관찰 메모·반복 문장·상투 표현·내 경험 문단을 점검한다. 수정 후보와 줄 번호를 사람이 읽는 리포트로 출력한다. 기준값은 변경 가능한 키트 기본값으로 적고, 광고 표시·이미지 설명 원칙의 조사 근거는 `rule_basis`로 분리했다. 공정위의 ‘제목 또는 첫 부분’을 법적 근거로 설명하고 키트는 본문 첫 문단을 검사한다. `--affiliate`로 짧은 링크 탐지 누락을 보완한다. 기본 종료 0 / `--strict` 수정 후보 2 / 파일·설정 오류 1이다.
- `markdown_tools.py`, `render.py`: 제목·문단·평면 목록·인용·단순 표·코드·강조·링크·이미지 → `editor.html`과 모바일 폭 `preview.html`. 원시 HTML은 글자로 표시하고 위험한 URL 방식을 거절한다. 로컬 이미지는 초안 폴더 안에서만 읽어 출력의 `assets/`로 복사한다. 코드·주석의 이미지 예시는 파일로 읽지 않는다.
- `review.py`: 원문/리포트·경험·권리/AI·광고 관계·미리보기의 다섯 검수 항목을 사람이 채운 뒤 해시 승인을 기록한다. 재변환은 체크와 승인을 초기화한다. 초안·HTML·이미지·리포트·설정·검수표가 승인 후 달라지면 발행을 차단한다.
- `publish.py`: 기본 네트워크·인증 파일 접근 0회의 드라이런. Blogger `isDraft=true`, 설치형 WordPress `status=draft`만 제공한다. live는 사람 승인과 사용자가 직접 준비한 `.env`, 본인 OAuth 액세스 토큰/인증 JSON 또는 애플리케이션 비밀번호가 있어야 한다. 환경변수가 `.env`보다 우선하며 토큰 파일을 지정하면 해당 토큰을 사용한다. 인증값·응답 전문을 출력/저장하지 않고 결과 ID와 초안 상태만 기록한다. 리다이렉트·자동 재전송을 금지하고, 전송 전 배타적으로 만든 `LIVE_ATTEMPT.json`을 실패 후에도 유지한다. 가상 샘플·로컬 이미지의 live를 차단한다.
- 네이버·티스토리는 편집기에 붙여 넣는 안내만 제공한다. WordPress.com의 별도 OAuth는 구현 대상에서 제외했다. API 초안 저장 뒤 실제 공개는 사용자가 관리 화면에서 확인하고 직접 한다. 이는 B2 채택 범위 내의 최소 구현이다.
- `daily.py`: 날짜별 프롬프트·유형별 초안 틀·자료/출처/경험/권리/AI/광고/공개 URL 메모를 만든 뒤 사람 작성 대기에서 종료한다. `--resume`은 생성 당시 설정으로 검사·HTML 변환까지만 한다. 날짜 중복 생성 거부와 선택 로그를 제공한다.
- `schedule_setup.py`: 기존 키트의 현지 시각·날짜 폴더·중복 보호·인자 검증 방식을 재사용했다. Windows 작업 스케줄러와 macOS/Linux cron의 등록·확인·수동 실행·삭제 명령만 출력한다. 실제 예약 등록·무인 승인·발행은 하지 않는다.
- 한국어 `README.md`: 터미널·경로·가상환경·Markdown·토큰 설명, Windows/macOS 명령, 명령별 ‘이렇게 보이면 성공’, 수동 발행·선택 live·복구·예약 안내를 작성했다. 실행 의존성은 없으며 개발 테스트용 `requirements-dev.txt`만 추가했다. `.env`, `auth/`, 토큰 파일, 개인 설정·실제 출력은 `.gitignore` 대상이다.

## 대표 예시와 동봉 출력

가상 블로그 **‘퇴근 후 생활 정보’**의 **‘청년 직장인 지원 제도, 신청 전에 어디부터 볼까’**를 기획→프롬프트→검사→HTML 예시로 이어 썼다. 인스타의 ‘출근길 3분 생활 뉴스’와 같은 생활 정보 주제이며 실제 제도명·금액·성과·브랜드를 지어내지 않는다. 수아의 경험은 가상 편집 연습이라고 본문에 표시했다.

`blog-kit/samples/`에 원본 글·직접 그린 SVG·프롬프트를, `samples/rendered/`에 복사된 초안·이미지·HTML·리포트·미승인 검수표·변환 기록을 동봉했다. 승인·인증 파일은 없다. 샘플 검사 결과는 제목 **27자**, 본문 **1,369자**, 자동 수정 후보 **0개**다. 실제 사실·경험 검증이나 발행 승인을 뜻하지 않는다.

## 검증

- Linux / **Python 3.10.12**. `/tmp/shorts-final-tools/bin/python -m pytest blog-kit/tests -ra`: **97 passed**. 이미 있던 개발 환경의 pytest를 사용했다. 시스템 패키지·신규 의존성 설치는 없었다.
- 테스트 중 소켓 연결을 차단한다. 전체 오프라인 흐름, 세 유형 프롬프트, 각 검사 규칙·기준값 변경·빈 출처/부정형 광고 문구, HTML/URL 처리·로컬 이미지·코드 예시, 승인 전/후 변경 차단, 무인 발행 차단, 두 API 드라이런·발행 모킹·HTTP/타임아웃/잘못된 응답·재전송 거부·비밀값 비노출, 설정·날짜·예약 명령을 확인했다.
- 깨끗한 임시 복사본의 새 가상환경에서 README 기본 명령 **23개**를 실행했다. 프롬프트·strict 검사·변환·사람 체크를 모사한 승인·Blogger/WordPress 드라이런·두 수동 경로·일일 시작/재개·세 OS 예약 안내·각 CLI 도움말이 성공했다. `sitecustomize`로 이 복사본의 모든 Python 네트워크 연결을 차단했다. POSIX 명령 실행 검증이며 Windows/macOS 실기기 성공을 뜻하지 않는다.
- Chromium에서 동봉 미리보기를 `file://`로 열어 **1280·375·360px**의 가로 넘침 0, 이미지 로딩·대체 텍스트·제목, 콘솔/페이지 오류 0을 확인했다. 360px 전체 화면을 직접 읽어 글과 순서도를 확인했다. 미리보기에는 외부 요청이 없었다.
- `python3 -m compileall -q blog-kit`, `git diff --check` 통과. `.env`, `auth/token.json`, 실제 출력 경로가 Git 제외 대상임을 `git check-ignore`로 확인했다.
- Blogger insert·posts 리소스·시작 안내, WordPress Posts/애플리케이션 비밀번호, 공정위 현행 지침을 공식 원문으로 추가 확인했다. 근거 연결은 `research-blog/07-api-automation.md`, `08-policy-copyright.md`, `ai-production-blog.md`의 B010~B014·B037·BL-API·BL-LAW·BL-AI를 따른다.

## 한계·통합 요청

- 실제 계정 인증·토큰 발급/갱신·API 저장·공개 발행, Windows/macOS 예약 등록·다음 날 실행·절전/권한은 미실행이다. 이 단계는 오프라인·모킹 검증 완료이며 실게시 성공 기록이 아니다.
- 검사는 문자열·구조를 보는 편집 보조다. 광고 관계와 문구의 진실성, 숫자 출처의 정확성·적용 범위, 경험 진위, 이미지/인용 권리는 사람이 판단한다. 제휴 링크 탐지는 누락·오탐이 있고 한 줄의 출처가 해당 줄 모든 숫자를 설명하는지도 사람이 확인해야 한다.
- 렌더러는 README에 적은 Markdown 부분집합이다. 플랫폼 편집기에서 사진을 다시 올리고 제목·서식·대체 텍스트를 확인해야 한다. OAuth 발급/갱신, 이미지 API 업로드, 공개/예약 발행 자동화는 포함하지 않았다.
- live 결과가 불명확하면 기록을 삭제해 재시도하지 말고 서버 글 목록과 ID부터 확인한다. 중복 방지는 같은 출력 폴더를 기준으로 한다.
- **통합 담당자 요청:** 사이트 실습에서 키트 명령은 README 경로와 맞추고, `brief → 사람 작성 → daily --resume → 사람 검수/승인 → 드라이런 → 선택 초안 저장 → 관리 화면 공개 확인`으로 연결한다. `docs/PROJECT_STATE.md`·서가 진행표 갱신은 통합 담당자가 이 결과를 반영한다. 병렬 소유 규칙과 이번 사용자 범위에 따라 이 작업에서는 두 문서를 수정하지 않았다.
- `site-blog/`, `starter-kit/`, `shorts-kit/`, `site/`, `site-shorts/` 및 기존 사용자 변경을 수정하지 않았다. commit/push는 하지 않았다.

완료 알림은 `python3 scripts/notify.py "✅ [blog-kit 완료] ..."`로 전송했고 HTTP 200 응답을 확인했다.
