# Instagram 실습 1~10 절차 근거 노트

작성: 2026-10-26, Codex. **2026년 10월 조사 기준**, 컷오프 2026-10-26. Phase 7r 조사 편집본이며 Hermes 원응답이 아니다. `site/`·`starter-kit/`을 수정하거나 실제 계정에 로그인·게시하지 않았다.

**판정: API·파일 전송·호스팅의 문서 근거는 확보했지만, 오늘의 한국 앱 화면을 끝까지 검증한 게시 매뉴얼은 아니다.** 앱 게시를 핵심 경로로 유지하되 아래 `미확인` 메뉴를 검증된 안내로 집필하면 안 된다. Phase 7w의 집필 재료와 확인 공백을 함께 제공한다. 실계정 성공 검증은 조건부 Phase 7v의 범위다.

## 읽는 법·조사 기록

- **본문 확인**: Codex가 공식 URL을 직접 열고 해당 절을 읽었다. 기기 화면이나 실행 성공을 확인했다는 뜻은 아니다.
- **메타데이터만**: 제목·소개는 읽었지만 절차 본문은 수신하지 못했다. 버튼 위치의 근거로 사용하지 않는다.
- **기존 Hermes 근거**: 이전 조사 원응답의 확인 범위다. 이번 직접 확인과 구분한다.
- **미확인**: 공식 본문 또는 적용 범위를 확인하지 못했다. 아래에 적힌 메뉴 탐색 후보도 확정 절차가 아니다.
- **로컬 문서**: 키트 README/코드 읽기 또는 교과서의 편집 제안이다. 외부 서비스의 정책·기능 근거와 구분한다.

각 S번호는 [SOURCES.md](SOURCES.md)의 공식 URL·게시/갱신일·접근일·확인 범위로 연결한다. 날짜 미상은 조사일로 대체하지 않았다. API 문서의 이번 텍스트 응답에서 갱신일은 다시 확인하지 못했으므로 기존 출처 기록의 날짜와 구분한다. PRAC 번호는 [FACT-SHEET.md](FACT-SHEET.md)의 주장 단위다.

Hermes는 초기 6회와 좁은 보충 2회, 합계 **8회/상한 8회**, 최대 동시 4회, 각 `--max-turns 40`으로 실행했다. 8회 모두 exit 0이나 웹 중계 `search.parallel.ai` 연결의 403으로 공식 본문·검색 근거 확보에 실패했다. 이를 Meta 원서버 차단 또는 한국 미지원으로 해석하지 않는다. Codex는 별도 HTTP/web 경로로 **공식 문서 22개의 관련 본문**을 직접 읽었다.

- 외부 RUN: `/home/yonghun/project/hermes-research/output/ai-insta-research-20261026/`
- 질의: `queries/practice-{account,app-publish,transfer-hosting,api-setup-token,api-media-version,schedule-insights}.txt`와 `practice-app-publish-supplement.txt`, `practice-api-setup-token-supplement.txt`.
- 원응답: 같은 이름의 `raw/practice-*.md`. 원응답은 수정하지 않고 공개 저장소에도 넣지 않았다.
- [실행·해시 기록](provenance-phase-7r.json), [직접 확인·제한 기록](verification-phase-7r.json).

## 실습 2. 키트 설치와 첫 실행

이 절은 외부 UI 재조사 대상이 아니라 **현재 로컬 키트 계약의 연결 노트**다(PRAC-25). 설치/OS별 재실행 검증을 이번에 하지 않았다. 근거는 [README](../starter-kit/README.md)의 1~3절이다. 7w 작업자가 바꾸면 해당 README와 다시 맞춰야 한다.

1. 저장소 ZIP을 풀고 터미널에서 `starter-kit` 폴더로 이동한다. `run_pipeline.py`가 보여야 한다. **로컬 문서 확인**.
2. Python 3.11 이상인지 확인한다. Windows cmd는 `py -3.11 -m venv .venv`, macOS/Linux는 `python3 -m venv .venv`로 가상환경을 만든다. 활성화는 각각 `.venv\Scripts\activate.bat`, `source .venv/bin/activate`다. **로컬 문서 확인**, 다른 OS에서 실행 성공 미검증.
3. `python -m pip install --cache-dir .cache/pip -r requirements.txt`를 실행한다. 설치만 인터넷이 필요하다는 키트 안내를 따른다. **로컬 문서 확인**.
4. `python run_pipeline.py --offline`으로 첫 결과를 만든다. `output/실행날짜/REVIEW.md`에서 검수 대기로 끝나는 것이 기대 결과다. **로컬 문서 확인**, 실제 실행 안 함.

**막힐 때:** `PIL/yaml/imageio_ffmpeg` 모듈 오류는 가상환경/설치를, 출력 폴더 중복은 `--output output/second-practice`를 점검한다. 합성 피드를 실제 뉴스로 게시하지 않는다. 이 절에서 계정·키·결제를 추가할 필요는 없다.

## 실습 3. 오늘 소재·문안·웹 채팅 붙여넣기

준비물은 이용 조건을 확인한 원자료와 현재 `copy.json` 구조다. **로컬 문서 확인/편집 제안**이며 특정 웹 서비스의 현재 버튼·무료량을 새로 보장하지 않는다. [README의 LLM 연결](../starter-kit/README.md), [LAW-08·AI-07](FACT-SHEET.md), PRAC-25를 따른다.

1. 원자료의 제목·날짜·URL·핵심 사실·재사용 허락을 기록한다. 전체 기사·사진을 무단으로 복사하는 단계로 만들지 않는다. **기존 권리 근거/편집 제안**, [S010](SOURCES.md#s010).
2. 키트의 `llm.mode: prompt` 경로로 `news.json`, `config.json`, `prompt.md`를 만든다. 문안 대기에서 멈추는 것이 현재 계약이다. **로컬 문서 확인**.
3. 본인이 이용할 수 있는 웹 채팅에 `prompt.md`를 붙여넣고, 수정 작업이면 현재 `copy.json`도 함께 제공한다. 반환된 전체 JSON만 `copy.json`에 저장한다. **편집 제안/로컬 계약**. 서비스별 로그인·붙여넣기·응답 버튼의 오늘 화면은 이번 범위에서 미확인.
4. `python write_copy.py 출력폴더/news.json --validate --output 출력폴더/copy.json`으로 구조를 검사한다. 인명·날짜·수치·부정·조건은 원문과 사람이 대조한다. 구조 검사는 사실 검증이 아니다. **로컬 문서 확인**.

**막힐 때:** JSON 앞뒤의 코드 울타리·설명을 제거하고 필수 필드/원출처 링크를 보존한다. 무료 웹 한도가 걸렸다고 유료 API를 자동으로 대체하지 않는다.

## 실습 4. 뉴스카드 캐러셀 파일 준비

준비물은 검증한 `copy.json`과 사용 권리가 있는 이미지/폰트다. **로컬 문서 확인**, [README](../starter-kit/README.md); 외부 규격은 PRAC-08·10과 [S004](SOURCES.md#s004), [S068](SOURCES.md#s068).

1. 키트 `python run_pipeline.py render 출력폴더`로 카드를 만든다. `cards/card-01.png`부터 표지→본문→마무리 순으로 직접 연다. **로컬 문서 확인**.
2. 잘린 문장·작은 글자·잘못된 출처·합성 자료 표시를 고치고 다시 렌더링한다. 기대 결과는 휴대폰에서 읽히는 카드다. **편집 제안**, 대비/자막의 기존 근거 [S121](SOURCES.md#s121), [S122](SOURCES.md#s122).
3. API 게시에는 대응하는 `.jpg`를 사용한다. **본문 확인:** JPEG·최대 8MB·비율 4:5~1.91:1·너비 320~1440px. 키트의 1080×1350은 제작 선택이며 유일한 Instagram 규격이 아니다. [S004](SOURCES.md#s004)
4. 이미지와 동영상을 섞을지 결정한다. **API 본문 확인:** 합계 최대20개, 첫 이미지 기준 크롭 주의. 앱은 같은 혼합·20개를 메타 설명/기존 Hermes에서 확인했으나 이번 편집·선택 화면은 미확인이다. [S001](SOURCES.md#s001), [S004](SOURCES.md#s004), [S068](SOURCES.md#s068)

**막힐 때:** API에 PNG를 그대로 넣거나 앱의 3:4 지원을 API까지 확대하지 않는다. 앱 혼합 캐러셀에서 항목별 비율이 달라지는 정확한 현행 동작은 미확인이므로 게시 전 미리보기에서 전부 점검한다.

## 실습 5. 본인 녹음 릴스 파일 준비

준비물은 완성 카드·대본·본인 음성과 필요한 경우 권리를 확인한 배경음악이다. **로컬 문서 확인**, [README의 영상·음성](../starter-kit/README.md), PRAC-25.

1. 대본을 본인이 읽어 녹음하고 키트가 안내하는 `reel.narration`에 파일을 지정한다. 특정 휴대폰 녹음 앱의 현재 버튼은 조사하지 않았다. **로컬 계약/녹음 UI 미확인**.
2. `render` 후 `reel.mp4`를 처음부터 끝까지 재생한다. 내레이션·자막·장면 전환·배경음악을 실제로 듣고 본다. 기본 설정은 무음+자막이므로 소리가 없다는 이유만으로 실패로 보지 않는다. **로컬 문서 확인**.
3. API 규격을 별도 점검한다. **본문 확인:** MOV/MP4, H.264/HEVC, 23~60fps, 3초~15분·최대300MB, 9:16 권장. 앱 촬영 상한·추천 길이와 다르다. [S004](SOURCES.md#s004)
4. 사진/영상 혼합 캐러셀의 동영상과 독립 릴스를 구분한다. API 캐러셀 자식은 `media_type=VIDEO`이며 `REELS`를 자식으로 넣는 것이 아니다. **본문 확인**, [S004](SOURCES.md#s004), PRAC-10.

**막힐 때:** 이번 S066 재요청은 본문 없이 최대3분이라는 메타 설명만 반환했다. 과거 Hermes의 본문20분과 상충하므로 앱 길이 상한을 확정하지 않는다(PRAC-21). 20초는 현재 키트의 학습 샘플이며 플랫폼 의무 길이가 아니다. 라이선스 없는 음악을 넣어 해결하지 않는다.

## 실습 6. 게시 전 검수와 라벨 결정

목표는 파일·사실·권리·표시를 사람이 확인하는 것이다. [현재 키트 검수](../starter-kit/README.md) 및 기존 [LABEL·LAW·TAX 사실](FACT-SHEET.md)을 함께 본다. 이번에는 법령을 새로 재조사한 것이 아니며 개별 콘텐츠의 적법성을 판정하지 않는다.

1. 카드와 영상을 모두 열고 원문 대조·출처·권리·음원·오해를 부르는 실제 장면 표현을 확인한다. **편집 제안/기존 근거**, [S010](SOURCES.md#s010), [S121](SOURCES.md#s121).
2. 실사형 합성 영상·사실적으로 들리는 합성 음성 등을 썼다면 AI 자기공개 필요성을 검토한다. AI 글쓰기 보조와 같은 조건으로 일괄 판정하지 않는다. **기존 공식 발표 근거**, [S071](SOURCES.md#s071). 앱 토글 위치는 실습7의 미확인 항목이다.
3. 현금·무료 제공 등 경제적 이해관계가 있으면 국내 표시 기준과 플랫폼 라벨을 각각 확인한다. 유료 파트너십 라벨과 광고 집행 허락은 구분한다. **기존 법령 근거**, [S008](SOURCES.md#s008). 앱의 자격·승인 순서는 미확인이다.
4. 로컬 `REVIEW.md`를 실제로 확인한 뒤 체크하고 `python run_pipeline.py approve 출력폴더`로 승인한다. 변경 뒤에는 렌더링·검수를 다시 한다. **로컬 문서 확인**, PRAC-25.

**화면이 다를 때:** 라벨이 없다는 이유로 필요 없다고 결론내리지 않는다. 필요한 표시를 확인할 수 없는 콘텐츠는 게시 준비 단계에 남긴다. 캡션에 설명을 쓰는 것이 플랫폼 라벨 의무의 대체라는 근거는 없다(PRAC-22).

## 실습 7. 앱으로 첫 게시하기 — 핵심 경로

### 7-A. PC 파일을 휴대폰에 저장

아래는 **공식 본문 확인** 절차다. 실제 기기 전송은 하지 않았으며 메뉴의 한국어는 이해를 위한 병기다(PRAC-17~19).

1. **Windows→Android USB**: 잠금을 풀고 데이터 전송 가능한 USB 케이블로 연결 → 휴대폰의 `USB로 이 기기 충전 중 / Charging this device via USB` 알림 → `USB 사용 / Use USB for`에서 `파일 전송 / File Transfer` → PC 전송 창에서 JPEG/MP4를 복사 → Windows에서 꺼내고 케이블을 뺀다. 기대 결과는 휴대폰에 원본 파일이 있는 상태다. 일부 단계는 Android14 이상이라는 조건을 함께 표시한다. [S194](SOURCES.md#s194)
2. **Drive→iPhone 사진 보관함**: PC에서 본인 Drive로 파일을 올린 뒤 휴대폰 Drive 앱에서 대상 파일 옆 `더보기 / More(⋯)` → `사본 보내기 / Send a copy` → `이미지 저장 / Save image` 또는 `동영상 저장 / Save video`. 기대 결과는 사진 앱에서 파일을 여는 것이다. PC의 업로드 클릭 순서는 이번에 재확인하지 않았고 위 다운로드 단계는 확인했다. [S193](SOURCES.md#s193)
3. **Mac→iPhone AirDrop 대안**: 두 기기의 Wi-Fi/Bluetooth·수신 허용을 확인 → Mac 파일의 `공유 / Share` → `AirDrop` → 본인 기기 선택 → 필요하면 수신 기기 `수락 / Accept`. Finder의 AirDrop에 파일을 끌어놓는 방법도 있다. 같은 Apple Account이면 자동 수신할 수 있다. 파일이 Photos/Files 중 어디에 저장됐는지 직접 확인한다. 최신 안내의26.2 이후 코드 화면은 표시되는 경우 문서에 따라 진행한다. [S192](SOURCES.md#s192)

**흔한 문제:** USB 충전만 되는 경우 데이터 케이블/연결 모드를 점검한다. Drive의 `Open in > Save to Files`는 사진 보관함 저장과 다르다. AirDrop 미표시 시 Wi-Fi/Bluetooth/수신 대상을 확인한다. 제조사 갤러리의 인덱싱·사진 접근 권한 화면과 메신저의 압축 여부는 이번 조사에서 미확인이므로 전송 뒤 크기·재생·화질을 직접 비교한다. Drive 공유 미리보기 URL은 API용 파일 URL로 간주하지 않는다.

### 7-C. AI 정보·유료 파트너십 표시

1. **AI 표시:** 게시 최종 설정 화면에서 `AI 라벨 추가 / Add AI label`, `AI 정보 / AI info`에 해당하는 항목을 찾는다. 별도 `더 많은 옵션 / More options` 또는 `고급 설정 / Advanced settings` 안에 있는지는 **미확인**이다. [S183](SOURCES.md#s183)은 공유 전 AI 표시라는 소개만 확인했다. [S007](SOURCES.md#s007)의 표시 설명은 토글 위치 근거가 아니다.
2. **협찬 표시:** `파트너십 레이블 및 광고 / Partnership label & ads`, `유료 파트너십 레이블 추가 / Add paid partnership label`, 브랜드 파트너 선택/요청은 **탐색 후보이며 미확인**이다. [S184](SOURCES.md#s184)의 본문은 열지 못했다. 브랜드 승인·계정 자격·부스팅 허용을 같은 동작으로 단정하지 않는다.
3. **게시 후 수정:** 게시물 `⋯` → `수정 / Edit`에 관련 토글이 있는지의 현재 경로·지원 여부도 **미확인**이다. 게시 후 고칠 수 있다고 가정하지 말고 게시 전에 필요한 설정을 확인한다.
4. **표시가 안 보일 때:** 앱 도움말에서 기능을 검색하고 OS·앱 버전·계정 유형과 누락 메뉴를 기록한다. 필요한 AI/광고 라벨을 못 켰다면 해당 콘텐츠를 미완료로 남긴다. 캡션만 추가해 해결됐다고 쓰지 않는다. 사실적 AI 인물의 계정 단위 라벨은 게시물 AI 정보와 별도이며 이번에 재검증하지 않았다.

한국어 메뉴명은 화면을 직접 읽은 번역이 아니다. iOS·Android·한국 계정별 배포 차이는 미확인이다. 공개 URL·개발자 앱·토큰을 앱 수동 게시의 선행 조건으로 넣지 않는다.

## 실습 8. 선택 심화: Instagram Login API 게시

이 절은 **문서상 설정·호출 절차**다. 실제 로그인·토큰 발급·업로드·`--live`를 실행하지 않았다. 계정 역할·검수·일반 공개 범위가 서로 다른 조건이므로 오늘의 공개 게시 완료는 실습7을 우선한다.

### 8-A. 앱·역할·계정·토큰

1. Meta 개발자 등록 요건을 갖춘 본인 계정으로 [App Dashboard](https://developers.facebook.com/apps)에 들어가 `Create App`을 누른다. **문서 본문 확인**, [S176](SOURCES.md#s176). 개발자 가입/인증 마법사의 오늘 화면은 미확인이다.
2. 문서의 생성 흐름은 `Other` → `Next` → `Business` → `Next` → 앱 이름·연락 이메일 → `Next`다. `Instagram` 제품의 `Set up`을 누르면 `API setup with Instagram login`이 추가된다. **본문 확인**, [S176](SOURCES.md#s176). 현재 화면에 다른 use case 마법사가 나오면 이 순서를 강요하지 않고 제품/API setup의 존재를 확인한다.
3. `Instagram > API setup with Instagram login`의 토큰 생성 영역에 공개 Instagram 계정을 추가한다. 문서는 Instagram 로그인 안내가 나온다고 설명한다. 계정 추가/제거는 `App Roles > Roles` 또는 API setup에서 한다. **본문 확인**, [S176](SOURCES.md#s176).
4. 본인의 Administrator/Developer/Tester 역할과 대상 Instagram 계정 연결을 확인한다. 역할 초대 수락이 필요한 경우 **Instagram의 현행 수락 메뉴는 미확인**이다. S179의 Facebook `Settings > Apps and Websites > Requests > Accept`를 Instagram 메뉴로 베끼지 않는다. [S179](SOURCES.md#s179)
5. 본인 소유·관리 계정은 `Standard Access`, 외부 고객 계정 서비스는 `Advanced Access`·앱 검수라는 문서 구분을 적용한다. **본문 확인**, [S031](SOURCES.md#s031), [S030](SOURCES.md#s030). 개발 모드 역할 사용자 테스트는 이 문서 조합상 가능하지만 실게시 성공은 검증하지 않았다. 공통 App Modes는 테스트 게시물의 비역할 사용자 비노출을 안내하고 앱 생성 Step10은 live data 검수를 요구한다. **일반 독자 공개를 검수 면제만으로 보장할 수 없다.** [S178](SOURCES.md#s178), [S176](SOURCES.md#s176), PRAC-02·03.
6. 대시보드 `Instagram > API setup with Instagram business login` → 해당 계정의 `Generate token` → Instagram 로그인 → 토큰 복사. **본문 확인**, [S177](SOURCES.md#s177). 두 공식 페이지에서 `with Instagram login`과 `with Instagram business login` 표기가 다르므로 같은 항목인지 실제 화면에서 확인한다. 토큰은 본인의 비공개 실행 환경에만 둔다.
7. 대시보드 토큰은 **60일 장기**, Business Login OAuth는 **1시간 단기**다. OAuth 단기 토큰의 장기 교환은 서버에서 `GET https://graph.instagram.com/access_token`에 `grant_type=ig_exchange_token`, `client_secret`, `access_token`을 전달한다. 앱 시크릿을 브라우저/공개 파일에 넣지 않는다. **본문 확인**, [S177](SOURCES.md#s177), [S030](SOURCES.md#s030).
8. `GET https://graph.instagram.com/v26.0/me?fields=user_id,username`에 토큰을 인증으로 전달해 본인 대상 계정 ID와 이름을 확인한다. **본문 확인**, [S177](SOURCES.md#s177). **현재 Graph API 버전은 v26.0, 2026-07-29 출시**, [S174](SOURCES.md#s174), [S175](SOURCES.md#s175). 토큰/시크릿을 터미널 기록·스크린샷·Git에 노출하지 않는다.
9. 장기 토큰은 발급24시간 이후·만료 전에 `GET https://graph.instagram.com/refresh_access_token`에 `grant_type=ig_refresh_token`, `access_token`을 전달하면 다시60일 갱신할 수 있다. 만료 토큰은 갱신할 수 없으므로 다시 인증한다. **본문 확인**, [S030](SOURCES.md#s030). 실제 `expires_in`과 취소/권한 상태도 확인하며 Facebook Page 토큰 수명과 섞지 않는다.

**화면이 다를 때/흔한 오류:** Instagram 제품이 없으면 앱 유형/생성 use case부터 확인한다. 권한 오류는 대상 계정 연결·초대 수락·로그인 경로·토큰 대상·`instagram_business_basic`, `instagram_business_content_publish` 동의를 점검한다. 검수 페이지 일부의 `*_publishing` 표기는 제품/게시 문서의 `*_publish`와 불일치하므로 전자를 새 scope로 복사하지 않는다. 원인을 확인하기 전 Live 전환·불필요한 전체 권한 요청을 해결책으로 추가하지 않는다.

### 8-B. 무료 공개 URL 호스팅 후보와 실제 파일 확인

**이미지:** `image_url` 필수이며 Meta가 공개 서버에서 JPEG를 가져온다. **Instagram Login 릴스:** 공개 `video_url` 경로를 사용한다. 로그인 필요한 Drive 미리보기·로컬 `C:\...`/`localhost`는 이 조건을 충족하지 않는다. **본문 확인**, [S004](SOURCES.md#s004), [S001](SOURCES.md#s001), PRAC-08·09.

[S186](SOURCES.md#s186), [S188](SOURCES.md#s188). R2의 `r2.dev`는 개발용·rate limit이며 운영은 사용자 도메인 등 조건을 별도 검토해야 한다. 무료량은 무과금 상한 잠금을 뜻하지 않는다. [S189](SOURCES.md#s189), [S190](SOURCES.md#s190)

URL 확인은 다음 **운영 점검 제안**이며 호스팅 서비스의 Meta 인증 보장이 아니다.

1. 시크릿 창에서 로그인 없이 해당 JPEG/MP4 자체를 열거나 다운로드한다. 오류/미리보기 HTML이면 파일 URL부터 수정한다.
2. HTTP 응답·리다이렉트 최종 URL·`Content-Type`이 파일과 맞는지 확인한다. `curl -I -L '실제 공개 파일 URL'`은 헤더 점검이고 GET 파일 수신의 대체는 아니므로 실제 파일도 열어 본다.
3. 서명 URL 만료·공유 권한·봇 차단·hotlink 제한 때문에 Meta가 읽지 못할 수 있다. 브라우저 성공만으로 Meta 성공을 단정하지 않는다.
4. 키트는 현재 `--public-base-url` 아래 `cards/card-01.jpg` 등과 `reel.mp4`를 찾는다. `cards/` 경로를 빠뜨리거나 raw URL 하나를 base로 쓰지 않는다. 파일별/폴더 경로 제공 가능 여부를 먼저 맞춘다. **로컬 코드 확인**, [publish.py](../starter-kit/publish.py).
5. 공개 폴더에 `.env`·설정·토큰·내부 검수 파일을 올리지 않고 배포에 필요한 미디어만 둔다. 업로드/게시 처리 전에 파일을 지우거나 바꾸지 않는다. 유지 기간의 공식 보장값은 이번에 확정하지 않았다.

### 8-C. 미디어 생성→처리 확인→발행

아래는 **현재 공식 본문 확인**이며 실제 호출하지 않았다. [S001](SOURCES.md#s001), [S004](SOURCES.md#s004), PRAC-08~13.

1. 이미지: `POST https://graph.instagram.com/v26.0/{IG_ID}/media`에 `image_url`과 필요한 `caption`을 전달한다. 응답 `id`는 컨테이너 ID이며 게시 완료가 아니다.
2. 릴스: 같은 `/media`에 `media_type=REELS`, 공개 `video_url`, 필요한 `caption`을 전달한다. 본문 규격을 충족한 파일을 사용한다.
3. 혼합 캐러셀: 각 이미지에 `image_url`, 각 영상에 `media_type=VIDEO`, `video_url`, 공통 `is_carousel_item=true`로 자식 컨테이너를 만든다. 자식 상태를 확인한 뒤 부모에 `media_type=CAROUSEL`, 순서대로 `children`, `caption`을 전달한다. 합계 최대20개를 본문에서 확인했으며 예전10개 발췌와 충돌한 이력은 보존한다.
4. AI 표시가 필요하면 단일/부모 컨테이너의 `is_ai_generated=true`를 설정한다. 캐러셀 자식에는 설정하지 않는다. 유료 파트너십 API 파라미터는 **Facebook Login 전용**이므로 이 Instagram Login 경로/현재 키트의 지원으로 설명하지 않는다.
5. `GET /v26.0/{CONTAINER_ID}?fields=status_code`로 `FINISHED`를 확인한다. 공식 권고는 분당1회·최대5분 확인이다. `ERROR`·`EXPIRED`·`IN_PROGRESS`는 게시 성공이 아니다. 5분 이후 무한 자동 재시도를 공식 권고로 만들지 않는다.
6. `POST /v26.0/{IG_ID}/media_publish`에 `creation_id={CONTAINER_ID}`를 전달한다. 응답의 게시 미디어 ID를 보관하고 게시물/`permalink`와 앱에서 결과를 확인한다. permalink 조회는 기존 미디어 레퍼런스의 필드를 사용해야 하며 이번에는 실제 조회하지 않았다.
7. 현재 키트의 `--live`는 승인·환경변수·실제 HTTPS base URL을 요구하고 캐러셀+릴스 **2개 게시 시도**를 한다. `python publish.py 출력폴더 --live --public-base-url '본인 공개 출력폴더 URL'`은 실행 경로의 설명이며 이번에 실행하지 않았다. 지원 인자는 해당 시점 `--help`와 README에서 다시 확인한다. 합성 샘플은 live 거부라는 현재 계약도 보존한다. **로컬 코드/문서 확인**.

**재개 업로드 범위:** 공식 가이드는 `upload_type=resumable`을 **Facebook Login for Business를 구현한 앱의 동영상**에 한정하며 `rupload.facebook.com`으로 로컬 바이너리 또는 공개 파일을 보낸다. 미디어 레퍼런스에는 릴스·캐러셀 동영상 자식 경로도 있다. **Instagram Login의 `rupload.instagram.com`, JPEG 바이너리 업로드 지원 근거는 없다.** 따라서 이 실습/키트의 공개 URL을 재개 업로드로 단순 대체하지 않는다. 가이드의 버전 없는 경로와 예제의 `.../ig-api-upload/{API_VERSION}/{CONTAINER_ID}`가 혼재하고 예제에 여분의 backtick도 있어 그대로 실행 가능한 문법으로 복사하지 않는다. 실제 세션 응답/공식 레퍼런스 대조가 필요하다.

**오류 점검:** URL 가져오기 실패는 공개 파일/형식/인증을, 권한 실패는 토큰·대상 계정·scope를, 처리 실패는 인코딩을, 만료는 컨테이너 생성 시각을 확인한다. 미발행 컨테이너는24시간 후 만료한다. 발행 응답이 유실되면 일부 게시가 이미 됐을 수 있으므로 앱 확인 전 전체를 재실행하지 않는다. 현재 키트의 시도 기록을 지워 중복 방지를 무력화하지 않는다. 일반 게시100/24시간과 캐러셀절50/24시간은 공식 본문 상충이며 `content_publishing_limit`의 실효값을 확인한다.

## 실습 9. 선택: 예약 게시와 자동 실행

앱/Business Suite의 **현행 클릭 경로 본문은 미확인**이다(PRAC-23). 아래는 후속 검증용 순서이며 오늘의 한국 계정에서 가능한 기능으로 보장하지 않는다.

1. **앱 후보:** 실습7의 최종 게시 설정에서 `더 많은 옵션 / More options` 또는 `고급 설정 / Advanced settings` → `이 게시물 예약 / Schedule this post`, `이 릴스 예약 / Schedule this reel`에 해당하는 항목을 찾는다. 표시되는 날짜·시간을 선택하고 최종 버튼이 `예약 / Schedule`인지 확인한다. **전 단계 미확인**, [S037](SOURCES.md#s037).
2. **앱 관리 후보:** 프로필 메뉴의 `예약된 콘텐츠 / Scheduled content`에 해당하는 항목에서 대상·예약 시각·수정/취소를 확인한다. **메뉴명·경로·지원 미확인**, [S037](SOURCES.md#s037). 30일/75일·하루25개 단편을 한국의 확정 한도로 쓰지 않는다.
3. **Business Suite 데스크톱 후보:** 본인 Instagram 프로필 연결/접속 조건을 먼저 확인 → 콘텐츠 만들기 → 게시 대상을 Instagram으로 선택 → 파일·캡션·필요한 표시 확인 → 일정 옵션에서 날짜·시간 확인 → 예약 → Planner/Content에서 수정·취소 확인. **정확한 버튼·순서·페이지 연결 조건은 미확인**, [S038](SOURCES.md#s038), [S040](SOURCES.md#s040). S039는 재요청 제목이 **모바일 앱**용으로 나와 데스크톱 순서의 근거로 쓰지 않는다.
4. **교육용 확인 항목:** 예약 저장 직후 대상 계정·현지 날짜·시간대·파일·캡션·라벨을 다시 확인하고 예약 시각 뒤 실제 게시 여부를 확인한다. 이것은 편집 제안이며 모든 도구의 시간대 처리 방식이 같다는 뜻이 아니다.
5. **Python 자동 실행:** 현재 키트가 예약 서비스·토큰 갱신·미디어 호스팅을 대신한다고 설명하지 않는다. 별도 스케줄러의 OS별 설정을 이번에 조사/구현하지 않았다. API 컨테이너24시간 만료 때문에 먼 미래용 컨테이너를 미리 만들어 두는 방식도 피한다. **본문 확인+설계 제안**, [S004](SOURCES.md#s004).

**막힐 때:** 예약 항목이 없거나 필요한 AI/협찬 라벨·음악을 함께 설정할 수 있는지 모르면 수동 앱 게시 경로로 돌아간다. 기능 부재를 개인 계정 전체/한국 전체의 비지원으로 단정하지 않는다. 이미 예약이 저장됐는지 확인하고 새 예약을 만들며, 확인 없이 중복 예약하지 않는다.

## 실습 10. 첫24시간·7일 지표 확인

24시간·7일은 **교과서의 관찰 시점**이며 Instagram이 정한 성공 판정 기한이 아니다. 앱 경로는 **미확인**, 지표 정의는 기존 공식 API 본문 근거다(PRAC-24).

1. 실습7에서 게시물 링크·대상 계정·게시 시각·포맷을 적는다. 같은 게시물을 다시 찾는 기준으로 쓴다. **편집 제안**.
2. 게시물을 열고 `인사이트 보기 / View insights`에 해당하는 항목을 찾는다. 또는 프로필의 `프로페셔널 대시보드 / Professional dashboard` → `인사이트 / Insights` 후보를 확인한다. **정확한 메뉴·날짜 필터는 미확인**, [S195](SOURCES.md#s195)은 제목/소개만 확인.
3. 첫24시간과7일에 같은 게시물의 표시된 조회·도달·저장·공유와 릴스 시청시간을 기록한다. 계정 합계/단일 게시물, 유료/자연, Instagram/Facebook 합산, 기간을 함께 적는다. **편집 제안**, 지표 구분의 기존 근거 [S110](SOURCES.md#s110), [S111](SOURCES.md#s111).
4. 조회는 반복 표시/재생을 포함할 수 있고 도달은 고유 계정 추산이므로 같은 사람 수로 비교하지 않는다. 저장·공유도 고유 사람 수로 일괄 해석하지 않는다. **기존 본문 확인**, [S110](SOURCES.md#s110), [S111](SOURCES.md#s111).
5. 값이 없으면0으로 넣지 말고 `미제공`으로 남기고 계정 유형·게시 전환 시점·지원 지표·집계 지연을 확인 항목으로 둔다. 전환 전 데이터의 현행 앱 보존 범위는 미확인이다. **API의 빈 데이터 제한은 기존 본문 확인**, [S109](SOURCES.md#s109); 앱에 동일한 기간을 임의 적용하지 않는다.

**막힐 때:** 조회0·저장0을 계정 제재의 증거로 단정하지 않는다. 평균 시청시간을 조회로 임의 나눠 재현하지 않고 화면의 단위·설명을 보존한다. 한국 초보 계정의 고정 성장 기준이나 수익 예측 수치를 추가하지 않는다.
