output/status.json의 posts 안에서 첫 조회는 id=1·status="future"인지 보세요. 이 파일의 date·date_gmt·link에서 예약 시각과 주소를 확인해요. 자세한 기록은 private/state.sqlite3에도 남아요. 기본 예약 날짜는 2026-10-28T09:00:00이에요. 마지막 명령 뒤에는 status="publish"와 link를 확인해요. --advance-days 2는 mock 시계만 앞으로 옮겨 공개 상태를 다시 조회해요. 실제 서버 시각은 바꾸지 않아요.

실제 예약은 정각 공개를 보장하지 않아요. WP-Cron은 방문 요청 때 기한이 된 작업을 실행해요. 운영 서버의 시간대를 한국 시간으로 맞추고 예약 시각 뒤 같은 조회 명령으로 status="publish"와 공개 URL을 확인하세요. 아직 future이면 스케줄러·시간대·서버 오류를 점검해요.[BX004][BX127]

mock에서 시간을 옮겨 공개 재조회하는 연습은 A9에서도 반복해요. 실제 블로그에서는 본인 HTTPS 주소·모바일 원고·그림·첫머리 표시도 열어 확인해요. 건강·협찬 글은 알림에 답이 없다는 이유로 자동 승인하지 않아요.

코드 읽기

서버 원문과 미디어가 준비한 내용과 같은지 다시 읽어 확인해요.

wordpress/integrity.py:21의 실제 발췌예요.

def verify_remote(client, row):
    """서버 원고의 내용과 분류 및 대표 미디어를 확인한다."""
    remote = client.request('GET', f"posts/{row['post_id']}?context=edit")
    expected = row['snapshot']
    for key in ('slug', 'title', 'content', 'excerpt'):
        if _raw(remote.get(key)) != expected.get(key):
            raise ValueError('서버 원고 변경 → 초안을 다시 준비하고 승인하세요')
    for key in ('categories', 'tags', 'featured_media'):
        if remote.get(key) != expected.get(key):
            raise ValueError('서버 분류 또는 미디어 변경 → 초안을 다시 준비하세요')
    for ident, expected_hash in row.get('prepared', {}).get('media_hashes', {}).items():
        if digest(client.media_bytes(int(ident))) != expected_hash:
            raise ValueError('서버 사진 변경 → 미디어를 다시 준비하고 승인하세요')
    return remote

확인할 점

실서버는 HTTPS·글/미디어 권한과 Authorization 전달을 확인하세요. 실제 예약 시각 뒤 publish 상태를 읽고 원고·미디어를 열어 봐야 공개 확인이 끝나요. Blogger를 선택하면 본인 Google Cloud 프로젝트의 OAuth·쿼터를 확인하고 광고 승인도 별도로 기록하세요. 키트의 하루 상한은 프로젝트 운영 설정이에요.[BX003][BX004][BX127][BX011]
