단계 ① · 서버 선택부터 좁혀요

단계 ① · 서버 선택부터 좁혀요

설치형 WordPress는 글·사진·분류를 REST API로 다룰 수 있어 이 과정의 기준 서버예요. REST API는 프로그램이 주소로 요청하고 응답을 받는 통로예요. 네이버 글쓰기 Open API와 티스토리 Open API는 종료됐어요. 기존 블로그에서는 공식 편집기로 이어 가세요.[BX004][BX013][BX014]

WordPress.com은 모든 유료 플랜에서 플러그인 설치를 안내하고 WordAds는 Premium 이상이에요. 설치형은 선택한 호스팅 안에서 플러그인·외부 광고 코드를 직접 관리해요.[BX008][BX009] 외부 광고는 코드 삽입 지원과 광고망 승인을 확인하고, API는 WordPress.com 전용 인증과 설치형 앱 비밀번호를 구별하세요. SSH는 서버에서 명령을 실행하는 원격 연결, FTP는 파일을 옮기는 연결, WAF는 웹 요청을 걸러 주는 방화벽이에요. Authorization 헤더는 요청에 인증 정보를 담는 칸이에요. 아래 표에서 연결 경로부터 구별하세요. OAuth는 내 계정의 특정 권한을 프로그램에 허용하는 인증 방식이에요.

싼 호스팅은 가격보다 필요한 기능부터 진단하세요. 카페24의 해당 스타트업 상품은 월 500원·설치 5,000원(VAT 포함)이에요. 코드 삽입·플러그인·REST·복구 지원은 구매 전에 확인해요. 가격만으로 코드 운영 가능 여부를 정하지 마세요.[BX015]

단계 ② · 연결 위치와 성공 증거를 구별해요

단계 ② · 연결 위치와 성공 증거를 구별해요

앱 비밀번호는 사용자 프로필에서 만들고 본래 로그인 비밀번호와 구별해요. 운영 서버는 HTTPS를 쓰세요. 메뉴가 없으면 HTTPS 인식 → 보안 플러그인 → 호스팅의 기능 제한을 확인해요.[BX003]

앱이 업데이트되면 버튼 이름이나 위치가 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 공식 도움말을 확인하세요.

.env는 비밀 설정 파일이에요. 키트 루트에 WP_USERNAME과 WP_APP_PASSWORD를 보관하고 저장소에 올리지 마세요. 사이트 주소에 비밀번호를 넣지 않아요.

실제 호스팅 · 나중에별도 폴더에 HTTPS 주소와 본인 자격 설정본인 사이트 초안 ID와 사진, 승인 후 공개 URL·서버 상태 확인.

로컬은 고정 WordPress·MariaDB 이미지로 맞추고, 실제 이전은 DB와 업로드 폴더를 함께 새 서버에 복구해요. 위 표의 태그를 유지해 키트의 로컬 설치 안내로 준비하세요. Compose용 DB 비밀은 ops/.env, REST용 비밀은 루트 .env예요. 로컬 HTTP 예외를 공용 서버에 적용하지 마세요. 실제 이전은 DB와 wp-content/uploads를 함께 복구하고 글·대표 사진·분류·주소를 대조해요. mock 상태 ZIP을 실제 DB 백업으로 쓰지 않아요.

  1. 로컬에서 DB 내보내기와 wp-content/uploads 사본을 같은 시점에 만들어요. 관리형 호스팅은 업체의 내보내기·복구 화면을 사용해요.
  2. 실제 서버의 공개 전 테스트 공간에 같은 WordPress 환경을 준비하고 DB를 가져온 뒤 uploads를 복구해요. 업체의 주소 변경 도구로 로컬 주소를 본인 HTTPS 주소로 바꿔요.
  3. 키트를 별도 폴더로 복사해 wordpress.mode="live"·본인 url을 설정하고, 새 서버에서 앱 비밀번호를 새로 발급해 그 폴더의 .env에만 넣어요.
  4. 관리자 글 목록·대표 사진·분류·글 주소와 REST 응답의 ID를 대조해요. A6의 초안 준비 → 최종 승인 → 예약 → 공개 재조회를 새 목적지에서 다시 확인해요.

DB 가져오기·주소 변경·복구 메뉴는 호스팅별 공식 안내를 사용해요. 이 선택 과제의 실서버 이전은 기본 mock 실습에 포함되지 않아요.
