output/topics.json

편집기에서 output/topics.json을 열어 as_of와 topics를 보세요. JSON은 이름과 값을 짝지어 저장하는 텍스트 형식이에요. category는 분류, age_range는 대상 월령이에요.

터미타임 글은 놀이로 분류해도 건강·안전 글로 검토해요. 키트의 play 샘플은 항상 사람 승인이 필요해요. 학습 단계에서 건강 조언을 새로 만들지 말고, 공식 안내와 적용 월령을 확인하세요.

단계 ② · 글 유형에 맞는 빈칸을 읽어요

단계 ② · 글 유형에 맞는 빈칸을 읽어요

네 가지 스키마가 글의 필수 칸을 정해요. 스키마는 JSON에 있어야 할 이름과 값의 종류를 적은 규칙이에요. 모두 author·as_of·source_notes·experience·media·contract를 가져요.

같은 구조, 다른 작성 책임
유형·파일이어 쓸 글추가 확인
info · content/info.schema.json2026 부모급여·아동수당 한 번에 정리공식 금액·지역 조건·기준일. 경험 칸은 비워 둘 수 있어요.
play · content/play.schema.json터미타임 놀이건강·안전 위험 표시, 공식 근거, 사람 승인. 제목의 놀이가 안전 검토를 지우지 않아요.
affiliate · content/affiliate.schema.json손톱깎이 vs 전동 손톱갈이commercial_relations·product_records. 비교 설명과 직접 사용 후기를 구별해요.
sponsor · content/sponsor.schema.json가상 도담 그림책꽂이 후기계약의 AI 허용 확인·사람 경험·대가성 표시·광고주 확인 뒤 최종 승인.

samples/info.json의 source_notes를 읽어 보세요. url(원문 주소)·official(공식 기관 여부)·country(국가)·checked_on(확인일)·age_range(대상 월령)·license(이용 허락)·claims(이 자료로 뒷받침하는 설명)를 나눠요. 글 기준일은 최상위 as_of, 출처 확인일은 checked_on이에요. 자료 자체의 기준일과 수정일은 개인 출처 메모에도 따로 남겨요.

부모급여·아동수당 금액이 바뀌면 관할 기관의 원문으로 갱신해요. 복지서비스 API는 원문을 찾는 출발점이에요. API 수정일만 새롭다고 금액을 최신으로 쓰지 마세요. 보건복지부·복지로·정부24와 지자체 원문에서 대상·시행일·지역 조건을 확인하고 출처 메모를 고치세요.[BX089]

단계 ③ · 공공자료의 모양과 허락을 구별해요

단계 ③ · 공공자료의 모양과 허락을 구별해요

어린이집 기관 정보와 복지서비스는 무료 공개 API로 찾을 수 있어요. 센터 수는 CSV 집계, 센터 연락처는 주소록에서 찾아요. 공개 접종 일정은 공식 파일을 확인하세요.[BX068][BX089]

CSV 집계, 기관 주소록, API는 서로 다른 자료예요. 센터 수를 보여 주는 파일에서 내 동네 센터 전화번호를 찾으면 안 돼요.

공공자료 3종 · 목적에 맞게 선택해요
형태실제 예·기준할 일
CSV 집계 파일육아종합지원센터 현황: 2025-12-31 기준, 유형·연도별 집계[BX090]센터 수·변화를 설명해요. 개별 주소록으로 쓰지 않아요.
기관 주소록중앙육아종합지원센터 전국 현황: 센터 소재지·연락처[BX070]방문 전 해당 센터 원문에서 운영·연락처를 다시 확인해요.
요청형 API어린이집 기관 정보·중앙부처 복지서비스: XML 응답[BX068][BX069][BX089]각 자료의 활용 신청·허용 범위·트래픽 단위를 확인해요. 아이 명단·입소 가능 자리로 해석하지 않아요.

예방접종 공개 일정표는 아이 개인 접종기록 API가 아니에요. 질병관리청 예방접종도우미의 표준 일정표는 공식 원문을 찾는 출발점이에요. 표시된 검토일·첨부 연도를 보고 최신 안내를 확인하세요. 최신 일정과 첨부 재이용 범위를 확인하기 전에는 복사·자동 반영을 보류하고 공식 페이지를 연결해요.[BX091]

공공누리는 유형마다 상업 이용과 변경 허용이 달라요. 출처만 붙이면 사진까지 모두 복사할 수 있는 것은 아니에요.[BX122]

광고·제휴가 붙는 글은 상업 이용 여부부터 확인하세요. 데이터의 이용허락과 첨부 사진·로고·제3자 권리를 따로 봐요. 원문 URL·기관·자료 기준일·확인일·이용허락을 한 묶음으로 남기세요.[BX122]

def build_topics(today: str) -> dict:
    """고정 기준일을 포함한 글감 지도를 반환한다."""
    return {'as_of': today, 'topics': [
        {'category': '월령', 'title': '월령으로 찾는 집 놀이', 'age_range': '0~3세'},
        {'category': '발달', 'title': '개인차를 이해하고 공식 발달 안내 찾기', 'age_range': '0~3세'},
        {'category': '제도', 'title': '부모급여와 아동수당', 'age_range': '0~3세'},
        {'category': '놀이', 'title': '생후 3~4개월 터미타임', 'age_range': '3~4개월'},
        {'category': '제품', 'title': '손톱 관리 도구 비교', 'age_range': '0~3세'},
        {'category': '그림책', 'title': '아이와 책 정리하기', 'age_range': '0~3세'}]}

output/topics.json의 마지막 제목을 확인해요. 키워드 한 줄이 바뀌어도 경험을 자동 생성해 주지는 않아요. 파일을 원래 문장으로 되돌린 뒤 시작 상태 복원 → 단계 ① → 검사 순서로 실행하세요. start는 이 코드 수정까지 되돌리지 않아요.

월령만 바꾼 비슷한 글을 늘리는 방법은 피하세요. 검색 순위를 조작하려 추가 가치 없는 글을 대량 생성하면 스팸 정책에 걸릴 수 있어요. 대상 독자의 다른 질문·새 자료·직접 기여를 한 줄로 설명할 수 없다면 기존 글을 고치세요.[BX064][BX065]
