E2E · 심화 진행표

2026년 10월 조사 기준 · 가상 블로그 「봄이랑 크는 집」

세 경로를 나눠 기록하고, 일곱 가지 모의 상황을 끝까지 확인해요.

먼저 답부터

mock에서 일곱 시나리오를 통과하면 코드 실습을 완주한 거예요. 로컬 WordPress와 실제 블로그는 각각 연결하고 확인한 뒤 따로 체크하세요. 광고 승인·검색 반영·입금은 코드 실습 완료와 다른 기록이에요.

서윤실제 블로그가 없어도 끝낼 수 있나요?

태오네. mock 열부터 마치세요. 나머지 두 열은 선택한 때 이어 가요.

시작 상태 확인

A1의 환경을 준비했다면 E2E부터 복원해 실행할 수 있어요. 가상환경을 켜고 blog.py와 course.py가 있는 연습용 키트 폴더에서 실행하세요. 처음부터 이어 온 사람도 기존 파일을 보관한 뒤 같은 시작 상태로 맞춰요.

start는 output/·private/·config.toml을 교체해요. 보관할 실습 파일을 다른 폴더에 복사하세요. .env는 보존해요. 실제 운영 폴더에서는 실행하지 마세요.

Windows·macOS·Linux 공통

python course.py start E2E

코드 읽기

시나리오끼리 실습 상태를 섞지 않도록 매번 새 폴더를 만들어요. course/scenarios.py:19부터 읽어요.

    kit_root = Path(kit_root)
    result = {}
    for name in NAMES:
        with TemporaryDirectory(prefix='blog-scenario-') as folder:
            root = Path(folder)
            shutil.copytree(kit_root / 'samples', root / 'samples')
            shutil.copyfile(kit_root / 'config.example.toml', root / 'config.example.toml')
            evidence = getattr(cases, name)(root, Store(root))
            result[name] = {'passed': True, 'evidence': evidence}
    path = kit_root / 'output/scenarios.json'; path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(result, ensure_ascii=False, indent=2) + '\n', encoding='utf-8', newline='\n')
읽는 법
키트 줄하는 일
19~21키트 위치와 결과를 준비하고 일곱 이름을 순회해요.
22~25시나리오별 임시 폴더에 샘플·예제 설정만 복사해요.
26~27검사 함수를 실행하고 통과 여부와 증거를 기록해요.
28~29현재 키트 output/scenarios.json에 결과를 저장해요.

assert는 기대한 조건이 틀리면 실행을 멈추는 검사예요. 예를 들어 중복 방지는 서버 글이 하나인지 검사해요. JSON 파일은 이름과 값을 짝지어 저장한 문서예요. 이름을 바꾸지 말고 증거 문장을 읽으세요.

바꿔 보기

내 실행 날짜를 바꿔도 일곱 시나리오는 고정 날짜로 재현돼요. 파일 탐색기에서 config.example.toml을 같은 폴더에 복사해 config.toml로 이름을 바꾸세요. 이 파일의 [clock] 아래 한 줄을 today = "2026-10-28"로 바꾸고 같은 명령을 실행하세요.

Windows·macOS·Linux 공통

python blog.py run --scenarios

터미널은 앞과 같아요. output/scenarios.json의 첫 증거도 “고정 시계 10월 29일 공개 확인”으로 같아요. 시나리오는 현재 config.toml 대신 예제 설정과 고정 날짜를 쓰기 때문이에요. 내 날짜로 실제 서버를 시험한 결과는 진행표의 선택 경로에 따로 기록해요.

원래 기본 결과로 돌아가려면 아래 체크포인트를 실행하세요. 보관할 파일은 복원 전에 복사해요.

E2E 산출물·상태가 다름이전 실행 결과나 변경된 파일이 섞였어요.결과를 보관하고 아래 체크포인트로 다시 맞춰요.
로컬 WordPress의 future가 그대로임예약 등록 뒤 실제 공개가 아직 안 됐어요.A11에서 시각·WP-Cron을 확인하고 서버를 재조회해요.
메모 저장 불가 안내브라우저가 저장을 막고 있어요.기록은 현재 화면에서 쓰고 전체 내용을 개인 메모로 옮겨 보관해요.
시나리오 실행이 멈춤검사 조건이나 파일·권한에 문제가 생겼어요.마지막 오류와 실행 폴더를 적고 A1 진단부터 확인해요.

WordPress의 future는 예약, publish는 공개 상태예요. WP-Cron은 페이지 요청 때 실행돼 공개가 늦어질 수 있어요. 예약 응답만으로 실제 공개에 체크하지 마세요.[BX004][BX127]

확인할 점

모의 검사가 통과해도 실제 계정의 광고 승인·제품 자료·세금 판단은 남아요. 선택 경로는 A2의 연결, A6의 공개 재조회, A11의 복구, A12의 출시 점검을 본인 환경에서 마치세요. 건강·협찬·제휴·아이 정보·기존 글 갱신은 항상 사람이 승인해요.

정리

  • mock 파일과 일곱 증거를 확인하면 기본 코드 과정을 완주해요.
  • 로컬 WordPress와 실제 블로그는 따로 연결·확인하고 기록해요.
  • 실패·보류는 이유와 다음 행동을 남기고 공개를 멈춰요.
