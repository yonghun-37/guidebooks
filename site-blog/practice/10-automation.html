왜 하나요? 반복 작업은 줄이되 경험·사실 확인과 공개 판단은 직접 맡기 위해서예요.

세 글의 고정 제목·메모·사진 파일명을 이어 씁니다. 정보는 info-notes.txt·support-check.svg, 후기는 review-notes.txt·dehumidifier-tank.jpg와 dehumidifier-room.jpg, 여행은 trip-notes.txt·trip-river.jpg와 trip-shelter.jpg입니다. 원고 이름은 draft.txt로 유지하고 선택한 글의 제목을 제목칸에 넣으세요.

핵심 · 첫 7일은 숫자와 바꾼 것을 같이 적어요

자동화 설치를 건너뛰어도 관찰은 오늘 시작하세요. 네이버는 내 블로그의 통계, 티스토리는 블로그 관리의 통계, 외부 사이트는 Search Console과 광고·제휴 보고서를 열어요. 보통 ‘통계/방문 분석’, ‘실적’, ‘보고서’와 같은 이름을 찾아요.

  1. 매일 같은 시각에 공개 URL·수정 내역·실제 작업시간을 기록해요. 방문자·조회수는 화면의 지표 이름 그대로 적어요.
  2. Search Console은 같은 기간·검색 유형의 노출·클릭을 기록해요. 네이버 블로그만 쓴다면 내 통계의 유입 경로·검색어를 적고 해당 없는 칸은 “해당 없음”으로 둬요.
  3. 광고·제휴는 승인 상태, 예상·확정·입금, 주문·취소를 나눠요. 아직 집계되지 않은 값은 “아직 미집계”, 보고서의 0은 0으로 적어요.
  4. 다음 글에서는 고칠 것 하나만 정해요. 노출은 있는데 클릭이 적으면 검색어와 제목의 약속을, 읽고 도움이 안 된다는 반응이면 본문·경험 설명을 확인해요.

PV는 페이지가 열린 횟수예요. UV는 해당 통계에서 중복을 뺀 방문자예요. 같은 사람이 여러 글을 읽으면 값이 달라져요. 일별 UV를 더한 값을 월간 순방문자라고 부르지 않아요. 가상 계산: 같은 기간 검색 클릭 3 ÷ 노출 100 × 100 = 검색 클릭률 3%예요. 광고 클릭률과 구분하세요.

휴대폰만 있는 독자: 이 표를 메모 앱에 복사하고 매일 3분을 잡아요. 키트 설치·드라이런은 선택이에요. 오늘 결과 확인으로 바로 가도 돼요.

선택 · blog-kit를 새 폴더에서 준비해요

샘플 연습은 계정·API 키 없이 오프라인으로 끝나요. blog-kit는 내 컴퓨터에서 프롬프트·점검·HTML·전송할 요청 내용을 만드는 Python 도구예요. 드라이런은 서버에 보내지 않고 요청만 미리 보는 실행이에요.

동봉 blog-kit ZIP 받기 · 같은 배포본의 README · GitHub의 blog-kit README를 열어 버전과 파일을 확인해요. 저장소의 Code → Download ZIP 같은 메뉴로 받은 파일을 새 폴더에 압축 해제해요. 압축 파일 안에서 명령을 실행하지 않아요. Windows는 짧은 C:\blog 폴더로 blog-kit 내용을 옮겨도 돼요.

터미널은 글자로 명령을 입력하는 창이에요. 경로는 파일이나 폴더의 주소예요. Windows는 시작 메뉴에서 PowerShell, macOS는 Spotlight에서 터미널을 열어요. 아래 경로를 내 압축 해제 위치로 바꿔요.

Windows PowerShell

py -3 --version
cd "C:\blog"
dir
py -3 -m venv .venv
.venv\Scripts\python.exe --version

Python 3.10 이상과 brief.py·check.py·samples가 보여야 해요. 폴더가 다르면 탐색기 주소창에서 실제 경로를 복사해 cd 뒤 따옴표 안에 넣어요.

macOS / Linux

python3 --version
cd "/Users/내이름/Downloads/guidebooks-main/blog-kit"
ls
python3 -m venv .venv
.venv/bin/python --version

Python 3.10 이상과 brief.py·check.py·samples가 보여야 해요. Linux도 내 압축 해제 경로로 바꿔요.

Python이 없으면 공식 다운로드에서 설치 안내를 따라요. 가상환경 .venv는 이 폴더에서 쓸 Python 상자예요. 실행 패키지 설치나 활성화 명령 없이 아래 Python 경로를 그대로 써요.

따라 하기 · 샘플 → 점검 → HTML

Windows PowerShell

.venv\Scripts\python.exe brief.py --keyword "2025 청년내일저축계좌 대상 신청 기간" --type 정보 --platform naver --notes samples/info-notes.txt --output output/practice/brief.md
.venv\Scripts\python.exe check.py samples/article.md --output output/practice/report.md --strict
.venv\Scripts\python.exe render.py samples/article.md --output output/practice/article

macOS / Linux

.venv/bin/python brief.py --keyword "2025 청년내일저축계좌 대상 신청 기간" --type 정보 --platform naver --notes samples/info-notes.txt --output output/practice/brief.md
.venv/bin/python check.py samples/article.md --output output/practice/report.md --strict
.venv/bin/python render.py samples/article.md --output output/practice/article

이렇게 보이면 성공: 첫 명령은 프롬프트 생성 완료:와 brief.md 경로, 둘째는 확인할 항목: 0개와 제목: 27자 / 본문: 1798자(공백 포함), 셋째는 HTML 생성 완료:와 검수 대기:가 보여요.

output/practice/article/preview.html을 더블 클릭해요. 글과 순서도가 보이면 변환이 됐어요. editor.html은 편집기용 본문 조각, draft.md는 복사한 초안이에요. Markdown은 # 제목·## 소제목처럼 표시를 붙이는 텍스트 형식이에요.

이 샘플은 수아의 편집 연습 글이에요. 경험 확인은 예시를 내 실제 체험처럼 게시하지 않겠다는 확인을 뜻해요. 내 공개 글은 실습 4의 본인 자료로 따로 만들어요.

따라 하기 · 사람 확인 → Blogger 드라이런

  1. REVIEW.md와 report.md, preview.html을 열어 출처·경험·이미지·관계 표시·미리보기를 읽어요.
  2. REVIEW.md의 다섯 확인 항목에서 [ ]를 [x]로 바꿔 저장해요. Windows 메모장, macOS 일반 텍스트 편집기를 사용해요. 확장명이 .md.txt로 바뀌지 않게 확인하세요.
  3. 다음 명령으로 승인 기록을 만들고 Blogger 요청을 미리 봐요.

Windows PowerShell

.venv\Scripts\python.exe review.py output/practice/article --approve
.venv\Scripts\python.exe publish.py output/practice/article --platform blogger

macOS / Linux

.venv/bin/python review.py output/practice/article --approve
.venv/bin/python publish.py output/practice/article --platform blogger

이렇게 보이면 성공: 승인 명령은 사람 승인 기록 완료. publish.py는 기본 드라이런입니다.를 보여요. 다음 출력에서 아래 항목을 찾아요. 이 부분은 실행 결과의 발췌예요.

"mode": "dry-run"
"platform": "blogger"
"endpoint": "https://www.googleapis.com/blogger/v3/blogs/<BLOG_ID>/posts?isDraft=true"
"authorization": "<REDACTED>"
"state": "draft"

output/practice/article/dry-run.json에도 요청이 저장돼요. JSON은 이름과 값으로 정보를 묶어 적는 텍스트 형식이에요. 서버 전송은 없어요. <BLOG_ID>는 내 블로그 ID를 넣을 자리이며, 이 연습에서는 그대로 둬요. 승인 뒤 원고·이미지·검수표를 바꾸면 다시 변환·검수·승인해야 해요.

네이버·티스토리: 공식 글쓰기 API가 종료돼 키트에서 자동 발행하지 않아요. preview.html에서 복사한 뒤 공식 편집기에서 사진을 다시 올리고 직접 발행해요.[B006][B007]

Windows PowerShell

.venv\Scripts\python.exe publish.py output/practice/article --platform naver

macOS / Linux

.venv/bin/python publish.py output/practice/article --platform naver

실제 출력은 편집기에 붙여 넣기:로 시작해요. 티스토리는 --platform tistory로 바꾸세요. 로그인 매크로를 대신 쓰지 않아요.[B158]

다음 글 · 매일 쓸 틀만 준비해요

Windows PowerShell

.venv\Scripts\python.exe daily.py --date 2026-10-26

macOS / Linux

.venv/bin/python daily.py --date 2026-10-26

이렇게 보이면 성공: 작성 대기:와 output/daily/2026-10-26/draft.md가 보여요. 여기 날짜는 연습 날짜예요. 내 작업은 --date를 빼면 컴퓨터의 오늘 날짜를 사용해요.

materials.md에 내 출처·경험·사진 권리·AI 역할·제공 관계를 넣어요. brief.md를 무료 AI에 단계별로 붙이고, 직접 검수한 본문을 draft.md에 # 제목·## 소제목 형태로 저장해요. 예시 글을 내 글로 복사하지 않아요.

Windows PowerShell

.venv\Scripts\python.exe daily.py --date 2026-10-26 --resume

macOS / Linux

.venv/bin/python daily.py --date 2026-10-26 --resume

같은 폴더에 preview.html·editor.html·report.md·REVIEW.md가 생기고 검수 대기:에서 멈춰요. 다시 읽고 승인한 뒤 같은 폴더 경로로 드라이런해요. 반복 실행만으로 AI 작성·승인·발행이 되지는 않아요.

더 해 볼 때 · 인증과 실제 전송을 구분해요

오늘은 드라이런에서 멈춰도 충분해요. API는 프로그램이 서비스에 요청을 보내는 공식 통로예요. 실제 API 초안 저장은 본인 자료로 새 글을 만들고 README의 준비 절차를 따른 뒤 선택해요.

대상준비할 것실제 전송 전 확인
Blogger · 기본Google Cloud의 Blogger API·OAuth 동의·쓰기 범위 액세스 토큰·본인 블로그 숫자 IDOAuth는 사용자가 권한을 허용하는 인증이에요. API key만으로 글을 쓸 수 없어요.[B012][B014]
설치형 WordPress · 심화HTTPS 사이트·작성 권한·사용자 프로필의 애플리케이션 비밀번호도구 전용 비밀번호예요. 주 로그인 비밀번호를 넣지 않아요.[B010][B011]
WordPress.com · 비교별도 OAuth와 .com API키트의 설치형 WordPress Basic 인증과 다르므로 같은 설정을 넣지 않아요.[B144]

Blogger는 Google Cloud에서 API 활성화·OAuth 동의·테스트 사용자·클라이언트 설정 후 공식 시작 안내대로 본인 동의를 진행해요. 토큰은 허용된 API 요청에 붙이는 인증용 비밀값이에요. 이 키트는 토큰을 발급·갱신하지 않아요. .env는 내 컴퓨터에 인증값을 두는 텍스트 파일이에요. 실제 전송을 고를 때만 README의 .env.example 복사·입력 안내를 따라요. 토큰을 AI 대화·명령줄·공개 원고에 넣지 마세요.

키트의 --live는 초안 저장이에요. 공개는 Blogger/WordPress 관리 화면에서 내용을 확인하고 직접 해요. 가상 샘플과 로컬 이미지가 있는 글은 실제 전송을 막아요. 사진은 적법한 HTTPS 주소를 준비하거나 수동 편집기에서 올리세요.

오류다시 보내기 전에
401토큰 만료·인증 정보를 공식 설정에서 확인해요.
403쓰기 권한·API 설정·호스팅 제한을 확인해요.
시간 초과·응답 오류LIVE_ATTEMPT.json을 보관하고 관리 화면의 글 ID·초안 목록부터 확인해요. 이미 생긴 글이 있으면 재전송하지 않아요.
확인할 점

타임아웃 뒤 시도 기록을 지워 같은 요청을 반복하지 마세요. 같은 폴더에서 실제 전송을 다시 하기 전에 서버의 저장 상태를 먼저 확인해요. 첫 7일의 작은 차이로 수익·검색 효과를 판단하지 말고 바꾼 내용과 지표를 함께 읽으세요.

자주 묻는 질문 5개

키트와 드라이런은 무엇인가요?

키트는 내 컴퓨터에서 파일과 요청을 만들고, 드라이런은 전송 없이 미리 봐요. 성공 출력의 dry-run·isDraft=true를 찾으세요.

네이버·티스토리에도 자동 발행하나요?

두 플랫폼은 공식 편집기로 직접 발행해요. 종료된 API 대신 로그인 매크로를 쓰지 않아요. 수동 안내를 보세요.[B006][B007][B158]

Blogger OAuth·WordPress 비밀번호는 무엇인가요?

본인 글 작성 권한을 도구에 허용하는 인증이에요. Blogger는 사용자 동의 토큰, 설치형 WordPress는 도구 전용 비밀번호예요. 준비 표를 확인해요.[B014][B011]

오류가 나면 다시 실행하나요?

실제 전송이었다면 서버의 초안 목록부터 확인해요. LIVE_ATTEMPT.json을 지우지 말고 오류 표에서 원인을 나눠 보세요.

첫 7일에 무엇을 적나요?

같은 기간의 방문·검색·수입 상태와 바꾼 내용을 적어요. 미집계는 0과 나눠요. 기록표를 메모에 복사하세요.

자동화·무료 대안

무료 기본 경로는 공식 편집기 발행과 메모 앱 기록이에요. blog-kit는 구독 없이 오프라인으로 같은 작업 파일을 만들고, API 초안 저장만 별도로 선택할 수 있어요. blog-kit 실행 순서에서 필요한 부분만 따라 하세요. 휴대폰만 있다면 메모 앱과 공식 편집기로 끝내도 돼요.
