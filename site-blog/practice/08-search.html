지금 하는 일

내 플랫폼에 필요한 검색 확인만 하고, 상태와 다음 확인일을 기록해요.

이 실습이 끝나면 내 손에 있는 것: 검색 허용 또는 소유확인·피드·URL 검사 기록.

왜 하나요? 공개된 글을 검색 도구가 읽을 수 있는지 살펴보기 위해서예요.

오늘 잡아 둘 시간: 15분 · 외부 사이트 연결을 나중에 할 경우 다음 확인일을 남겨요.

따라 하기 ① · 내 플랫폼의 경로만 따라요

네이버 블로그는 서치어드바이저에 따로 등록하지 않아요. 전체 공개·검색 허용을 확인하고 글 주소를 남겨요. 티스토리 등 외부 사이트는 소유확인·피드 제출로 이어 가요.[B173]

버튼 이름은 앱 버전에 따라 조금 다를 수 있어요. 최신 앱 화면에서 비슷한 이름의 버튼을 찾아 주세요. 못 찾겠으면 공식 도움말(네이버 블로그 · Search Console)을 확인하세요.

네이버 블로그 · 검색 허용부터 봐요

  1. 실습 7에서 저장한 글 주소를 로그인하지 않은 브라우저에서 열어요. 글이 읽히는지 확인해요.
  2. 작성자 계정으로 수정/발행 설정을 열고 전체 공개·검색 허용을 확인해요.[B048]
  3. 글 제목이나 본문 고유 문장으로 네이버에서 찾아봐요. 결과가 없으면 확인한 날짜·검색어·공개 상태를 메모해요.
  4. 아직 보이지 않으면 검색 제한 기준·허용 설정을 확인하고 다음 확인일을 정해요. 같은 글을 반복 삭제·재발행하지 않아요.[B004][B173]

수아의 네이버 정보 글은 여기까지예요. 서치어드바이저에서 blog.naver.com을 내 사이트로 등록하려고 하지 마세요. 결과 메모로 가요.

티스토리 · Search Console을 연결해요

티스토리는 공식 플러그인 연결부터 시도해요. 사이트를 검색 도구에 등록하는 것과 광고 심사는 각각 진행해요.[B183]

  1. PC 블로그 관리 → 플러그인 → Google Search Console → 계정 연결하기와 같은 항목을 열어요. 사용할 Google 계정을 확인하고 요청 권한을 읽은 뒤 적용해요.
  2. Search Console을 열어 내 티스토리 주소의 속성이 생겼는지 봐요. 속성은 검색 도구가 관리하는 사이트 주소 묶음이에요.
  3. 속성이 없으면 속성 추가 → URL 접두사에 https://내블로그.tistory.com/ 전체 주소를 넣어요. 기본 티스토리 주소에 도메인/DNS 방식을 고르지 않아요.[B177]
  4. 소유확인 방법에서 HTML 태그를 골랐다면 발급된 태그를 보관해요. 티스토리 스킨 편집 → HTML 편집과 같은 항목에서 원본을 복사해 보관한 뒤 <head> 안에 넣고 저장해요. 태그를 글 본문에 붙이지 않아요. 같은 계정의 Search Console에서 확인해요.[B035][B177]
  5. 사이트맵 메뉴에서 플러그인의 제출 내역을 확인해요. 없다면 https://내블로그.tistory.com/sitemap.xml을 직접 열어 정상 응답을 확인한 뒤 제출해요.[B183][B184]
  6. 상단 URL 검사에 실습 7의 글 주소를 넣어요. 색인 상태를 읽고 필요하면 실제 URL 테스트/색인 생성 요청 같은 항목을 사용해요.[B178]

Blogger: 같은 관리 Google 계정으로 Search Console에 이미 속성이 있는지 먼저 봐요. 없다면 URL 접두사 속성과 가능한 소유확인 방법을 따라요. 설치형 WordPress: 사이트가 제공하는 사이트맵 주소를 확인하고 테마·공식 연결 기능 또는 DNS 권한에 맞는 방법을 골라요. 주소를 임의로 만들어 제출하지 않아요.[B035][B177]

외부 사이트 · 네이버 서치어드바이저도 연결할 수 있어요

  1. 서치어드바이저 → 웹마스터 도구에서 사이트 등록/추가 같은 항목을 열어요. 발행 글 한 편의 경로 대신 내 사이트의 최종 HTTPS 주소를 넣어요.
  2. HTML 태그 방식이면 발급된 메타태그를 사이트의 <head> 안에 넣고 저장해요. 티스토리는 위 스킨 편집과 같은 위치예요. 원본을 먼저 보관하세요.
  3. 서치어드바이저에서 소유확인을 눌러요. 확인 파일 방식은 사이트 루트에 파일을 올릴 수 있을 때만 써요.[B174][B175]
  4. 소유확인한 사이트 → 요청 → RSS 제출 / 사이트맵 제출에서 실제 생성된 주소를 넣어요. 티스토리는 /sitemap.xml을 먼저 확인하고, RSS는 사이트가 제공하는 RSS 링크를 복사해 열어 봐요.[B176][B184]
  5. 제출 상태와 오류, 수집·색인 현황을 읽고 날짜와 함께 메모해요. 태그를 지우거나 스킨을 바꿨다면 소유확인도 다시 확인해요.

이렇게 보이면 성공 · 상태와 다음 확인일을 남겨요

네이버는 공개·검색 허용 기록, 외부 사이트는 소유확인·제출·URL 검사 기록이 남아요. 아직 검색 결과가 없더라도 상태와 다음 행동을 기록하면 오늘 등록 과제를 끝낼 수 있어요.

휴대폰만 있다면: 네이버는 앱의 공개·검색 허용과 휴대폰 검색 결과를 확인해요. 외부 사이트는 모바일 브라우저에서 Search Console과 티스토리 관리의 데스크톱 사이트 보기를 시도해요. HTML 편집이 어려우면 공개 주소와 다음 확인일을 남기고 PC에서 연결해요.

확인할 점

색인 요청은 즉시 노출이나 순위를 약속하지 않아요. 소유확인·수집·색인·검색 노출은 각각 확인하세요. 과거 공식 플러그인 안내와 현재 메뉴가 다르면 위 공식 도움말에서 지원 방식을 다시 확인해요.[B178][B183]

이렇게 보이면?

상황지금 할 일
소유확인 태그를 못 찾는대요등록한 http/https·호스트가 맞는지 봐요. HTML 원문 head에 저장됐는지 확인하고 글 본문에서는 지워요.
사이트맵/RSS가 비었어요공개 글과 실제 피드 주소를 브라우저에서 확인해요. 로그인 화면이나 오류 페이지를 제출하지 않아요.
등록은 됐는데 검색이 안 돼요URL 검사 결과와 수집 제한을 읽어요. 확인일을 남기고 원고의 독자 질문·접근 가능 여부를 점검해요.

자주 묻는 질문 5개

네이버도 등록해야 하나요?

별도 서치어드바이저 연동은 필요 없어요. 전체 공개·검색 허용을 확인하고 네이버 경로로 마쳐요.[B173]

티스토리 소유확인은 어떻게 하나요?

Search Console 플러그인부터 연결해요. 속성이 없으면 정확한 HTTPS 주소로 URL 접두사 방식을 써요. 연결 순서를 따라요.[B183][B177]

사이트맵·RSS 주소는 무엇을 넣나요?

실제로 열리는 피드 주소를 넣어요. 티스토리는 sitemap.xml을 확인하고 RSS는 사이트의 제공 링크를 열어 보세요. 제출 순서를 보세요.[B176][B184]

요청하면 바로 검색되나요?

즉시 노출은 보장되지 않아요. “신청 완료”와 “검색됨”을 나눠 적고 다음 확인일을 정하세요.[B178]

소유확인 실패는 어디서 보나요?

주소 범위와 HTML head부터 확인해요. 글 본문에 태그를 붙이지 않았는지 보고 오류 표대로 고쳐요.[B175]

자동화·무료 대안

blog-kit는 공개 URL과 작업 메모를 보관하는 데 쓸 수 있어요. 검색 도구 등록·소유확인·색인 요청은 해당 공식 화면에서 직접 진행해요. blog-kit 실행 순서에서 필요한 부분만 따라 하세요. 휴대폰만 있다면 메모 앱과 공식 편집기로 끝내도 돼요.

오늘 한 일을 남겨요

체크와 메모는 이 브라우저에 저장돼요. 중요한 결과는 개인 파일에도 남기세요.
