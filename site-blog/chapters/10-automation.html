공식 예약 · 완성한 글의 공개 시각을 정합니다

예약 발행은 사람이 완성한 글을 정한 시각에 공개하도록 맡기는 기능입니다. [B002][B170]

기준·예
네이버 PC는 글쓰기의 발행 → 발행 시간 → 예약에서 고릅니다. 티스토리는 완료 뒤 발행 시각/예약과 같은 항목을 찾습니다. [B002][B170]
조건

선택 API · 프로그램이 내 블로그에 초안을 보냅니다

API는 프로그램이 정해진 방식으로 서비스에 요청을 보내는 통로입니다. 공식 글쓰기 API는 Blogger·WordPress 경로를 사용합니다. 네이버·티스토리는 공식 편집기로 옮깁니다. [B012][B010][B006][B007]

흐름
본인 원고 → 사람 검수 → 요청 미리보기 → 인증된 초안 저장 → 관리 화면에서 직접 공개입니다.
기준·예
네이버 글쓰기 API는 2020년 5월 6일 종료됐습니다. 티스토리는 2023년 12월 말~2024년 2월 말 Open API 순차 종료를 공지했습니다. 로그인·발행 매크로로 대신하지 마세요. [B006][B007][B158]
조건
Blogger는 쓰기 권한과 OAuth 동의가, 설치형 WordPress는 HTTPS와 작성 권한·애플리케이션 비밀번호가 필요합니다. [B012][B014][B011]
언제 쓰나
공식 편집기로 반복해 발행해 본 뒤 원고 이동이 번거로울 때 선택합니다.
지금 할 일
내 플랫폼이 아래 어느 행인지 적고 준비가 안 됐으면 직접 발행을 유지하세요.
확인할 점

WordPress.com은 별도 OAuth API를 씁니다. 설치형용 비밀번호 연결과 섞지 마세요. API 한도는 본인 설정에서 확인합니다. 이 키트는 공개·예약 API 호출을 제공하지 않습니다. [B144][B012][B010]

자동화·무료 대안 · blog-kit은 파일을 준비합니다

blog-kit은 내 컴퓨터에서 프롬프트·검사 리포트·HTML을 만드는 선택 도구입니다.

흐름
brief → 사람 작성 → check·render → 사람 검수·승인 → publish 드라이런 순서입니다. 드라이런은 서버에 보내지 않고 요청 내용만 보여 주는 연습입니다.
기준·예
키트 실행에 추가 패키지·유료 AI API는 필요하지 않습니다. 아래 샘플 검사는 제목 27자·본문 1,369자·확인할 항목 0개를 출력합니다.
조건
터미널에서 blog-kit 폴더로 이동합니다. 터미널은 명령을 글자로 입력하는 창입니다. 설치·운영체제별 경로는 다운로드한 키트의 README ‘폴더와 Python 준비’를 따릅니다.
언제 쓰나
프로그램이 익숙하면 선택합니다. 브라우저에서 직접 만들고 발행해도 같은 과제를 마칩니다.
지금 할 일
아래 검사·미리보기부터 연습하세요. 리포트의 항목을 읽고 원문·경험·사진을 직접 확인합니다.
확인할 점

검사 0개는 사실·권리 검증 완료를 뜻하지 않습니다. 동봉 샘플은 편집 연습으로만 씁니다. 토큰·정산서·개인정보를 AI 입력이나 공유 파일에 넣지 마세요.

python check.py samples/article.md --output output/practice/report.md --strict
python render.py samples/article.md --output output/practice/article

이렇게 보이면 성공: 확인할 항목: 0개, 제목: 27자 / 본문: 1369자가 나오고, 변환 뒤 HTML 생성 완료:와 검수 대기:가 보입니다. output/practice/article/preview.html을 브라우저로 열어 보세요.

위 명령의 python은 준비한 가상환경 Python으로 바꿉니다. Windows는 .venv\Scripts\python.exe, macOS/Linux는 .venv/bin/python입니다. 가상환경은 이 폴더의 Python 실행 환경을 따로 담는 상자입니다.

python daily.py --date 2026-10-26
python daily.py --date 2026-10-26 --resume

첫 명령은 작성 대기:와 날짜별 draft.md를 만듭니다. 고정 날짜는 연습용이며 내 작업은 날짜 옵션을 빼도 됩니다. materials.md에 자료를 채우고 draft.md를 쓴 뒤 두 번째 명령을 실행합니다. HTML·리포트·검수표를 만들고 검수 대기:에서 멈춥니다.

REVIEW.md의 다섯 항목을 직접 확인해 체크한 뒤 아래 명령을 순서대로 실행합니다. 샘플의 경험 항목은 연습용 글임을 이해하고 실제 게시에 쓰지 않는다는 확인입니다.

python review.py output/practice/article --approve
python publish.py output/practice/article --platform blogger

이렇게 보이면 성공: 사람 승인 기록 완료. 뒤에 "mode": "dry-run", "state": "draft", isDraft=true가 보입니다. WordPress는 --platform wordpress로 바꾸면 "status": "draft"가 나옵니다. 서버 전송은 없습니다.

원고를 다시 변환하면 이전 체크와 승인이 초기화됩니다. 선택 전송은 본인 원고·직접 준비한 인증 정보와 --live가 필요하며 초안만 저장합니다. 응답이 끊기면 LIVE_ATTEMPT.json을 지우고 재전송하지 말고, 관리 화면의 글 목록·ID부터 확인합니다.

python schedule_setup.py --os windows --time 20:30
python schedule_setup.py --os macos --time 20:30

둘 중 내 운영체제 명령 하나를 고릅니다. 안내만 생성했습니다.가 나오며 실제 예약 등록은 하지 않습니다. 출력한 명령을 사용자가 등록해도 날짜별 자료·초안 틀 준비까지만 합니다. 컴퓨터 전원·현지 시각·실행 로그를 확인하세요. 승인·발행을 무인 예약에 넣지 않습니다.

반복 작업을 시작할 때 묻는 질문

무엇부터 템플릿으로 만드나요?

자료 칸과 검수 질문부터 고정합니다.

지원 제도 글은 공고·대상·기간 칸을 만듭니다. 세 가지 양식 중 다음 글에 맞는 것을 고르세요.

네이버·티스토리도 API로 발행하나요?

종료된 공식 글쓰기 API로 새 발행 연결을 만들지 않습니다.

네이버는 2020년 종료, 티스토리는 종료 공지를 따릅니다. 플랫폼 표를 보고 공식 편집기·예약을 쓰세요. [B006][B007]

Blogger·WordPress는 무엇이 필요한가요?

본인 블로그 쓰기 권한과 해당 인증이 필요합니다.

Blogger는 OAuth 토큰, 설치형 WordPress는 전용 애플리케이션 비밀번호를 준비합니다. OAuth는 사용자가 동의한 권한으로 접근하는 인증 방식입니다. 준비 표를 확인하세요. Blogger의 기본 호스팅·blogspot 주소는 무료입니다. 설치형 서버·도메인 비용은 따로 확인합니다.[B069][B017] [B014][B011]

예약과 자동 생성은 무엇이 다른가요?

예약은 완성한 글의 공개 시각을 정하는 일입니다.

지원 제도 자료를 AI로 개요화하는 일과 구분하세요. 공식 예약 전에 원문을 대조합니다. [B002][B170]

AI 글을 하루 수십 개 올려도 되나요?

검수 없이 가치가 낮은 글을 대량 생성하는 방식은 피합니다.

Google은 가치 없는 대량 생성 남용을 제한합니다. 다음 글 하나에 내 자료가 있는지 입력 칸부터 확인하세요. [B032]
